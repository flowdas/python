파이썬 초기화 구성¶

PyInitConfig C API¶

Added in version 3.14.

파이썬은 :c:func:`Py_InitializeFromInitConfig`를 사용하여 초기화할 수 있습니다.

Py_RunMain() 함수는 사용자 정의 Python 프로그램을 작성하는 데 사용될 수 있습니다.

초기화, 파이널리제이션 및 스레드도 참조하십시오.

더 보기

PEP 741 “Python Configuration C API”.

예시¶

Python Development Mode <devmode>`가 활성화된 상태에서 항상 실행되는 사용자 맞춤형 파이썬의 예; 오류 시 `-1``을 반환합니다:

int init_python(void)
{
    PyInitConfig *config = PyInitConfig_Create();
    if (config == NULL) {
        printf("PYTHON INIT ERROR: 메모리 할당 실패\n");
        return -1;
    }

    // Python 개발자 모드 활성화
    if (PyInitConfig_SetInt(config, "dev_mode", 1) < 0) {
        goto error;
    }

    // 구성으로 파이썬 초기화
    if (Py_InitializeFromInitConfig(config) < 0) {
        goto error;
    }
    PyInitConfig_Free(config);
    return 0;

error:
    {
        // 에러 메시지 출력.
        //
        // 이 흔치 않은 중괄호 스타일은 goto 대상이 변수 선언을 가리킬 수 없기 때문에 사용됩니다.
        const char *err_msg;
        (void)PyInitConfig_GetError(config, &err_msg);
        printf("PYTHON INIT ERROR: %s\n", err_msg);
        PyInitConfig_Free(config);
        return -1;
    }
}

구성 생성¶

struct PyInitConfig¶

파이썬 초기화를 구성하기 위한 불투명 구조체입니다.

PyInitConfig *PyInitConfig_Create(void)¶

Isolated Configuration 기본값을 사용하여 새로운 초기화 구성을 생성합니다.

이것은 :c:func:`PyInitConfig_Free`에 의해 해제되어야 합니다.

메모리 할당 실패 시 NULL 을 반환합니다.

void PyInitConfig_Free(PyInitConfig *config)¶

초기화 구성 config 의 메모리를 해제합니다.

config 가 NULL 인 경우 아무 작업도 수행되지 않습니다.

에러 처리¶

int PyInitConfig_GetError(PyInitConfig *config, const char **err_msg)¶

config 의 에러 메시지를 가져옵니다.

  • Set *err_msg and return 1 if an error is set.

  • Set *err_msg to NULL and return 0 otherwise.

에러 메시지는 UTF-8 인코딩된 문자열입니다.

만약 config 에 종료 코드가 있으면, 종료 코드를 에러 메시지 형태로 포맷합니다.

오류 메시지는 다른 PyInitConfig 함수와 config 함께 호출될 때까지 유효합니다. 호출자는 오류 메시지를 해제할 필요가 없습니다.

int PyInitConfig_GetExitCode(PyInitConfig *config, int *exitcode)¶

config 의 종료 코드를 가져옵니다.

  • Set *exitcode and return 1 if config has an exit code set.

  • config 에 종료 코드가 설정되어 있지 않으면 0 을 반환합니다.

Py_InitializeFromInitConfig() 함수는 parse_argv 옵션이 0이 아닌 경우에만 종료 코드를 설정할 수 있습니다.

명령줄 구문 분석 실패(종료 코드 2) 또는 명령줄 옵션에서 명령어 도움말 표시를 요청한 경우(종료 코드 0)에 종료 코드를 설정할 수 있습니다.

옵션 가져오기¶

구성 옵션 name 매개 변수는 NULL이 아닌 null 종단 UTF-8 인코딩된 문자열이어야 합니다. :ref:`Configuration Options <pyinitconfig-opts>`를 참조하십시오.

int PyInitConfig_HasOption(PyInitConfig *config, const char *name)¶

구성 필드에 name 이라는 옵션이 있는지 테스트합니다.

옵션이 존재하면 1 을 반환하고, 그렇지 않으면 0 을 반환합니다.

int PyInitConfig_GetInt(PyInitConfig *config, const char *name, int64_t *value)¶

정수 구성 옵션을 가져옵니다.

  • *value 를 설정하고 성공하면 0 을 반환합니다.

  • config 에 오류를 설정하고 오류가 발생하면 -1 을 반환합니다.

int PyInitConfig_GetStr(PyInitConfig *config, const char *name, char **value)¶

널 종단 UTF-8 인코딩된 문자열 형태로 문자열 구성 옵션을 가져옵니다.

  • *value 를 설정하고 성공하면 0 을 반환합니다.

  • config 에 오류를 설정하고 오류가 발생하면 -1 을 반환합니다.

옵션이 선택적 문자열이고 해당 옵션이 설정되지 않은 경우, value 는 NULL 로 설정될 수 있습니다.

성공적으로 반환된 경우, string은 NULL 이 아니면 free(value) 를 사용하여 해제해야 합니다.

int PyInitConfig_GetStrList(PyInitConfig *config, const char *name, size_t *length, char ***items)¶

널 종단 UTF-8 인코딩된 문자열 배열 형태로 문자열 리스트 구성 옵션을 가져옵니다.

  • *length 와 *value 를 설정하고 성공하면 0 을 반환합니다.

  • config 에 오류를 설정하고 오류가 발생하면 -1 을 반환합니다.

성공적으로 반환된 경우, 문자열 리스트는 `PyInitConfig_FreeStrList(length, items)`로 해제해야 합니다.

void PyInitConfig_FreeStrList(size_t length, char **items)¶

`PyInitConfig_GetStrList()`에 의해 생성된 문자열 리스트의 메모리를 해제합니다.

옵션 설정¶

구성 옵션 name 매개 변수는 NULL이 아닌 null 종단 UTF-8 인코딩된 문자열이어야 합니다. :ref:`Configuration Options <pyinitconfig-opts>`를 참조하십시오.

일부 구성 옵션은 다른 옵션에 부수 효과를 가집니다. 이 로직은 Py_InitializeFromInitConfig() 가 호출될 때만 구현되며, 아래의 “Set” 함수로는 설정되지 않습니다. 예를 들어, dev_mode 를 1 로 설정해도 faulthandler 는 1 로 설정되지 않습니다.

int PyInitConfig_SetInt(PyInitConfig *config, const char *name, int64_t value)¶

정수 구성 옵션을 설정합니다.

  • 성공하면 0 을 반환합니다.

  • config 에 오류를 설정하고 오류가 발생하면 -1 을 반환합니다.

int PyInitConfig_SetStr(PyInitConfig *config, const char *name, const char *value)¶

널 종단 UTF-8 인코딩된 문자열로부터 문자열 구성 옵션을 설정합니다. 문자열은 복사됩니다.

  • 성공하면 0 을 반환합니다.

  • config 에 오류를 설정하고 오류가 발생하면 -1 을 반환합니다.

int PyInitConfig_SetStrList(PyInitConfig *config, const char *name, size_t length, char *const *items)¶

널 종단 UTF-8 인코딩된 문자열 배열로부터 문자열 리스트 구성 옵션을 설정합니다. 문자열 리스트는 복사됩니다.

  • 성공하면 0 을 반환합니다.

  • config 에 오류를 설정하고 오류가 발생하면 -1 을 반환합니다.

모듈¶

int PyInitConfig_AddModule(PyInitConfig *config, const char *name, PyObject *(*initfunc)(void))¶

빌트인 확장 모듈을 빌트인 모듈 테이블에 추가합니다.

새로운 모듈은 name 이라는 이름으로 가져올 수 있으며, 첫 번째 시도된 import 호출 시 초기화 함수로 initfunc 를 사용합니다.

  • 성공하면 0 을 반환합니다.

  • config 에 오류를 설정하고 오류가 발생하면 -1 을 반환합니다.

Python이 여러 번 초기화되는 경우, PyInitConfig_AddModule() 을 각 Python 초기화마다 호출해야 합니다.

PyImport_AppendInittab() 함수와 유사합니다.

Python 초기화¶

int Py_InitializeFromInitConfig(PyInitConfig *config)¶

초기화 구성으로부터 Python을 초기화합니다.

  • 성공하면 0 을 반환합니다.

  • config 에 오류를 설정하고 오류가 발생하면 -1 을 반환합니다.

  • config 에 종료 코드를 설정하고, Python이 종료하려는 경우 -1 을 반환합니다.

종료 코드 사례는 PyInitConfig_GetExitcode() 를 참조하십시오.

실행 시간 파이썬 구성 API¶

런타임 시에는 PyConfig_Get() 및 PyConfig_Set() 함수를 사용하여 구성 옵션을 가져오고 설정할 수 있습니다.

구성 옵션 name 매개 변수는 NULL이 아닌 null 종단 UTF-8 인코딩된 문자열이어야 합니다. :ref:`Configuration Options <pyinitconfig-opts>`를 참조하십시오.

일부 옵션은 sys 속성으로부터 읽어옵니다. 예를 들어, “argv” 옵션은 :data:`sys.argv`에서 읽어옵니다.

PyObject *PyConfig_Get(const char *name)¶

구성 옵션의 현재 런타임 값을 파이썬 객체로 가져옵니다.

  • 성공 시 새 참조를 반환합니다.

  • 오류 발생 시 예외를 설정하고 NULL 을 반환합니다.

객체 유형은 구성 옵션에 따라 다릅니다. 다음과 같습니다:

  • bool

  • int

  • str

  • list[str]

  • dict[str, str]

호출하는 쪽은 :term:`attached thread state`가 필요합니다. 이 함수는 파이썬 초기화 전이나 파이썬 최종화 후에 호출될 수 없습니다.

Added in version 3.14.

int PyConfig_GetInt(const char *name, int *value)¶

:c:func:`PyConfig_Get`과 유사하지만, C int로 값을 가져옵니다.

  • 성공하면 0 을 반환합니다.

  • 오류 발생 시 예외를 설정하고 -1 을 반환합니다.

Added in version 3.14.

PyObject *PyConfig_Names(void)¶

모든 구성 옵션 이름을 frozenset 형태로 가져옵니다.

  • 성공 시 새 참조를 반환합니다.

  • 오류 발생 시 예외를 설정하고 NULL 을 반환합니다.

호출하는 쪽은 :term:`attached thread state`가 필요합니다. 이 함수는 파이썬 초기화 전이나 파이썬 최종화 후에 호출될 수 없습니다.

Added in version 3.14.

int PyConfig_Set(const char *name, PyObject *value)¶

구성 옵션의 현재 런타임 값을 설정합니다.

  • 선택한 오퍼레이터 name 이 존재하지 않으면 ValueError 를 발생시킵니다.

  • value 가 유효한 값이 아니면 ValueError 를 발생시킵니다.

  • 옵션이 읽기 전용이면 (설정할 수 없으면) :exc:`ValueError`를 발생시킵니다.

  • value 가 적절한 타입이 아니면 TypeError 를 발생시킵니다.

호출하는 쪽은 :term:`attached thread state`가 필요합니다. 이 함수는 파이썬 초기화 전이나 파이썬 최종화 후에 호출될 수 없습니다.

인자 name, value 와 함께 auditing event cpython.PyConfig_Set 을 발생시킵니다.

Added in version 3.14.

PyConfig C API¶

Added in version 3.8.

파이썬은 Py_InitializeFromConfig() 와 PyConfig 구조체를 사용하여 초기화할 수 있습니다. 또한, Py_PreInitialize() 및 PyPreConfig 구조체로 미리 초기화할 수 있습니다.

다음 두 종류의 구성이 있습니다:

  • :ref:`Python Configuration <init-python-config>`은 일반 파이썬처럼 동작하는 맞춤화된 파이썬을 구축하는 데 사용할 수 있습니다. 예를 들어, 환경 변수 및 명령줄 인자가 파이썬을 구성하는 데 사용됩니다.

  • :ref:`Isolated Configuration <init-isolated-conf>`은 파이썬을 애플리케이션에 임베드(embed)할 때 사용할 수 있습니다. 이는 시스템으로부터 파이썬을 격리합니다. 예를 들어, 환경 변수는 무시되고, LC_CTYPE 로케일은 변경되지 않으며, 시그널 핸들러는 등록되지 않습니다.

Py_RunMain() 함수는 사용자 정의 Python 프로그램을 작성하는 데 사용될 수 있습니다.

초기화, 파이널리제이션 및 스레드도 참조하십시오.

더 보기

PEP 587 “파이썬 초기화 구성”.

예시¶

항상 격리 모드에서 실행되는 사용자 정의 파이썬의 예:

int main(int argc, char **argv)
{
    PyStatus status;

    PyConfig config;
    PyConfig_InitPythonConfig(&config);
    config.isolated = 1;

    /* Decode command line arguments.
       Implicitly preinitialize Python (in isolated mode). */
    status = PyConfig_SetBytesArgv(&config, argc, argv);
    if (PyStatus_Exception(status)) {
        goto exception;
    }

    status = Py_InitializeFromConfig(&config);
    if (PyStatus_Exception(status)) {
        goto exception;
    }
    PyConfig_Clear(&config);

    return Py_RunMain();

exception:
    PyConfig_Clear(&config);
    if (PyStatus_IsExit(status)) {
        return status.exitcode;
    }
    /* Display the error message and exit the process with
       non-zero exit code */
    Py_ExitStatusException(status);
}

        return PyStatus_NoMemory();

    return PyStatus_Ok();
}

{
    void *ptr;
    PyStatus status = alloc(&ptr, 16);
    if (PyStatus_Exception(status)) {
        Py_ExitStatusException(status);
    }

    return 0;

PyPreConfig을 사용하여 Python을 사전 초기화합니다.¶

Python의 사전 초기화:

  • Python 메모리 할당자 설정 (PyPreConfig.allocator)

  • Configure the LC_CTYPE locale (locale encoding)

  • Python UTF-8 모드 (PyPreConfig.utf8_mode)를 설정합니다.

현재 사전 구성 (PyPreConfig 타입)은 _PyRuntime.preconfig 에 저장됩니다.

파이썬을 사전 초기화하는 함수:

preconfig 사전 구성에서 파이썬을 사전 초기화합니다.

preconfig 는 NULL 이 아니어야 합니다.

preconfig 사전 구성에서 파이썬을 사전 초기화합니다.

:c:member:`~PyPreConfig.parse_argv`가 0이 아닌 경우 preconfig*의 *argv 명령줄 인자(바이트 문자열)를 구문 분석합니다.

preconfig 는 NULL 이 아니어야 합니다.

PyStatus Py_PreInitializeFromArgs(const PyPreConfig *preconfig, int argc, wchar_t *const *argv)¶

preconfig 사전 구성에서 파이썬을 사전 초기화합니다.

:c:member:`~PyPreConfig.parse_argv`가 0이 아닌 경우 preconfig*의 *argv 명령줄 인자(와이드 문자열)를 구문 분석합니다.

preconfig 는 NULL 이 아니어야 합니다.

호출자는 PyStatus_Exception()과 Py_ExitStatusException() 을 사용하여 예외(에러나 종료)를 처리해야 합니다.

Python 초기화 구성 (PyPreConfig_InitPythonConfig())의 경우, Python이 명령줄 인자와 함께 초기화되면, 해당 인자들은 인코딩과 같이 사전 구성에 영향을 미치므로 preinitialize Python으로 전달되어야 합니다. 예를 들어, -X utf8 명령줄 옵션은 :ref:`Python UTF-8 모드 <utf8-mode>`를 활성화합니다.

PyMem_SetAllocator()는 Py_PreInitialize() 이후에 Py_InitializeFromConfig() 이전에 호출하여 사용자 정의 메모리 할당자를 설치할 수 있습니다. PyPreConfig.allocator가 PYMEM_ALLOCATOR_NOT_SET으로 설정되면 Py_PreInitialize() 전에 호출할 수 있습니다.

PyMem_RawMalloc() 와 같은 Python 메모리 할당 함수는 Python 사전 초기화 이전에 사용해서는 안 되며, malloc() 및 free() 를 직접 호출하는 것은 항상 안전합니다. Py_DecodeLocale() 은 Python 사전 초기화 전에 호출되어서는 안 됩니다.

:ref:`Python UTF-8 모드 <utf8-mode>`를 활성화하는 사전 초기화 예시:

PyStatus status;
PyPreConfig preconfig;
PyPreConfig_InitPythonConfig(&preconfig);

preconfig.utf8_mode = 1;

status = Py_PreInitialize(&preconfig);
if (PyStatus_Exception(status)) {
    Py_ExitStatusException(status);
}

/* 이 시점에서 파이썬은 UTF-8을 사용하여 통신합니다 */

Py_Initialize();
/* ... 여기서 Python API를 사용 ... */
Py_Finalize();

PyStatus PyConfig_Read(PyConfig *config)¶

모든 파이썬 구성을 읽습니다.

이미 초기화된 필드는 변경되지 않습니다.

Python 3.11 버전부터 이 함수를 호출할 때 path configuration 필드는 더 이상 계산되거나 수정되지 않습니다.

The PyConfig_Read() function only parses PyConfig.argv arguments once: PyConfig.parse_argv is set to 2 after arguments are parsed. Since Python arguments are stripped from PyConfig.argv, parsing arguments twice would parse the application options as Python options.

필요한 경우 :ref:`Preinitialize Python <c-preinit>`을 참조하세요.

버전 3.10에서 변경: 이제 PyConfig.argv 인수는 한 번만 파싱됩니다. 인수 파싱 후 PyConfig.parse_argv 가 2 로 설정되며, PyConfig.parse_argv 가 1 인 경우에만 인수가 파싱됩니다.

버전 3.11에서 변경: :c:func:`PyConfig_Read`는 모든 경로를 계산하지 않으므로, :c:func:`Py_InitializeFromConfig`가 호출될 때까지 :ref:`Python Path Configuration <init-path-config>`에 나열된 필드는 업데이트되지 않을 수 있습니다.

void PyConfig_Clear(PyConfig *config)¶

구성 메모리를 해제합니다.

Most PyConfig methods preinitialize Python if needed. In that case, the Python preinitialization configuration (PyPreConfig) is based on the PyConfig. If configuration fields which are in common with PyPreConfig are tuned, they must be set before calling a PyConfig method:

  • PyConfig.dev_mode

  • PyConfig.isolated

  • PyConfig.parse_argv

  • PyConfig.use_environment

또한, PyConfig_SetArgv() 또는 :c:func:`PyConfig_SetBytesArgv`가 사용되는 경우, 전 초기화 구성이 명령 줄 인수에 의존하므로 (만약 :c:member:`~PyConfig.parse_argv`가 0이 아니면), 이 메서드는 다른 메서드보다 먼저 호출되어야 합니다.

이 메서드의 호출자는 PyStatus_Exception()과 Py_ExitStatusException() 을 사용하여 예외(에러나 종료)를 처리해야 합니다.

구조체 필드:

PyWideStringList argv¶

argv 를 기반으로 sys.argv 명령 줄 인자를 설정합니다. 이 매개변수는 프로그램의 main() 에 전달되는 것과 유사하지만, 첫 번째 항목이 파이썬 인터프리터를 호스팅하는 실행 파일이 아니라 실행될 스크립트 파일을 참조해야 한다는 차이점이 있습니다. 실행할 스크립트가 없으면, argv 의 첫 번째 항목은 빈 문자열일 수 있습니다.

Set parse_argv to 1 to parse argv the same way the regular Python parses Python command line arguments and then to strip Python arguments from argv.

만약 :c:member:`~PyConfig.argv`가 비어 있으면, :data:`sys.argv`가 항상 존재하고 절대 비어 있지 않도록 빈 문자열이 추가됩니다.

기본값: NULL.

PyConfig를 사용한 초기화¶

구성 구조체에서 인터프리터를 초기화하는 것은 :c:func:`Py_InitializeFromConfig`를 호출하여 처리됩니다.

호출자는 PyStatus_Exception()과 Py_ExitStatusException() 을 사용하여 예외(에러나 종료)를 처리해야 합니다.

만약 PyImport_FrozenModules(), PyImport_AppendInittab() 또는 PyImport_ExtendInittab() 가 사용된다면, 파이썬 사전 초기화 후 그리고 파이썬 초기화 전에 설정되거나 호출되어야 합니다. 파이썬이 여러 번 초기화되는 경우, 각 파이썬 초기화 전에 PyImport_AppendInittab() 또는 PyImport_ExtendInittab() 가 호출되어야 합니다.

현재 구성(PyConfig 타입)은 PyInterpreterState.config 에 저장됩니다.

프로그램 이름을 설정하는 예:

void init_python(void)
{
    PyStatus status;

    PyConfig config;
    PyConfig_InitPythonConfig(&config);

    /* 프로그램을 이름 지정합니다. 암시적으로 파이썬을 사전 초기화합니다. */
    status = PyConfig_SetString(&config, &config.program_name,
                                L"/path/to/my_program");
    if (PyStatus_Exception(status)) {
        goto exception;
    }

    status = Py_InitializeFromConfig(&config);
    if (PyStatus_Exception(status)) {
        goto exception;
    }
    PyConfig_Clear(&config);
    return;

exception:
    PyConfig_Clear(&config);
    Py_ExitStatusException(status);
}

기본 구성을 수정하는 더 완전한 예입니다. 구성을 읽은 다음 일부 파라미터를 재정의합니다. 3.11 버전부터 많은 파라미터가 초기화될 때까지 계산되지 않으며, 따라서 값은 구성 구조체에서 읽을 수 없다는 점에 유의하십시오. initialize가 호출되기 전에 설정된 모든 값은 초기화에 의해 변경되지 않습니다:

PyStatus init_python(const char *program_name)
{
    PyStatus status;

    PyConfig config;
    PyConfig_InitPythonConfig(&config);

    /* Set the program name before reading the configuration
       (decode byte string from the locale encoding).

       Implicitly preinitialize Python. */
    status = PyConfig_SetBytesString(&config, &config.program_name,
                                     program_name);
    if (PyStatus_Exception(status)) {
        goto done;
    }

    /* Read all configuration at once */
    status = PyConfig_Read(&config);
    if (PyStatus_Exception(status)) {
        goto done;
    }

    /* Specify sys.path explicitly */
    /* If you want to modify the default set of paths, finish
       initialization first and then use PySys_GetAttrString("path") */
    config.module_search_paths_set = 1;
    status = PyWideStringList_Append(&config.module_search_paths,
                                     L"/path/to/stdlib");
    if (PyStatus_Exception(status)) {
        goto done;
    }
    status = PyWideStringList_Append(&config.module_search_paths,
                                     L"/path/to/more/modules");
    if (PyStatus_Exception(status)) {
        goto done;
    }

    /* Override executable computed by PyConfig_Read() */
    status = PyConfig_SetString(&config, &config.executable,
                                L"/path/to/my_executable");
    if (PyStatus_Exception(status)) {
        goto done;
    }

    status = Py_InitializeFromConfig(&config);

done:
    PyConfig_Clear(&config);
    return status;
}

격리된 구성¶

PyPreConfig_InitIsolatedConfig()와 PyConfig_InitIsolatedConfig() 함수는 시스템에서 파이썬을 격리하는 구성을 만듭니다. 예를 들어, 파이썬을 응용 프로그램에 내장하기 위해.

This configuration ignores global configuration variables, environment variables, command line arguments (PyConfig.argv is not parsed) and user site directory. The C standard streams (ex: stdout) and the LC_CTYPE locale are left unchanged. Signal handlers are not installed.

구성 파일을 사용하여 기본 경로가 지정되지 않은 경우에도 여전히 사용됩니다. 기본 경로 구성을 계산하는 것을 방지하려면 :c:member:`PyConfig.home`이 지정되었는지 확인하십시오.

파이썬 구성¶

PyPreConfig_InitPythonConfig()와 PyConfig_InitPythonConfig() 함수는 일반 파이썬처럼 동작하는 사용자 정의된 파이썬을 빌드하기 위한 구성을 만듭니다.

환경 변수와 명령 줄 인자는 파이썬을 구성하는 데 사용되는 반면, 전역 구성 변수는 무시됩니다.

This function enables C locale coercion (PEP 538) and Python UTF-8 Mode (PEP 540) depending on the LC_CTYPE locale, PYTHONUTF8 and PYTHONCOERCECLOCALE environment variables.

파이썬 경로 구성¶

PyConfig에는 경로 구성을 위한 여러 필드가 포함되어 있습니다:

  • 경로 구성 입력:

    • PyConfig.home

    • PyConfig.platlibdir

    • PyConfig.pathconfig_warnings

    • PyConfig.program_name

    • PyConfig.pythonpath_env

    • 현재 작업 디렉터리: 절대 경로를 얻기 위해

    • (PyConfig.program_name에서) 프로그램 전체 경로를 얻기 위한 PATH 환경 변수

    • __PYVENV_LAUNCHER__ 환경 변수

    • (윈도우 전용) HKEY_CURRENT_USER와 HKEY_LOCAL_MACHINE의 “SoftwarePythonPythonCoreX.YPythonPath” 아래에 있는 레지스트리의 응용 프로그램 경로 (여기서 X.Y는 파이썬 버전입니다).

  • 경로 구성 출력 필드:

    • PyConfig.base_exec_prefix

    • PyConfig.base_executable

    • PyConfig.base_prefix

    • PyConfig.exec_prefix

    • PyConfig.executable

    • PyConfig.module_search_paths_set, PyConfig.module_search_paths

    • PyConfig.prefix

If at least one “output field” is not set, Python calculates the path configuration to fill unset fields. If module_search_paths_set is equal to 0, module_search_paths is overridden and module_search_paths_set is set to 1.

위에 나열된 모든 경로 구성 출력 필드를 명시적으로 설정하여 기본 경로 구성을 계산하는 것을 완전히 무시할 수 있습니다. 문자열은 비어 있지 않은 경우에도 설정된 것으로 간주됩니다. module_search_paths_ 는 module_search_paths_set 가 1 로 설정되면 설정된 것으로 간주됩니다. 이 경우, module_search_paths_ 가 수정 없이 사용됩니다.

경로 구성 계산 시 경고를 억제하려면 pathconfig_warnings 를 0 으로 설정하십시오 (유닉스 전용, 윈도우는 모든 경고를 기록하지 않음).

base_prefix나 base_exec_prefix 필드가 설정되지 않으면, 각각 prefix와 exec_prefix의 값을 상속합니다.

Py_RunMain()과 Py_Main()은 sys.path를 수정합니다:

  • run_filename이 설정되고 __main__.py 스크립트를 포함하는 디렉터리이면, run_filename을 sys.path 앞에 추가합니다.

  • isolated가 0이면:

    • run_module이 설정되면, 현재 디렉터리를 sys.path 앞에 추가합니다. 현재 디렉터리를 읽을 수 없으면 아무것도 하지 않습니다.

    • run_filename이 설정되면, 파일명의 디렉터리를 sys.path 앞에 추가합니다.

    • 그렇지 않으면, 빈 문자열을 sys.path 앞에 추가합니다.

site_import가 0이 아니면, site 모듈이 sys.path를 수정할 수 있습니다. user_site_directory가 0이 아니고 사용자의 site-package 디렉터리가 존재하면, site 모듈은 사용자의 site-package 디렉터리를 sys.path에 추가합니다.

다음과 같은 구성 파일이 경로 구성에 사용됩니다:

  • pyvenv.cfg

  • ._pth 파일(예: python._pth)

  • pybuilddir.txt (유닉스 전용)

._pth 파일이 있는 경우:

  • isolated 를 1 로 설정합니다.

  • use_environment 를 0 으로 설정합니다.

  • site_import 를 0 으로 설정합니다.

  • user_site_directory 를 0 으로 설정합니다 (3.15부터).

  • safe_path 를 1 로 설정합니다.

home 이 지정되지 않았고, executable 과 동일한 디렉터리에 pyvenv.cfg 파일이 있거나 그 부모에 존재하며, prefix 와 exec_prefix 가 설정된 경우 해당 위치를 사용합니다. 이런 일이 발생하면 base_prefix 와 base_exec_prefix 는 여전히 값을 유지하며 기본 설치를 가리킵니다. 자세한 내용은 가상 환경 를 참조하십시오.

__PYVENV_LAUNCHER__ 환경 변수는 :c:member:`PyConfig.base_executable`을 설정하는 데 사용됩니다.

버전 3.14에서 변경: prefix 와 exec_prefix 는 이제 pyvenv.cfg 디렉터리로 설정됩니다. 이전에는 site 가 이 작업을 수행했기 때문에 -S 에 영향을 받습니다.

버전 3.15에서 변경: user_site_directory 는 ._pth 파일이 존재할 때 0으로 설정됩니다.

다단계 초기화 비공개 잠정적 API¶

이 섹션은 PEP 432의 핵심 기능인 다단계 초기화를 소개하는 비공개 잠정적 API입니다:

  • “핵심(Core)” 초기화 단계, “최소한의 파이썬”:

    • 내장형;

    • 내장 예외;

    • 내장과 프로즌 모듈(frozen modules);

    • sys 모듈은 부분적으로만 초기화됩니다 (예를 들어: sys.path는 아직 존재하지 않습니다).

  • “주(Main)” 초기화 단계, 파이썬이 완전히 초기화됩니다:

    • importlib를 설치하고 구성합니다;

    • 경로 구성을 적용합니다;

    • 시그널 핸들러 설치;

    • sys 모듈 초기화를 완료합니다 (예를 들어: sys.stdout과 sys.path를 만듭니다);

    • faulthandler와 tracemalloc과 같은 선택적 기능을 활성화합니다;

    • site 모듈을 임포트 합니다;

    • 등등

비공개 잠정적 API:

int PyConfig._init_main¶

0으로 설정되면, :c:func:`Py_InitializeFromConfig`는 “Core” 초기화 단계에서 멈춥니다.

PyStatus _Py_InitializeMain(void)¶

“주” 초기화 단계로 이동하여, 파이썬 초기화를 완료합니다.

“핵심” 단계에서는 아무런 모듈도 임포트 하지 않고 importlib 모듈이 구성되지 않습니다: 경로 구성은 “주” 단계에서만 적용됩니다. 경로 구성을 재정의하거나 조정하기 위해 파이썬에서 파이썬을 사용자 정의할 수 있으며, 사용자 정의 sys.meta_path 임포터(importer)나 임포트 훅 등을 설치할 수 있습니다.

핵심 단계 이후에 주 단계 이전에 파이썬에서 경로 구성을 계산할 수 있게 될 수 있고, 이것이 PEP 432의 동기 중 하나입니다.

“핵심” 단계가 제대로 정의되지 않았습니다: 이 단계에서 무엇을 사용할 수 있고, 무엇이 그렇지 않아야 하는지는 아직 지정되지 않았습니다. API는 비공개이자 잠정적인 것으로 표시됩니다: 적절한 공개 API가 설계될 때까지 언제든지 API를 수정하거나 제거할 수 있습니다.

“핵심”과 “주” 초기화 단계 사이에서 파이썬 코드를 실행하는 예제:

void init_python(void)
{
    PyStatus status;

    PyConfig config;
    PyConfig_InitPythonConfig(&config);
    config._init_main = 0;

    /* ... 'config' 구성 사용자 정의 ... */

    status = Py_InitializeFromConfig(&config);
    PyConfig_Clear(&config);
    if (PyStatus_Exception(status)) {
        Py_ExitStatusException(status);
    }

    /* sys.stdout은 _Py_InitializeMain()에 의해서만 생성되므로 sys.stderr을 사용합니다. */
    int res = PyRun_SimpleString(
        "import sys; "
        "print('Run Python code before _Py_InitializeMain', "
               "file=sys.stderr)");
    if (res < 0) {
        exit(1);
    }

    /* ... 여기에 더 많은 구성 코드를 추가합니다 ... */

    status = _Py_InitializeMain();
    if (PyStatus_Exception(status)) {
        Py_ExitStatusException(status);
    }
}
