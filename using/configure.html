3. Python 구성¶

3.1. 빌드 변경¶

CPython을 빌드하려면 다음이 필요합니다:

  • A C11 compiler. Optional C11 features are not required.

  • Windows에서는 Microsoft Visual Studio 2017 이상이 필요합니다.

  • IEEE 754 부동 소수점 숫자 및 floating-point Not-a-Number (NaN) 지원.

  • 스레드 지원입니다.

버전 3.5에서 변경: 윈도우에서는 Visual Studio 2015 이상 버전이 필요합니다.

버전 3.6에서 변경: 선택된 C99 기능, 예: <stdint.h> 및 static inline 함수는 이제 필수입니다.

버전 3.7에서 변경: 스레드 지원이 필요합니다.

버전 3.11에서 변경: C11 컴파일러, IEEE 754 및 NaN 지원이 이제 요구됩니다. Windows에서는 Visual Studio 2017 이상 버전을 요구합니다.

또한 PEP 7 “C 코드 스타일 가이드” 및 PEP 11 “CPython 플랫폼 지원”을 참조하십시오.

3.1.1. 선택적 모듈 요구사항¶

표준 라이브러리의 일부 :term:`optional modules <optional module>`은 개발을 위해 타사 라이브러리 설치를 요구합니다 (예: 헤더 파일 사용 가능해야 함).

누락된 요구 사항은 configure 출력에서 보고됩니다. 누락된 종속성으로 인해 누락되는 모듈은 make 출력의 끝부분 근처에 나열되며, 때로는 내부 이름 (예: ctypes 모듈의 경우 _ctypes)을 사용합니다.

선택적 모듈 없이 CPython 인터프리터를 배포하는 경우, 표준 라이브러리 모듈이 이용 가능할 것이라고 일반적으로 기대할 사용자들에게 조언하는 것이 가장 좋습니다.

3.2. 생성된 파일¶

빌드 종속성을 줄이려면, Python 소스 코드에는 여러 생성된 파일들이 포함되어 있습니다. 모든 생성된 파일을 재생성하는 명령어:

make regen-all
make regen-stdlib-module-names
make regen-limited-abi
make regen-configure

Makefile.pre.in 파일은 생성된 파일, 그 입력값 및 재생성에 사용되는 도구를 문서화합니다. regen-* make 타겟을 검색해 보세요.

3.2.1. configure 스크립트 <configure script>¶

make regen-configure 명령어는 Tools/build/regen-configure.sh 셸 스크립트를 사용하여 aclocal.m4 파일과 configure 스크립트를 재생성합니다. 이 스크립트는 동일한 도구 버전과 재현 가능한 출력을 얻기 위해 Ubuntu 컨테이너를 사용합니다.

컨테이너는 선택 사항이며, 다음 명령어는 로컬에서 실행할 수 있습니다:

autoreconf -ivf -Werror

생성된 파일은 사용되는 도구의 정확한 버전에 따라 변경될 수 있습니다. CPython이 사용하는 컨테이너는 Autoconf 2.72, aclocal (Automake <https://www.gnu.org/software/automake>`_ ) 1.16.5, 그리고 pkg-config 1.8.1을 사용합니다.

버전 3.13에서 변경: :file:`configure`를 재생성하는 데 이제 Autoconf 2.71과 aclocal 1.16.5이 사용됩니다.

버전 3.14에서 변경: :file:`configure`를 재생성하는 데 이제 Autoconf 2.72가 사용됩니다.

3.3. 구성 옵션 <Configure Options>¶

다음 명령을 사용하여 모든 configure 스크립트 옵션을 나열합니다:

./configure --help

Python 소스 배포판의 :file:`Misc/SpecialBuilds.txt`도 참조하세요.

3.3.1. 일반 옵션 <General Options>¶

--enable-loadable-sqlite-extensions¶

sqlite3 모듈의 _sqlite 확장 모듈에서 로드 가능한 확장을 지원합니다 (기본값은 아니요).

sqlite3 모듈의 sqlite3.Connection.enable_load_extension() 메서드를 참조하세요.

Added in version 3.6.

--disable-ipv6¶

IPv6 지원을 비활성화합니다 (지원되는 경우 기본적으로 활성화됨). socket 모듈을 참조하세요.

--enable-big-digits=[15|30]¶

Python int 자릿수의 크기를 비트 단위로 정의합니다: 15비트 또는 30비트.

기본값은 30입니다.

PYLONG_BITS_IN_DIGIT 를 15 또는 30 으로 정의합니다.

:data:`sys.int_info.bits_per_digit <sys.int_info>`를 참조하세요.

--with-suffix=SUFFIX¶

Python 실행 파일 접미사를 SUFFIX 로 설정합니다.

기본 접미사는 Windows와 macOS에서 .exe 이며(실행 파일 이름: python.exe), Emscripten node에서는 .js, Emscripten 브라우저에서는 .html, WASI에서는 .wasm 이고, 기타 플랫폼에서는 빈 문자열입니다 (실행 파일 이름: python).

버전 3.11에서 변경: WASM 플랫폼의 기본 접미사는 .js, .html 또는 .wasm 중 하나입니다.

--with-tzpath=<list of absolute paths separated by pathsep>¶

zoneinfo.TZPATH`에 대한 기본 시간대 검색 경로를 지정합니다. :mod:`zoneinfo 모듈의 :ref:`컴파일 시간 설정 <zoneinfo_data_compile_time_config>`을 참조하세요.

기본값: /usr/share/zoneinfo:/usr/lib/zoneinfo:/usr/share/lib/zoneinfo:/etc/zoneinfo 입니다.

os.pathsep 경로 구분자를 참조하세요.

Added in version 3.9.

--without-decimal-contextvar¶

코루틴 로컬 컨텍스트 대신 스레드 로컬 컨텍스트를 사용하여 _decimal 확장 모듈을 빌드합니다 (기본값). decimal 모듈을 참조하세요.

decimal.HAVE_CONTEXTVAR 및 contextvars 모듈을 참조하세요.

Added in version 3.9.

--with-dbmliborder=<list of backend names>¶

dbm 모듈의 검사를 위한 오버라이드 순서를 지정합니다.

만료한 백엔드 이름들로 구성된 콜론(:)으로 구분된 유효한 문자열입니다:

  • ndbm;

  • gdbm;

  • bdb.

--without-c-locale-coercion¶

UTF-8 기반 로케일로 C 로케일 강제 변환을 비활성화합니다 (기본값).

PY_COERCE_C_LOCALE 매크로를 정의하지 마십시오.

PYTHONCOERCECLOCALE 및 :pep:`538`을 참조하십시오.

--with-platlibdir=DIRNAME¶

파이썬 라이브러리 디렉터리 이름입니다 (기본값은 lib).

페도라(Fedora)와 수제(SuSE)는 64비트 플랫폼에서 lib64 를 사용합니다.

:data:`sys.platlibdir`을 참조하십시오.

Added in version 3.9.

--with-wheel-pkg-dir=PATH¶

ensurepip 모듈이 사용하는 휠 패키지 디렉터리 이름입니다 (기본값 없음).

일부 리눅스 배포판의 패키징 정책은 종속성을 번들링하는 것을 권장하지 않습니다. 예를 들어, 페도라(Fedora)는 휠 패키지를 /usr/share/python-wheels/ 디렉터리에 설치하며 ensurepip._bundled 패키지는 설치하지 않습니다.

Added in version 3.10.

--with-pkg-config=[check|yes|no]¶

구성 시 :program:`pkg-config`를 사용하여 빌드 종속성을 감지할지 여부입니다.

  • check (기본값): :program:`pkg-config`는 선택 사항입니다.

  • yes: :program:`pkg-config`가 필수입니다.

  • no: 구성 시에 :program:`pkg-config`가 존재하더라도 사용하지 않습니다.

Added in version 3.11.

--with-missing-stdlib-config=FILE¶

Path to a JSON configuration file containing custom error messages for missing standard library modules.

이 옵션은 사용자가 누락되었거나 별도로 패키징된 표준 라이브러리 모듈을 마주칠 때 배포판별 지침을 제공하려는 파이썬 배포자들을 위한 것입니다.

JSON 파일은 누락된 모듈 이름을 사용자 정의 오류 메시지 문자열에 매핑해야 합니다. 예를 들어, 사용자의 배포판이 tkinter 및 _tkinter`를 별도로 패키징하고 법적 이유로 :mod:!_gdbm`을 제외하는 경우, 구성 파일에는 다음과 같은 내용이 포함될 수 있습니다:

{
    "_gdbm": "The '_gdbm' module is not available in this distribution",
    "tkinter": "Install the python-tk package to use tkinter",
    "_tkinter": "Install the python-tk package to use tkinter",
}

Added in version 3.15.

--enable-pystats¶

내부 파이썬 성능 통계 수집을 <0xEC><0xBC><0xAD>니다.

기본적으로 통계 수집은 꺼져 있습니다. 스크립트 시작 시 통계 수집을 켜려면 python3 -X pystats 명령을 사용하거나 PYTHONSTATS=1 환경 변수를 설정하십시오.

파이썬 종료 시, 통계를 수집했으며 지워지지 않았으면 통계를 덤프합니다.

효과:

  • -X pystats 명령줄 옵션을 추가합니다.

  • PYTHONSTATS 환경 변수를 추가합니다.

  • Py_STATS 매크로를 정의합니다.

  • sys 모듈에 함수들을 추가합니다:

    • sys._stats_on(): 통계 수집을 <0xEC><0xBC><0xAD>니다.

    • sys._stats_off(): 통계 수집을 <0xEB><0x81><0x95>니다.

    • sys._stats_clear(): 통계를 지웁니다.

    • sys._stats_dump(): 통계를 파일로 덤프하고, 통계를 지웁니다.

통계는 /tmp/py_stats/ (Unix) 또는 C:\temp\py_stats\ (Windows)에 있는 임의의 (아마도 고유한) 파일에 덤프됩니다. 해당 디렉터리가 존재하지 않으면, 결과가 stderr에 출력됩니다.

통계를 읽으려면 Tools/scripts/summarize_stats.py 를 사용하십시오.

통계:

  • Opcode:

    • 특수화 유형: 성공, 실패, 히트, 지연됨, 누락됨, 탈출, 실패;

    • 실행 횟수;

    • 쌍(Pair) 개수.

  • 호출:

    • 인라인된 파이썬 호출;

    • PyEval 호출;

    • 푸시된 프레임;

    • 생성된 프레임 객체;

    • Eval 호출: 벡터, 생성기, 레거시, 함수 VECTORCALL, 클래스 빌드, 슬롯, 함수 “ex”, API, 메서드.

  • 객체:

    • 증가(incref) 및 감소(decref);

    • 인터프리터 증가(incref) 및 감소(decref);

    • 할당: 모든, 512 바이트, 4 kiB, 대용량;

    • 자유(free);

    • free 리스트에 추가/제거;

    • 딕셔너리 물질화됨/비물질화됨;

    • 타입 캐시;

    • 최적화 시도;

    • 최적화 추적이 생성/실행되었습니다;

    • 실행된 우롭 수.

  • 가비지 컬렉터:

    • 가비지 컬렉션 횟수;

    • 방문된 <term id=”Objects”>객체</term> 수;

    • 수거된 객체 수.

Added in version 3.11.

--disable-gil¶

Enables support for running Python without the global interpreter lock (GIL): free-threaded build.

Py_GIL_DISABLED 매크로를 정의하고 sys.abiflags`에 `”t”`` 를 추가합니다.

자세한 내용은 :ref:`whatsnew313-free-threaded-cpython`<span id=”content”>`</span>을 참조하십시오.

Added in version 3.13.

--enable-experimental-jit=[no|yes|yes-off|interpreter]¶

:ref:`experimental just-in-time compiler <whatsnew314-jit-compiler>`를 통합하는 방법을 나타냅니다.

  • no: JIT를 빌드하지 않습니다.

  • yes: JIT를 활성화합니다. 런타임에 비활성화하려면 환경 변수 :envvar:`PYTHON_JIT=0 <PYTHON_JIT>`을 설정하십시오.

  • yes-off: JIT를 빌드하되, 기본값으로 비활성화합니다. 런타임에 활성화하려면 환경 변수 :envvar:`PYTHON_JIT=1 <PYTHON_JIT>`을 설정하십시오.

  • interpreter: “JIT 인터프리터”를 활성화합니다 (JIT 자체를 디버깅하는 경우에만 유용합니다). 런타임에 비활성화하려면 환경 변수 :envvar:`PYTHON_JIT=0 <PYTHON_JIT>`을 설정하십시오.

옵션을 제공하지 않은 경우 기본 동작은 --enable-experimental-jit=no 이며, --enable-experimental-jit 는 --enable-experimental-jit=yes 의 약어입니다. 필요한 빌드 시간 종속성 설치 방법 등 더 자세한 내용은 Tools/jit/README.md 를 참조하십시오.

참고

JIT가 활성화된 상태로 CPython을 빌드할 때는 시스템에 Python 3.11 이상이 설치되어 있는지 확인해야 합니다.

Added in version 3.13.

3.3.7. 성능 옵션¶

최적의 성능을 위해 --enable-optimizations --with-lto (PGO + LTO)를 사용하여 Python을 구성하는 것을 권장합니다. 실험적인 --enable-bolt 플래그도 성능 개선에 사용될 수 있습니다.

--enable-optimizations¶

:envvar:`PROFILE_TASK`를 사용하여 프로파일 기반 최적화(PGO)를 활성화합니다 (기본적으로 비활성화됨).

C 컴파일러 Clang은 PGO에 대해 llvm-profdata 프로그램을 필요로 합니다. macOS의 경우 GCC도 이를 요구합니다: macOS에서 GCC는 Clang의 별칭입니다.

–enable-shared`를 사용하고 GCC가 사용되는 경우, `libpython`에서의 의미론적 개입(semantic interposition)도 비활성화합니다: 컴파일러 및 링커 플래그에 `-fno-semantic-interposition``을 추가합니다.

참고

빌드 중에는 일부 소스 파일에 대해 프로파일 데이터가 사용 가능하지 않다는 컴파일러 경고가 발생할 수 있습니다. 이 경고는 무해하며, 프로파일 데이터 획득 중에 코드의 일부 하위 집합만 실행되기 때문입니다. Clang에서 이러한 경고를 비활성화하려면 CFLAGS`에 `-Wno-profile-instr-unprofiled``를 수동으로 추가하여 경고를 억제하십시오.

Added in version 3.6.

버전 3.10에서 변경: GCC에서 -fno-semantic-interposition 을 사용합니다.

PROFILE_TASK¶

Makefile에 사용되는 환경 변수: PGO 생성 작업을 위한 Python 명령줄 인자입니다.

기본값: -m test --pgo --timeout=$(TESTTIMEOUT) 입니다.

Added in version 3.8.

버전 3.13에서 변경: 태스크 실패는 더 이상 조용히 무시되지 않습니다.

모든 빌드에서 연결 시간 최적화(LTO)를 활성화합니다 (기본적으로 비활성화됨).

C 컴파일러 Clang은 LTO에 대해 llvm-ar``(macOS에서는 ``ar) 뿐만 아니라, LTO 인식 링커(ld.gold 또는 lld)를 필요로 합니다.

--enable-bolt¶

`BOLT post-link binary optimizer <https://github.com/llvm/llvm-project/tree/main/bolt>`_의 사용을 활성화합니다 (기본적으로 비활성화됨).

BOLT는 LLVM 프로젝트의 일부이지만, 빌드 배포판에 항상 포함되는 것은 아닙니다. 이 플래그는 llvm-bolt 와 merge-fdata 가 사용 가능하다는 것을 요구합니다.

BOLT는 여전히 상당히 새로운 프로젝트이므로, 현재는 실험적인 것으로 간주해야 합니다. 이 도구는 기계어에 작동하므로 그 성공은 빌드 환경 + 다른 최적화 구성 인자 + CPU 아키텍처의 조합에 따라 달라지며, 모든 조합이 지원되는 것은 아닙니다. LLVM 16 이전 버전의 BOLT는 일부 시나리오에서 BOLT 충돌을 일으킨 것으로 알려져 있습니다. BOLT 최적화를 위해 LLVM 16 이상을 사용하는 것이 강력히 권장됩니다.

BOLT_INSTRUMENT_FLAGS 및 BOLT_APPLY_FLAGS configure 변수를 정의하여 각각 `llvm-bolt`의 기본 인자 세트를 덮어쓰고, 바이너리에 BOLT 데이터를 주입하고 적용할 수 있습니다.

Added in version 3.12.

Added in version 3.12.

기본적으로 활성화되는 프레임 포인터를 비활성화합니다 (참고: PEP 831\).

기본적으로 빌드 시 BASECFLAGS 에 프레임 또는 백체인 포인터를 생성하기 위한 플래그가 추가됩니다.

  • 컴파일러가 지원하는 경우, -fno-omit-frame-pointer 및/또는 -mno-omit-leaf-frame-pointer 가 추가됩니다.

  • 지원되는 경우 32비트 ARM에서 -marm 및/또는 -mno-thumb 가 추가됩니다.

  • s390x 플랫폼에서는, 지원되는 경우 위의 프레임 포인터 플래그 대신에 `–mbackchain`이 추가됩니다.

  • ppc64le 플랫폼의 경우, 파워 ABI가 컴파일러에게 기본적으로 백 체인을 유지하도록 요구하므로 컴파일러 플래그는 필요하지 않습니다.

프레임 포인터는 프로파일러, 디버거 및 시스템 트레이싱 도구 (perf, eBPF, dtrace, gdb)가 DWARF 메타데이터 없이 C 호출 스택을 추적할 수 있게 합니다. 이 플래그는 :mod:`sysconfig`를 통해 서드파티 C 확장으로 전파됩니다. 이러한 플래그를 이해하지 못하는 컴파일러의 경우, 빌드는 자동으로 무시합니다.

커스텀 빌드 시스템으로 구축된 네이티브 라이브러리의 하위 패키지 작성자 및 작성자는 모든 네이티브 프레임에 걸쳐 언와인딩 체인이 끊어지지 않도록 동일한 플래그를 설정해야 합니다.

--with-pymalloc-hugepages¶

pymalloc 영역에 대한 유휴 페이지 지원을 활성화합니다 (기본적으로 비활성화됨). 활성화된 경우, 64비트 플랫폼의 영역 크기가 2MiB로 증가하며, 영역 할당은 MAP_HUGETLB (Linux) 또는 MEM_LARGE_PAGES (Windows)를 사용하고 일반 페이지로 자동으로 폴백합니다.

이 옵션으로 컴파일되었더라도, PYTHON_PYMALLOC_HUGEPAGES 환경 변수가 1 으로 설정되지 않는 한 런타임에 유휴 페이지는 사용되지 않습니다. 이 옵트인(opt-in)은 유휴 페이지가

  • Linux에서 위험을 초래할 수 있습니다: 만약 유휴 페이지 풀이 고갈되면, 페이지 폴트 ( os.fork() 이후의 copy-on-write fault 포함)가 SIGBUS 를 발생시키고 프로세스를 종료시킵니다.

  • Windows에서는 특별한 권한이 필요합니다. 자세한 내용은 `대형 페이지 지원에 대한 Windows 문서 <https://learn.microsoft.com/windows/win32/memory/large-page-support>`를 참조하십시오. 사용자가 필요한 권한인 `SeLockMemoryPrivilege <https://learn.microsoft.com/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/lock-pages-in-memory>`를 가지고 있지 않으면 Python은 시작 시 실패합니다.

configure 스크립트는 플랫폼이 MAP_HUGETLB 를 지원하는지 확인하고, 지원하지 않는 경우 경고 메시지를 방출합니다.

Windows에서는 build.bat`과 함께 `–pymalloc-hugepages`` 플래그를 사용하거나 UsePymallocHugepages MSBuild 속성을 설정하십시오.

Added in version 3.15.

3.3.8. Python 디버그 빌드¶

디버그 빌드는 --with-pydebug configure 옵션을 사용하여 구축된 Python입니다.

디버그 빌드의 효과:

  • 기본적으로 모든 경고를 표시합니다: warnings 모듈에서 기본 경고 필터 목록은 비어 있습니다.

  • sys.abiflags 에 d 를 추가하십시오.

  • sys.gettotalrefcount() 함수를 추가합니다.

  • 명령줄 옵션 -X showrefcount `을 추가합니다.

  • 파서 디버깅을 위해 -d 명령줄 옵션과 PYTHONDEBUG 환경 변수를 추가합니다.

  • 변수 __lltrace__ 지원을 추가합니다: 이 변수가 정의된 경우 바이트코드 평가 루프에서 낮은 수준의 추적을 활성화합니다.

  • 버퍼 오버플로우 및 기타 메모리 오류를 감지하기 위해 :ref:`메모리 할당자 <default-memory-allocators>`에 디버그 훅을 설치합니다.

  • Py_DEBUG 및 Py_REF_DEBUG 매크로를 정의합니다.

  • 런타임 검사를 추가합니다: #ifdef Py_DEBUG``와 ``#endif``로 둘러싸인 코드. ``assert(...) 및 _PyObject_ASSERT(...) 검사 활성화: NDEBUG 매크로는 설정하지 않습니다 (또한 --with-assertions 구성 옵션도 참조하십시오). 주요 런타임 검사:

    • 함수 인수에 대한 유효성 검사를 추가합니다.

    • 유니코드 및 int 객체는 초기화되지 않은 객체의 사용을 감지하기 위해 패턴으로 메모리가 채워지면서 생성됩니다.

    • 현재 예외를 지우거나 대체할 수 있는 함수가 예외와 함께 호출되지 않도록 보장합니다.

    • 할당 해제기가 현재 예외를 변경하지 않는지 확인합니다.

    • 가비지 컬렉터 (gc.collect() 함수)는 객체 일관성에 대한 기본 검사를 실행합니다.

    • Py_SAFE_DOWNCAST() 매크로는 넓은 유형에서 좁은 유형으로 다운캐스팅할 때 정수 언더플로우 및 오버플로우를 확인합니다.

또한 Python 개발 모드 <devmode>`와 :option:–with-trace-refs` 구성 옵션을 참조하십시오.

버전 3.8에서 변경: 릴리스 빌드는 이제 디버그 빌드와 ABI 호환됩니다: Py_DEBUG 매크로를 정의하는 것이 더 이상 Py_TRACE_REFS 매크로를 암시하지 않습니다 (참고: --with-trace-refs 옵션). 그러나 디버그 빌드는 여전히 릴리스 빌드보다 더 많은 심볼을 노출하며, 디버그 빌드로 작성된 코드가 반드시 릴리스 빌드와 호환되는 것은 아닙니다.

    --with-build-python=../x86_64/python

3.4. 파이썬 빌드 시스템¶

3.4.1. 빌드 시스템의 주요 파일들¶

  • configure.ac => configure;

  • Makefile.pre.in => Makefile ( :file:`configure`를 통해 생성됨);

  • pyconfig.h ( :file:`configure`를 통해 생성됨);

  • Modules/Setup: Module/makesetup 셸 스크립트를 사용하여 Makefile로 빌드된 C 확장 모듈입니다;

3.4.2. 주요 빌드 단계들¶

  • C 파일 (.c)은 객체 파일 (.o)로 빌드됩니다.

  • 정적 libpython 라이브러리 (.a)는 객체 파일로부터 생성됩니다.

  • python.o``와 정적 ``libpython 라이브러리가 최종 python 프로그램에 링크됩니다.

  • C 확장 모듈은 Makefile을 통해 빌드됩니다 ( Modules/Setup 참조).

3.4.3. 주요 Makefile 타겟들¶

3.4.3.1. make¶

대부분의 경우, 일부 코드를 편집하거나 업스트림으로부터 체크아웃을 새로 고침한 후 재빌드할 때, make 를 실행하기만 하면 됩니다. (Make의 의미에 따라) 이는 Makefile에서 정의된 첫 번째 기본 타겟을 빌드합니다. 전통적으로는 이 all 타겟인 경우가 많습니다 (CPython 프로젝트 포함). configure 스크립트는 @DEF_MAKE_ALL_RULE@ 이라는 자동감지 변수를 확장하여 make all 이 정확히 어떤 타겟을 빌드할지 설명합니다. 세 가지 선택지는 다음과 같습니다:

  • profile-opt (--enable-optimizations 로 구성됨)

  • build_wasm (호스트 플랫폼이 wasm32-wasi* 또는 wasm32-emscripten 인 경우 선택됨)

  • build_all (다른 옵션 중 어느 것도 명시적으로 사용하지 않고 구성됨)

가장 최근의 소스 파일 변경에 따라, Make는 필요한 경우 configure 를 다시 실행하는 것을 포함하여 최신 상태로 간주되는 모든 타겟 (객체 파일 및 실행 파일)을 재빌드합니다. 그러나 소스/대상 의존성은 많고 수동으로 관리되므로, Make가 재빌드가 필요한 모든 타겟을 정확하게 감지하는 데 필요한 모든 정보를 가지고 있지는 못한 경우가 있습니다. 어떤 타겟이 다시 빌드되지 않았는지에 따라 여러 문제가 발생할 수 있습니다. 달리 설명할 수 없는 빌드 또는 테스트 문제가 있다면, make clean && make 를 사용하면 일반적으로 대부분의 의존성 문제를 해결할 수 있지만, 빌드 시간이 길어지는 단점이 있습니다.

3.4.3.2. make platform¶

python 프로그램을 빌드하되, 표준 라이브러리 확장 모듈은 빌드하지 않습니다. 이 동작은 platform``이라는 파일을 생성하며, 파일에는 빌드 플랫폼의 세부 정보(예: ``macosx-14.3-arm64-3.12 또는 linux-x86_64-3.13)를 설명하는 단일 줄이 포함됩니다.

3.4.3.3. make profile-opt¶

프로파일 기반 최적화(PGO)를 사용하여 Python을 빌드합니다. configure``의 :option:`--enable-optimizations` 옵션을 사용하여 이를 `make` 명령의 기본 타겟 (``make all 또는 단순히 make)으로 설정할 수 있습니다.

3.4.3.4. make clean¶

빌드 파일을 제거합니다.

3.4.3.5. make distclean¶

make clean 작업 외에, configure 스크립트에 의해 생성된 파일들도 제거합니다. configure 를 다시 실행해야 빌드를 할 수 있습니다. [6]

3.4.3.6. make install¶

‘’all’’ 타겟을 빌드하고 Python을 설치합니다.

3.4.3.7. make test¶

‘’all’’ 타겟을 빌드하고 GUI 테스트 없이 --fast-ci 옵션으로 파이썬 테스트 스위트를 실행합니다. 변수:

  • TESTOPTS: 추가적인 regrtest 명령행 옵션입니다.

  • TESTPYTHONOPTS: 추가적인 Python 명령행 옵션입니다.

  • TESTTIMEOUT: 시간 초과를 초 단위로 지정합니다 (기본값: 10분).

3.4.3.8. make ci¶

이것은 make test 와 유사하지만, GUI 테스트도 실행하기 위해 -ugui 를 사용합니다.

Added in version 3.14.

3.4.3.9. make buildbottest¶

이것은 make test``와 유사하지만, ``--fast-ci 옵션 대신 –slow-ci 옵션과 기본 20분 시간 초과를 사용합니다.

3.4.3.10. make regen-all¶

대신, 원할 경우 이러한 파일을 강제로 재생성하기 위해 새로운 make regen-all 명령을 추가했습니다. 여기에는 (이에 국한되지 않지만) 바이트코드 케이스 및 파서 생성기 파일이 포함됩니다. 나머지 generated files 의 경우 make regen-stdlib-module-names 와 autoconf 를 별도로 실행해야 합니다.

3.4.4. C 확장은¶

일부 C 확장 기능은 sys 모듈과 같이 내장 모듈로 빌드됩니다. 이들은 Py_BUILD_CORE_BUILTIN 매크로가 정의되어 빌드됩니다. 내장 모듈에는 __file__ 속성이 없습니다:

>>> import sys
>>> sys
<module 'sys' (built-in)>
>>> sys.__file__
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
AttributeError: module 'sys' has no attribute '__file__'

다른 C 확장 기능은 _asyncio 모듈과 같이 동적 라이브러리로 빌드됩니다. 이들은 Py_BUILD_CORE_MODULE 매크로가 정의되어 빌드됩니다. Linux x86-64 예시:

>>> import _asyncio
>>> _asyncio
<module '_asyncio' from '/usr/lib64/python3.9/lib-dynload/_asyncio.cpython-39-x86_64-linux-gnu.so'>
>>> _asyncio.__file__
'/usr/lib64/python3.9/lib-dynload/_asyncio.cpython-39-x86_64-linux-gnu.so'

Modules/Setup`은 C 확장을 빌드하기 위한 Makefile 대상을 생성하는 데 사용됩니다. 파일 시작 부분에서, C 확장 기능은 내장 모듈로 빌드됩니다. ``*shared*` 마커 이후에 정의된 확장 기능은 동적 라이브러리로 빌드됩니다.

Include/exports.h`의 :c:macro:!PyAPI_FUNC()`, PyAPI_DATA() 및 PyMODINIT_FUNC 매크로는 Py_BUILD_CORE_MODULE 매크로가 정의되었는지 여부에 따라 다르게 정의됩니다:

  • Use Py_EXPORTED_SYMBOL if the Py_BUILD_CORE_MODULE is defined

  • 그렇지 않은 경우에는 Py_IMPORTED_SYMBOL 을 사용하십시오.

공유 라이브러리로 빌드된 C 확장에 실수로 Py_BUILD_CORE_BUILTIN 매크로를 사용하면, 해당 PyInit_xxx() 함수가 내보내지지 않아 모듈 임포트 시 :exc:`ImportError`이 발생합니다.

3.5. 컴파일러 및 링커 플래그들¶

./configure 스크립트와 환경 변수에 의해 설정되고 Makefile 에서 사용되는 옵션들입니다.

3.5.1. 전처리기 플래그들¶

CONFIGURE_CPPFLAGS¶

:envvar:`CPPFLAGS 변수에 ./configure 스크립트에 전달된 값입니다.

Added in version 3.6.

CPPFLAGS¶

(목적) C/C++ 전처리기 플래그들, 예: 표준이 아닌 디렉터리 include__dir 에 헤더가 있는 경우 -Iinclude_dir.

환경 변수에 지정된 디렉터리를 사용하여 확장 모듈을 빌드하려면, :envvar:`CPPFLAGS`와 `:envvar:`LDFLAGS 모두 쉘의 값을 포함해야 합니다.

BASECPPFLAGS¶

Added in version 3.4.

PY_CPPFLAGS¶

인터프리터 객체 파일을 빌드하기 위해 추가된 전처리기 플래그들입니다.

기본값: `$(BASECPPFLAGS) -I. -I$(srcdir)/Include $(CONFIGURE_CPPFLAGS) $(CPPFLAGS) “.

Added in version 3.2.

3.5.2. 컴파일러 플래그들¶

CC¶

C 컴파일러 명령어입니다.

예: gcc -pthread.

CXX¶

C++ 컴파일러 명령어입니다.

예: g++ -pthread.

CFLAGS¶

C 컴파일러 플래그들입니다.

CFLAGS_NODIST¶

:envvar:`CFLAGS_NODIST`는 인터프리터 및 stdlib C 확장을 빌드하는 데 사용됩니다. 컴파일러 플래그가 Python이 설치된 후 :envvar:`CFLAGS`의 일부가 *아니* 않아야 하는 경우에 사용합니다 (:gh:`65320).

특히, :envvar:`CFLAGS`에는 다음이 포함되어서는 안 됩니다:

  • 포함 파일의 검색 경로를 설정하는 컴파일러 플래그 -I``입니다. ``-I 플래그는 왼쪽에서 오른쪽으로 처리되며, CFLAGS`의 모든 플래그는 사용자 및 패키지 공급된 `-I`` 플래그보다 우선합니다.

  • 배포판이 사용자가 설치한 패키지가 그러한 강화된 표준을 준수하는지 제어할 수 없기 때문에 -Werror 와 같은 난독화 플래그는 피해야 합니다.

Added in version 3.5.

COMPILEALL_OPTS¶

make install``에서 PYC 파일을 빌드할 때 :mod:`compileall` 명령어에 전달되는 옵션입니다. 기본값: ``-j0.

Added in version 3.12.

EXTRA_CFLAGS¶

추가 C 컴파일러 플래그들입니다.

CONFIGURE_CFLAGS¶

:envvar:`CFLAGS 변수에 ./configure 스크립트에 전달된 값입니다.

Added in version 3.2.

CONFIGURE_CFLAGS_NODIST¶

:envvar:`CFLAGS_NODIST 변수에 ./configure 스크립트에 전달된 값입니다.

Added in version 3.5.

BASECFLAGS¶

기본 컴파일러 플래그들입니다.

OPT¶

최적화 플래그들입니다.

CFLAGS_ALIASING¶

Python/dtoa.c 를 컴파일하는 데 사용되는 엄격 또는 비엄격 별칭(aliasing) 플래그입니다.

Added in version 3.7.

CFLAGS_CEVAL¶

Python/ceval.c 를 컴파일하는 데 사용되는 플래그들입니다.

Added in version 3.14.5.

CCSHARED¶

공유 라이브러리를 빌드하는 데 사용되는 컴파일러 플래그입니다.

예를 들어, Linux 및 BSD에서는 -fPIC 가 사용됩니다.

CFLAGSFORSHARED¶

인터프리터 객체 파일을 빌드하기 위해 추가된 C 플래그들입니다.

Default: $(CCSHARED) when --enable-shared is used, or an empty string otherwise.

PY_CFLAGS¶

기본값: `$(BASECFLAGS) $(OPT) $(CONFIGURE_CFLAGS) $(CFLAGS) $(EXTRA_CFLAGS) “.

PY_CFLAGS_NODIST¶

기본값: $(CONFIGURE_CFLAGS_NODIST) $(CFLAGS_NODIST) -I$(srcdir)/Include/internal”.

Added in version 3.5.

PY_STDMODULE_CFLAGS¶

인터프리터 객체 파일을 빌드하는 데 사용되는 C 플래그들입니다.

기본값: `$(PY_CFLAGS_) $(PY_CFLAGS_NODIST) $(PY_CPPFLAGS) $(CFLAGSFORSHARED) “.

Added in version 3.7.

PY_CORE_CFLAGS¶

기본값: $(PY_STDMODULE_CFLAGS) -DPy_BUILD_CORE.

Added in version 3.2.

PY_BUILTIN_MODULE_CFLAGS¶

posix 모듈과 같은 표준 라이브러리 확장 모듈을 내장 모듈로 빌드하는 컴파일러 플래그입니다.

기본값: $(PY_STDMODULE_CFLAGS) -DPy_BUILD_CORE_BUILTIN.

Added in version 3.8.

PURIFY¶

Purify 명령어. Purify는 메모리 디버거 프로그램입니다.

기본값: 빈 문자열(사용되지 않음).

3.5.3. 링커 플래그들¶

LINKCC¶

라이브러리 이름인 python``과 ``_testembed 같은 프로그램을 빌드하는 데 사용되는 링커 명령어입니다.

기본값: $(PURIFY) $(CC).

CONFIGURE_LDFLAGS¶

./configure 스크립트에 전달되는 LDFLAGS 변수의 값입니다.

사용자가 설정된 값을 덮어쓰지 않고 명령어 라인에서 추가할 수 있도록 CFLAGS, LDFLAGS 등은 할당하는 것을 피하십시오.

Added in version 3.2.

LDFLAGS_NODIST¶

LDFLAGS_NODIST`는 :envvar:`CFLAGS_NODIST`와 동일한 방식으로 사용됩니다. Python이 설치된 후 링커 플래그가 :envvar:`LDFLAGS`의 일부여서는 *안* 되는 경우에 사용하십시오 (:gh:`65320).

특히, :envvar:`LDFLAGS`에는 다음 내용이 포함되지 않도록 합니다:

  • 컴파일러 플래그 -L``(라이브러리 검색 경로 설정용). ``-L 플래그는 왼쪽에서 오른쪽으로 처리되며, LDFLAGS`에 있는 모든 플래그는 사용자 및 패키지가 제공하는 `-L`` 플래그보다 우선합니다.

CONFIGURE_LDFLAGS_NODIST¶

./configure 스크립트에 전달되는 LDFLAGS_NODIST 변수의 값입니다.

Added in version 3.8.

LDFLAGS¶

라이브러리를 비표준 디렉토리 lib_dir 에 가지고 있는 경우, 예를 들어 -Llib_dir 와 같은 링커 플래그를 사용합니다.

환경 변수에 지정된 디렉터리를 사용하여 확장 모듈을 빌드하려면, :envvar:`CPPFLAGS`와 `:envvar:`LDFLAGS 모두 쉘의 값을 포함해야 합니다.

제공된 링커 플래그가 실행 파일별(executable specific)인 경우, 예를 들어 GCC의 -pie 플래그라면 EXE_LDFLAGS 를 사용하는 것을 고려하십시오.

LIBS¶

Python 실행 파일을 링크할 때 라이브러리를 링커에 전달하는 링커 플래그입니다.

예: -lrt 경.

LDSHARED¶

공유 라이브러리를 빌드하는 명령어입니다.

기본값: @LDSHARED@ $(PY_LDFLAGS).

BLDSHARED¶

libpython 공유 라이브러리를 빌드하는 명령어입니다.

기본값: @BLDSHARED@ $(PY_CORE_LDFLAGS).

PY_LDFLAGS¶

기본값: $(CONFIGURE_LDFLAGS) $(LDFLAGS).

PY_LDFLAGS_NODIST¶

기본값: $(CONFIGURE_LDFLAGS_NODIST) $(LDFLAGS_NODIST).

Added in version 3.8.

PY_CORE_LDFLAGS¶

인터프리터 객체 파일을 빌드하는 데 사용되는 링커 플래그입니다.

Added in version 3.8.

EXE_LDFLAGS¶

인터프리터와 같은 실행 가능한 대상(executable targets)을 빌드하는 데 사용되는 링커 플래그입니다. 제공되면, PY_CORE_LDFLAGS 대신 :envvar:`PY_CORE_EXE_LDFLAGS`가 사용됩니다.

Added in version 3.15.

CONFIGURE_EXE_LDFLAGS¶

./configure 스크립트에 전달되는 EXE_LDFLAGS 변수의 값입니다.

Added in version 3.15.

PY_CORE_EXE_LDFLAGS¶

인터프리터와 실행 가능한 대상(executable targets)을 빌드하는 데 사용되는 링커 플래그입니다.

기본값: $(PY_CORE_LDFLAGS)
