tkinter — Tcl/Tk 파이썬 인터페이스¶

소스 코드: Lib/tkinter/__init__.py

The tkinter package (“Tk interface”) is the standard Python interface to the Tcl/Tk GUI toolkit. Both Tk and tkinter are available on most Unix platforms, including macOS, as well as on Windows systems.

명령줄에서 python -m tkinter 를 실행하면 간단한 Tk 인터페이스를 시연하는 창을 열어, tkinter 가 시스템에 제대로 설치되었는지 알 수 있게 하며, 또한 어떤 버전의 Tcl/Tk가 설치되었는지 보여주므로, 해당 버전에 맞는 Tcl/Tk 문서를 읽을 수 있습니다.

Tkinter는 스레드 지원 여부와 상관없이 빌드된 다양한 Tcl/Tk 버전을 지원합니다. Tcl/Tk 8.5.12가 최소 지원 버전이며, 공식 파이썬 바이너리 배포판에는 Tcl/Tk 9.0이 포함되어 있습니다. 지원되는 버전에 대한 자세한 정보는 _tkinter 모듈의 소스 코드를 참조하십시오.

버전 3.11에서 변경: 8.5.12보다 오래된 Tcl/Tk 버전에 대한 지원이 제거되었습니다.

Tkinter는 얇은 래퍼가 아니며, 경험을 더욱 파이썬답게 만들기 위해 상당한 양의 고유 로직을 추가합니다. 이 문서는 이러한 추가 기능과 변경 사항에 초점을 맞추며, 변경되지 않은 세부 사항에 대해서는 공식 Tcl/Tk 문서를 참조합니다.

참고

Tcl/Tk 8.5 (2007)는 현대적인 테마의 사용자 인터페이스 구성 요소 세트와 이를 사용하기 위한 새 API를 도입했습니다. 구형 API와 신형 API 모두 여전히 사용할 수 있습니다. 온라인에서 찾을 수 있는 대부분의 문서는 여전히 구형 API를 사용하고 있어 심각하게 구식이 될 수 있습니다.

아키텍처¶

Tcl/Tk은 단일 라이브러리가 아니라, 각각 독립적인 기능과 자체 공식 문서를 가진 몇 개의 개별 모듈로 구성됩니다. Python의 바이너리 릴리스 또한 모듈과 함께 추가 모듈을 포함하여 제공합니다.

Tcl

Tcl은 Python과 마찬가지로 동적 인터프리터 언어입니다. 범용 프로그래밍 언어 자체로도 사용될 수 있지만, 가장 일반적으로는 C 애플리케이션에 스크립팅 엔진이나 Tk 툴킷으로의 인터페이스로 임베드됩니다. Tcl 라이브러리는 Tcl 인터프리터의 하나 이상을 생성하고 관리하며, 해당 인스턴스에서 Tcl 명령과 스크립트를 실행하고, Tcl이나 C로 구현된 사용자 정의 명령을 추가하기 위한 C 인터페이스를 제공합니다. 각 인터프리터는 이벤트 큐를 가지며, 이벤트 전송 및 처리를 위한 시설을 갖추고 있습니다. Python과 달리, Tcl의 실행 모델은 협조적 멀티태스킹을 기반으로 설계되었으며, Tkinter가 이 차이점을 연결합니다 (자세한 내용은 Threading model 을 참조하십시오).

Tk

Tk is a Tcl package implemented in C that adds custom commands to create and manipulate GUI widgets. Each Tk object embeds its own Tcl interpreter instance with Tk loaded into it. Tk’s widgets are very customizable, though at the cost of a dated appearance. Tk uses Tcl’s event queue to generate and process GUI events.

Ttk

Themed Tk (Ttk) is a newer family of Tk widgets that provide a much better appearance on different platforms than many of the classic Tk widgets. Ttk is distributed as part of Tk, starting with Tk version 8.5. Python bindings are provided in a separate module, tkinter.ttk.

내부적으로 Tk와 Ttk는 기본 운영체제의 기능을 활용합니다. 즉, Unix/X11에서는 Xlib를, macOS에서는 Cocoa를, Windows에서는 GDI를 사용합니다.

파이썬 애플리케이션에서 예를 들어 위젯을 생성하기 위해 Tkinter의 클래스를 사용하는 경우, tkinter 모듈은 먼저 Tcl/Tk 명령 문자열을 구성합니다. 그 다음 이 Tcl 명령 문자열을 내부 _tkinter 바이너리 모듈로 전달하며, 해당 모듈은 Tcl 인터프리터를 호출하여 이를 실행합니다. Tcl 인터프리터는 그 후 Tk 및/또는 Ttk 패키지를 호출하며, 이들은 다시 Xlib, Cocoa 또는 GDI를 호출합니다.

Tkinter 모듈¶

Support for Tkinter is spread across several modules. Most applications will need the main tkinter module, as well as the tkinter.ttk module, which provides the modern themed widget set and API:

from tkinter import *
from tkinter import ttk
class tkinter.Tk(screenName=None, baseName=None, className='Tk', useTk=True, sync=False, use=None)¶

최상위 Tk 위젯을 만들고 이 위젯에 대한 Tcl 인터프리터를 초기화합니다. 이 위젯은 일반적으로 응용 프로그램의 메인 창입니다. 인스턴스마다 고유한 Tcl 인터프리터가 연결됩니다.

The Tk 클래스는 일반적으로 모든 기본값을 사용하여 인스턴스화됩니다. 하지만 현재 인식되는 키워드 인수는 다음과 같습니다:

screenName

When given (as a string), sets the DISPLAY environment variable. (X11 only)

baseName

프로필 파일의 이름입니다. 기본적으로, baseName 은 프로그램 이름(sys.argv[0])으로부터 파생됩니다.

className

위젯 클래스의 이름입니다. 프로필 파일로 사용되며, Tcl이 호출되는 이름(interp*의 *argv0)으로도 사용됩니다.

useTk

If True, initialize the Tk subsystem. The tkinter.Tcl() function sets this to False.

sync

If True, execute all X server commands synchronously, so that errors are reported immediately. Can be used for debugging. (X11 only)

use

애플리케이션을 독립적인 toplevel window로 생성하는 대신 포함할 창의 id 를 지정합니다. id 는 최상위 위젯에 대한 -use 옵션 값과 동일한 방식으로 지정해야 합니다(즉, winfo_id() 에서 반환되는 것과 같은 형식입니다).

일부 플랫폼에서는 id 가 -container 옵션이 활성화된 Tk 프레임 또는 최상위 창을 참조할 때만 올바르게 작동한다는 점에 유의하십시오.

Tk reads and interprets profile files, named .className.tcl and .baseName.tcl, into the Tcl interpreter and calls exec() on the contents of .className.py and .baseName.py. The path for the profile files is the HOME environment variable or, if that isn’t defined, then os.curdir.

tk¶

The Tk application object created by instantiating Tk. This provides access to the Tcl interpreter. Each widget that is attached the same instance of Tk has the same value for its tk attribute.

master¶

이 위젯을 포함하는 위젯 객체입니다. Tk 의 경우, 메인 창이므로 master 는 None 입니다. master 와 parent 는 유사한 용어이며 때때로 인수 이름으로 혼용되기도 하지만, winfo_parent() 를 호출하면 위젯 이름의 문자열이 반환되는 반면 master 는 객체를 반환합니다. parent/child 은 트리 형태의 관계를 나타내며, master (또는 container)/content 는 컨테이너 구조를 반영합니다.

children¶

자식 위젯 이름을 키로, 자식 인스턴스 객체를 값으로 갖는 dict 형태의 이 위젯의 직계 자손입니다.

destroy()¶

이 위젯과 모든 하위(descendant) 위젯을 파괴하고, 메인 창의 경우 기본 Tcl 인터프리터와의 연결을 종료합니다.

loadtk()¶

Tk 서브시스템의 로드 및 초기화 완료. 이 기능은 인터프리터가 Tk 없이 생성된 경우(예: Tcl() 을 통한 경우)에만 필요하며, useTk 가 true인 경우 자동으로 호출됩니다.

readprofile(baseName, className)¶

사용자 프로필 파일인 .className.tcl`과 :file:.{baseName}.tcl`을 Tcl 인터프리터로 읽고 소스(source)하며, 해당 .className.py`와 :file:.{baseName}.py` 파일을 실행합니다. 이 기능은 초기화 과정 중에 호출됩니다. 위에서 설명한 생성자 설명을 참조하십시오.

report_callback_exception(exc, val, tb)¶

콜백 예외를 보고합니다. 이 기능은 Tkinter 콜백에서 예외가 발생하여 외부로 전파될 때 호출됩니다. exc_, val 및 tb 는 sys.exc_info() 에 의해 반환되는 예외 유형, 값 및 트레이스백입니다. 기본 구현은 트레이스백을 sys.stderr 에 출력합니다. 에러 처리를 사용자 정의하기 위해(예: 대화 상자에 트레이스백 표시) 이 기능을 재정의할 수 있습니다.

tkinter.Tcl(screenName=None, baseName=None, className='Tk', useTk=False)¶

Tcl() 함수는 Tk 서브시스템을 초기화하지 않는다는 점을 제외하고는 Tk 클래스로 생성된 것과 매우 유사한 객체를 생성하는 팩토리 함수입니다. 이 기능은 불필요한 최상위(toplevel) 창을 생성하고 싶지 않거나 생성할 수 없는 환경(X 서버가 없는 Unix/Linux 시스템 등)에서 Tcl 인터프리터를 구동할 때 주로 유용합니다. Tcl() 을 통해 생성된 객체는 loadtk() 메서드를 호출하여 최상위(Toplevel) 창을 생성하고 Tk 서브시스템을 초기화할 수 있습니다.

Tk 지원을 제공하는 모듈은 다음과 같습니다:

tkinter

주 Tkinter 모듈.

tkinter.colorchooser

사용자가 색상을 선택할 수 있게 하는 대화 상자.

여기에 나열된 다른 모듈에 정의된 대화 상자의 베이스 기본 클래스.

tkinter.filedialog

사용자가 열거나 저장할 파일을 지정할 수 있도록 하는 일반 대화 상자입니다.

tkinter.font

글꼴과 관련된 작업에 도움이 되는 유틸리티.

tkinter.messagebox

표준 Tk 대화 상자에 액세스합니다.

tkinter.scrolledtext

세로 스크롤 막대가 내장된 Text 위젯.

tkinter.simpledialog

기본 대화 상자와 편리 함수.

tkinter.ttk

Tk 8.5에 도입되어, 메인 tkinter 모듈의 많은 클래식 위젯에 대한 현대적인 대안을 제공하는 테마 위젯 세트입니다.

Python’s Integrated Development and Learning Environment (IDLE). Based on tkinter.

Tkinter 호출에 다양한 매개변수를 전달할 때 문자열 대신 사용할 수 있는 기호 상수입니다. 메인 tkinter 모듈에 의해 자동으로 임포트됩니다.

Tkinter 생명 유지 장치¶

이 절은 Tk나 Tkinter 모두에 대한 포괄적인 튜토리얼을 제공하기 위한 것은 아닙니다. 그 대신, Tkinter 애플리케이션이 어떤 모습인지에 대한 아주 빠른 오리엔테이션을 제공하고, 기초적인 Tk 개념을 식별하며, Tkinter 래퍼가 어떻게 구성되어 있는지 설명합니다.

이 섹션의 나머지는 Tkinter 애플리케이션에서 필요할 클래스, 메서드, 옵션을 식별하는 데 도움이 될 것이며, 공식 Tcl/Tk 참조 매뉴얼을 포함하여 더 자세한 문서를 찾을 수 있는 위치를 알려줄 것입니다.

Hello World 프로그램¶

Tkinter에서 “Hello World” 애플리케이션을 단계별로 살펴보면서 시작하겠습니다. 우리가 작성할 수 있는 가장 작은 예시는 아니지만, 알아야 할 몇 가지 핵심 개념을 설명하기에는 충분합니다.

from tkinter import *
from tkinter import ttk
root = Tk()
frm = ttk.Frame(root, padding=10)
frm.grid()
ttk.Label(frm, text="Hello World!").grid(column=0, row=0)
ttk.Button(frm, text="Quit", command=root.destroy).grid(column=1, row=0)
root.mainloop()

임포트 후에 다음 줄은 Tk 클래스의 인스턴스를 생성하여 Tk를 초기화하고 관련 Tcl 인터프리터를 생성합니다. 또한 애플리케이션의 메인 창 역할을 하는 루트 창으로 알려진 최상위 창도 생성합니다.

다음 줄은 프레임 위젯을 생성하며, 여기서는 다음에서 만들 레이블과 버튼을 포함할 것입니다. 이 프레임은 루트 창 안에 배치됩니다.

다음 줄은 정적 텍스트 문자열을 포함하는 레이블(label) 위젯을 생성합니다. 레이블이 포함된 프레임 위젯 내에서 레이블의 상대적 배치(위치)를 지정하기 위해 grid() 메서드를 사용하며, 이는 HTML의 테이블(table) 작동 방식과 유사합니다.

그 다음 버튼 위젯을 생성하여 레이블 오른쪽에 배치합니다. 이 버튼이 눌리면 루트 창의 destroy() 메서드가 호출됩니다.

마지막으로, mainloop() 메서드는 모든 것을 디스플레이에 표시하고 프로그램이 종료될 때까지 사용자 입력을 처리합니다.

중요한 Tk 개념¶

심지어 이 간단한 프로그램은 다음과 같은 주요 Tk 개념들을 보여줍니다:

위젯

Tkinter 사용자 인터페이스는 개별 위젯 들로 구성됩니다. 각 위젯은 ttk.Frame, ttk.Label, 및 ttk.Button 과 같은 클래스로 인스턴스화된 Python 객체로 표현됩니다.

위젯 계층 구조

위젯들은 계층 구조*로 배열됩니다. 레이블과 버튼은 프레임 안에 포함되었고, 그 프레임은 다시 루트 창 안에 포함되었습니다. 각 *자식 위젯을 생성할 때, 해당 부모 위젯이 위젯 생성자의 첫 번째 인자로 전달됩니다.

구성 옵션

위젯은 모양과 동작을 수정하는 구성 옵션 을 가지고 있으며, 레이블이나 버튼에 표시되는 텍스트 등이 있습니다. 다른 클래스의 위젯들은 서로 다른 옵션 세트를 가집니다.

지오메트리 관리

위젯을 생성한다고 해서 사용자 인터페이스에 자동으로 추가되는 것은 아닙니다. grid 와 같은 지오메트리 관리자 가 사용자 인터페이스의 어디에 배치되는지를 제어합니다.

이벤트 루프

Tkinter는 사용자 입력, 프로그램의 변경 사항, 심지어 디스플레이 새로고침까지 이벤트 루프 를 활발하게 실행할 때만 반응합니다. 프로그램이 이벤트 루프를 실행하고 있지 않으면 사용자 인터페이스가 업데이트되지 않습니다.

Tkinter가 Tcl/Tk를 래핑하는 방식 이해하기¶

애플리케이션이 Tkinter의 클래스와 메서드를 사용할 때, 내부적으로 Tkinter는 Tcl/Tk 명령을 나타내는 문자열을 조립하고, 애플리케이션의 Tk 인스턴스에 연결된 Tcl 인터프리터에서 해당 명령을 실행합니다.

참조 문서를 탐색하려고 하든, 올바른 메서드나 옵션을 찾으려고 하든, 기존 코드를 조정하든, Tkinter 애플리케이션을 디버깅하든, 그 근본적인 Tcl/Tk 명령이 어떻게 생겼는지를 이해하는 것이 유용할 때가 있습니다.

예를 들어, 여기에 위의 Tkinter 스크립트의 주요 부분에 해당하는 Tcl/Tk 등가물이 있습니다.

ttk::frame .frm -padding 10
grid .frm
grid [ttk::label .frm.lbl -text "Hello World!"] -column 0 -row 0
grid [ttk::button .frm.btn -text "Quit" -command "destroy ."] -column 1 -row 0

Tcl의 문법은 많은 셸 언어와 유사하여, 첫 번째 단어는 실행할 명령이고 그 뒤에 공백으로 구분된 인자들이 따라옵니다. 너무 많은 세부 사항을 다루지 않더라도 다음 사항을 주목하십시오:

  • 위젯을 생성하는 데 사용되는 명령(예: ttk::frame)은 Tkinter의 위젯 클래스에 해당합니다.

  • Tcl 위젯 옵션(예: -text)은 Tkinter의 키워드 인자와 대응합니다.

  • Tcl에서는 위젯이 경로명 (예: .frm.btn)으로 참조되는 반면, Tkinter는 이름을 사용하지 않고 객체 참조를 사용합니다.

  • 위젯의 위계 구조에서의 위치는 경로명(hierarchy name)에 인코딩되어 있으며, 여기서 경로는 구분자로 . (점)을 사용합니다. 루트 창의 경로명은 단순히 . (점)입니다. Tkinter에서는 계층 구조가 경로명으로 정의되는 것이 아니라, 각 자식 위젯을 생성할 때 부모 위젯을 지정하여 정의됩니다.

  • Tcl에서는 별도의 명령어 로 구현되는 작업(예: grid 또는 destroy)은 Tkinter 위젯 객체의 메서드 로 표현됩니다. 곧 보게 되겠지만, Tcl은 다른 시점에서는 위젯 객체에서 메서드 호출처럼 보이는 것을 사용하며, 이는 Tkinter에서 사용되는 것과 더 가깝습니다.

~가요…? 무엇이…?¶

Tkinter에서 무언가를 어떻게 해야 할지 확실하지 않고, 사용 중인 튜토리얼이나 참조 문서에서 바로 찾을 수 없다면, 도움이 될 수 있는 몇 가지 전략이 있습니다.

먼저, 개별 위젯의 작동 방식에 대한 세부 사항이 Tkinter와 Tcl/Tk의 여러 버전에서 다를 수 있음을 기억하십시오. 문서를 검색하는 경우, 시스템에 설치된 Python 및 Tcl/Tk 버전에 해당하는지 확인하십시오.

When searching for how to use an API, it helps to know the exact name of the class, option, or method that you’re using. Introspection, either in an interactive Python shell or with print(), can help you identify what you need.

임의의 위젯에서 사용 가능한 구성 옵션을 확인하려면 해당 위젯의 configure() 메서드를 호출하십시오. 이 메서드는 기본값과 현재 값을 포함하여 각 객체에 대한 다양한 정보가 담긴 딕셔너리를 반환합니다. 단순히 각 옵션의 이름만 가져오려면 keys() 를 사용하십시오.

btn = ttk.Button(frm, ...)
print(btn.configure().keys())

대부분의 위젯은 많은 공통 구성 옵션을 가지고 있으므로, 특정 위젯 클래스에만 있는 것이 무엇인지 아는 것이 유용할 수 있습니다. 프레임과 같은 더 간단한 위젯 목록과 옵션 목록을 비교하는 것이 한 가지 방법입니다.

print(set(btn.configure().keys()) - set(frm.configure().keys()))

마찬가지로, 표준 dir() 함수를 사용하여 위젯 객체에 대한 사용 가능한 메서드를 찾을 수 있습니다. 시도해 보면 200개가 넘는 공통 위젯 메서드가 있다는 것을 알 수 있으므로, 역시 특정 위젯 클래스에 특화된 것을 식별하는 것이 도움이 됩니다.

print(dir(btn))
print(set(dir(btn)) - set(dir(frm)))

Tcl/Tk 참조 매뉴얼 탐색¶

언급된 바와 같이, 공식 Tk commands 참조 매뉴얼(man 페이지)은 위젯에 대한 특정 동작이 무엇을 하는지 가장 정확하게 설명하는 자료입니다. 필요한 옵션이나 메서드의 이름을 알고 있더라도, 여전히 확인해야 할 곳이 몇 군데 더 있을 수 있습니다.

Tkinter의 모든 작업은 위젯 객체에 대한 메서드 호출로 구현되지만, 많은 Tcl/Tk 작업이 위젯 경로를 첫 번째 파라미터로 받고 그 뒤에 선택적 파라미터를 따르는 명령어로 나타나는 것을 보셨을 것입니다. 예를 들어:

destroy .
grid .frm.btn -column 0 -row 0

다른 것들은 위젯 객체에서 호출되는 메서드와 더 유사합니다 (사실 Tcl/Tk에서 위젯을 생성하면, 위젯 경로 이름을 가진 Tcl 명령을 생성하며, 그 명령의 첫 번째 매개변수가 호출할 메서드 이름입니다).

.frm.btn invoke
.frm.lbl configure -text "Goodbye"

공식 Tcl/Tk 참조 문서에서, 메서드 호출과 유사한 대부분의 동작은 특정 위젯의 매뉴얼 페이지(예를 들어, ttk::button 매뉴얼 페이지에서 invoke() 메서드를 확인할 수 있습니다)에 기재되어 있으며, 위젯을 파라미터로 받는 함수들은 종종 자체적인 매뉴얼 페이지(예를 들어, grid)를 가집니다.

options 또는 ttk_::widget 매뉴얼 페이지에서 많은 공통 옵션과 메서드를 찾을 수 있으며, 나머지는 특정 위젯 클래스의 매뉴얼 페이지에서 확인하실 수 있습니다.

또한 많은 Tkinter 메서드가 복합적인 이름을 가지고 있는 것을 알 수 있는데, 예를 들어 winfo_x(), winfo_height(), winfo_viewable() 등이 있습니다. 이들 모두에 대한 설명은 winfo 매뉴얼 페이지에서 찾을 수 있습니다.

참고

다소 혼란스럽게도, 실제로는 위젯에서 작동하지 않고, 위젯과는 독립적으로 전역 범위에서 작동하는 모든 Tkinter 위젯에 대한 메서드도 존재합니다. 클립보드나 시스템 벨에 접근하기 위한 메서드가 예시입니다. (이들은 모든 Tkinter 위젯이 상속받는 기본 Widget 클래스에 메서드 형태로 구현되어 있습니다).

스레딩 모델¶

Python and Tcl/Tk have very different threading models, which tkinter tries to bridge. If you use threads, you may need to be aware of this.

Python 인터프리터는 자신과 연결된 여러 스레드를 가질 수 있습니다. Tcl에서는 여러 스레드를 생성할 수 있지만, 각 스레드는 자체의 Tcl 인터프리터 인스턴스를 가집니다. 스레드는 또한 여러 개의 인터프리터 인스턴스를 생성할 수도 있지만, 각 인터프리터 인스턴스는 이를 생성한 단 하나의 스레드만 사용할 수 있습니다.

Each Tk object created by tkinter contains a Tcl interpreter. It also keeps track of which thread created that interpreter. Calls to tkinter can be made from any Python thread. Internally, if a call comes from a thread other than the one that created the Tk object, an event is posted to the interpreter’s event queue, and when executed, the result is returned to the calling Python thread.

Tcl/Tk 애플리케이션은 일반적으로 이벤트 중심(event-driven)으로 동작하며, 이는 초기화 후 인터프리터가 이벤트 루프(즉, Tk.mainloop)를 실행하고 이벤트에 반응함을 의미합니다. 단일 스레드 방식이므로 이벤트 핸들러는 신속하게 응답해야 하며, 그렇지 않으면 다른 이벤트의 처리가 차단됩니다. 이를 방지하기 위해 시간이 오래 걸리는 계산은 이벤트 핸들러에서 수행해서는 안 되며, 대신 타이머를 사용하여 더 작은 단위로 나누거나 별도의 스레드에서 실행해야 합니다. 이는 GUI가 이벤트 핸들러를 포함한 모든 애플리케이션 코드와 완전히 분리된 독립적인 스레드에서 실행되는 많은 GUI 툴킷과는 다릅니다.

Tcl 인터프리터가 이벤트 루프를 실행하고 이벤트를 처리하지 않는 경우, Tcl 인터프리터를 실행하는 스레드가 아닌 다른 스레드에서 이루어지는 모든 tkinter 호출은 실패합니다.

일부 특별한 경우가 존재합니다:

  • 스레드 지원 없이 빌드된 Tcl/Tk 라이브러리는 이제 드뭅니다. Tcl/Tk 9.0(번들 버전)은 항상 스레드 인식(thread-aware)이 가능하므로, 이 경우는 일부 오래된 8.x 빌드에서만 발생합니다. 라이브러리가 스레드를 인식하지 못하는 경우, tkinter 는 Tcl 인터프리터를 생성한 스레드와 다르더라도 원본 Python 스레드에서 라이브러리를 호출합니다. 전역 잠금(global lock)을 통해 한 번에 하나의 호출만 발생하도록 보장합니다.

  • While tkinter allows you to create more than one instance of a Tk object (with its own interpreter), all interpreters that are part of the same thread share a common event queue, which gets ugly fast. In practice, don’t create more than one instance of Tk at a time. Otherwise, it’s best to create them in separate threads and ensure you’re running a thread-aware Tcl/Tk build.

  • 이벤트 핸들러를 차단하는 것이 Tcl 인터프리터가 이벤트 루프를 재진입하는 것을 막는 유일한 방법은 아닙니다. 여러 개의 중첩된 이벤트 루프를 실행하거나 이벤트 루프 자체를 완전히 포기하는 것도 가능합니다. 이벤트나 스레드와 관련하여 까다로운 작업을 처리한다면, 이러한 가능성을 염두에 두어야 합니다.

  • There are a few select tkinter functions that presently work only when called from the thread that created the Tcl interpreter.

간편한 레퍼런스¶

옵션 설정¶

옵션은 위젯의 색상과 테두리 너비와 같은 것을 제어합니다. 옵션은 세 가지 방법으로 설정할 수 있습니다:

객체 생성 시, 키워드 인자 사용하기
fred = Button(self, fg="red", bg="blue")
객체 생성 후, 딕셔너리 인덱스처럼 옵션 이름을 다루기
fred["fg"] = "red"
fred["bg"] = "blue"
config() 메서드를 사용하여 객체 생성 이후 여러 어트리뷰트를 갱신하기.
fred.config(fg="red", bg="blue")

주어진 옵션과 그 동작에 대한 완전한 설명은, 해당 위젯의 Tk 매뉴얼 페이지를 참조하십시오.

매뉴얼 페이지는 각 위젯에 대해 “표준 옵션(STANDARD OPTIONS)”과 “위젯 특정 옵션(WIDGET SPECIFIC OPTIONS)”을 나열합니다. 전자는 많은 위젯에 공통적인 옵션 목록이며, 후자는 그 위젯에만 적용되는 옵션입니다. 표준 옵션은 options(3) 매뉴얼 페이지에 설명되어 있습니다.

이 문서에서는 표준과 위젯 특정 옵션을 구분하지 않습니다. 일부 옵션은 일부 위젯에 적용되지 않습니다. 특정 위젯이 특정 옵션에 응답하는지는 위젯의 클래스에 따라 다릅니다; 버튼에는 command 옵션이 있는데, 레이블은 그렇지 않습니다.

특정 위젯이 지원하는 옵션은 해당 위젯의 매뉴얼 페이지에 나열되거나, 인자 없이 config() 메서드를 호출하거나 해당 위젯에서 keys() 메서드를 호출하여 실행 시간에 조회할 수 있습니다. 이러한 호출의 반환 값은 키가 옵션 이름 문자열(예를 들어, 'relief')이고 값이 5-튜플인 딕셔너리입니다.

bg와 같은 일부 옵션은 긴 이름을 가진 공통 옵션의 동의어입니다 (bg는 “background”의 줄임말입니다). config() 메서드에 줄인 옵션을 전달하면 5-튜플이 아닌 2-튜플을 반환합니다. 전달된 2-튜플에는 동의어의 이름과 “실제” 옵션이 담겨있습니다 (가령 ('bg', 'background')).

패커¶

패커(packer)는 Tk의 지오메트리 관리 메커니즘 중 하나입니다. 지오메트리 관리자는 위젯들이 자신의 컨테이너 내에서 상대적인 위치 지정에 사용됩니다. 사용 빈도가 적고 여기서는 다루지 않는 더 번거로운 placer*와는 달리, 패커는 *위에, 왼쪽에, 채우기 등의 정성적(qualitative) 관계 규정을 취하고, 여러분을 위해 정확한 배치 좌표를 결정하기 위한 모든 작업을 수행합니다.

임의의 컨테이너 위젯 크기는 그 안에 있는 “콘텐츠 위젯”의 크기에 의해 결정됩니다. 패커는 콘텐츠 위젯이 패킹되는 컨테이너 내부에 어디에 나타날지 제어하는 데 사용됩니다. 원하는 레이아웃을 얻기 위해 위젯을 프레임에, 프레임을 다른 프레임에 패킹할 수 있습니다. 또한, 일단 패킹되면, 구성의 점진적인 변경을 수용하기 위해 배열이 동적으로 조정됩니다.

위젯은 지오메트리 관리자로 지오메트리가 지정될 때까지 표시되지 않는다는 점에 유의하십시오. 지오메트리 명세를 누락하는 것은 초기 단계에서 흔히 발생하는 실수이며, 이로 인해 위젯이 생성되었음에도 아무것도 나타나지 않아 당황하게 될 수 있습니다. 위젯은 예를 들어 패커의 pack() 메서드가 적용된 후에만 나타납니다.

pack() 메서드는 컨테이너 내에서 위젯이 표시되는 위치와 메인 응용 프로그램 윈도우의 크기가 조정될 때 어떻게 동작할지를 제어하는 키워드 옵션/값 쌍으로 호출할 수 있습니다. 여기 몇 가지 예가 있습니다:

fred.pack()                     # 기본값은 side = "top"
fred.pack(side="left")
fred.pack(expand=1)

위젯 변수 결합하기¶

(텍스트 입력 위젯과 같은) 일부 위젯의 현재 값 설정은 특수 옵션을 사용하여 응용 프로그램 변수에 직접 연결할 수 있습니다. 이 옵션은 variable, textvariable, onvalue, offvalue 및 value입니다. 이 연결은 양방향으로 작동합니다: 어떤 이유로 든 변수가 변경되면, 연결된 위젯은 새 값을 반영하도록 갱신됩니다.

Unfortunately, in the current implementation of tkinter it is not possible to hand over an arbitrary Python variable to a widget through a variable or textvariable option. The only kinds of variables for which this works are variables that are subclassed from a class called Variable, defined in tkinter.

There are many useful subclasses of Variable already defined: StringVar, IntVar, DoubleVar, and BooleanVar. To read the current value of such a variable, call the get() method on it, and to change its value you call the set() method. If you follow this protocol, the widget will always track the value of the variable, with no further intervention on your part.

예를 들면:

import tkinter as tk

class App(tk.Frame):
    def __init__(self, master):
        super().__init__(master)
        self.pack()

        self.entrythingy = tk.Entry()
        self.entrythingy.pack()

        # 여기에 응용 프로그램 변수를 만듭니다.
        self.contents = tk.StringVar()
        # 어떤 값으로 설정합니다
        self.contents.set("this is a variable")
        # Entry 위젯에 이 변수를 감시하도록 지시합니다.
        self.entrythingy["textvariable"] = self.contents

        # 사용자가 return 키를 눌렀을 때를 위한 콜백을 정의합니다.
        # 변수의 현재값을 인쇄합니다.
        self.entrythingy.bind('<Key-Return>',
                             self.print_contents)

    def print_contents(self, event):
        print("Hi. The current entry content is:",
              self.contents.get())

root = tk.Tk()
myapp = App(root)
myapp.mainloop()

창 관리자¶

In Tk, there is a utility command, wm, for interacting with the window manager. Options to the wm command allow you to control things like titles, placement, icon bitmaps, and the like. In tkinter, these commands have been implemented as methods on the Wm class. Toplevel widgets are subclassed from the Wm class, and so can call the Wm methods directly.

주어진 위젯이 포함된 최상위 창을 가져오려면, 종종 위젯의 물론 위젯이 프레임 안에 배치되어 있다면, :attr:!master`가 최상위 창을 나타내지는 않을 것입니다. 임의의 위젯이 포함된 최상위 창을 가져오려면 winfo_toplevel() 메서드를 호출할 수 있습니다. 또한 _root() 메서드도 있으며, 이는 밑줄로 시작하여 이 기능이 Tk 기능에 대한 인터페이스가 아니라 구현의 일부임을 나타냅니다. 이 메서드는 가장 가까운 포함된 최상위 창 대신 애플리케이션의 루트(root) 창을 반환합니다.

다음은 일반적인 사용 예입니다:

import tkinter as tk

class App(tk.Frame):
    def __init__(self, master=None):
        super().__init__(master)
        self.pack()

# 응용 프로그램을 만듭니다
myapp = App()

#
# 이것들은 창 관리자 클래스에 대한 메서드 호출입니다
#
myapp.master.title("My Do-Nothing Application")
myapp.master.maxsize(1000, 400)

# 프로그램을 시작합니다
myapp.mainloop()

바인딩과 이벤트¶

위젯 명령의 bind 메서드를 사용하면 특정 이벤트를 감시하고 해당 이벤트 유형이 발생할 때 콜백 함수가 트리거 되도록 할 수 있습니다. bind 메서드의 형식은 다음과 같습니다:

def bind(self, sequence, func, add=''):

여기에서:

sequence

대상 이벤트의 종류를 나타내는 문자열입니다. 물리적 이벤트는 <modifier-modifier-type-detail> 형식을 사용하며(예를 들어 "<Enter>" 또는 "<Control-Button-1>"), 애플리케이션에서 정의한 가상 이벤트는 "<<Paste>" 와 같이 이중 꺽쇠를 사용합니다. (자세한 내용은 bind(3tk) 매뉴얼 페이지 및 John Ousterhout의 저서 Tcl and the Tk Toolkit (2nd edition) 의 201쪽을 참고하십시오.)

func

는 하나의 인자를 취하는 파이썬 함수로, 이벤트가 발생할 때 호출됩니다. 이벤트 인스턴스가 인자로 전달됩니다. (이런 식으로 설치되는 함수를 흔히 콜백(callbacks)이라고 합니다.)

add

는 선택적이고, ''나 '+'입니다. 빈 문자열을 전달하면 이 바인딩이 이 이벤트와 연관된 다른 바인딩을 대체 함을 나타냅니다. '+'를 전달하면 이 함수가 이 이벤트 유형에 바인딩 된 함수 목록에 추가됩니다.

예를 들면:

def turn_red(self, event):
    event.widget["activeforeground"] = "red"

self.button.bind("<Enter>", self.turn_red)

이벤트의 widget 필드가 turn_red() 콜백에서 어떻게 액세스 되는지 주목하십시오. 이 필드는 X 이벤트를 포착한 위젯을 포함합니다. 다음 표에는 사용자가 액세스할 수 있는 다른 이벤트 필드와 Tk에서 이들을 표시하는 방법이 나열되어 있습니다. Tk 매뉴얼 페이지를 참조할 때 유용할 수 있습니다.

index 매개 변수¶

많은 위젯에는 “index” 매개 변수가 전달되어야 합니다. 이들은 Text 위젯의 특정 위치, Entry 위젯의 특정 문자 또는 Menu 위젯의 특정 메뉴 항목을 가리키는 데 사용됩니다.

Entry 위젯 인덱스 (인덱스, 뷰 인덱스 등)

Entry 위젯에는 표시되는 텍스트의 문자 위치를 참조하는 옵션이 있습니다. 다음 tkinter 함수를 사용하여 텍스트 위젯에서 이러한 특수 지점에 접근할 수 있습니다:

Text 위젯 인덱스

Text 위젯의 인덱스 표기법은 매우 풍부하며 Tk 매뉴얼 페이지에 자세히 설명되어 있습니다.

메뉴 인덱스 (menu.invoke(), menu.entryconfig() 등)

메뉴에 대한 일부 옵션 및 메서드는 특정 메뉴 항목을 조작합니다. 옵션이나 매개 변수에 메뉴 인덱스가 필요한 때는 언제든지 다음과 같이 전달할 수 있습니다:

  • 위에서부터 세고, 0에서 시작하는, 위젯에서 항목의 숫자 위치를 나타내는 정수.

  • 현재 커서 아래에 있는 메뉴 위치를 나타내는, 문자열 "active".

  • 마지막 메뉴 항목을 나타내는, 문자열 "last".

  • @6과 같이, @이 앞에 오는 정수로, 정수는 메뉴의 좌표계에서 y 픽셀 좌표로 해석됩니다.

  • 아무런 메뉴 항목을 가리키지 않는, 문자열 "none"은 menu.activate()와 함께 사용되어 모든 항목을 비활성화합니다, 마지막으로,

  • 메뉴 맨 위에서 아래로 스캔할 때, 메뉴 항목의 레이블과 패턴 일치하는 텍스트 문자열. 이 인덱스 유형은 다른 모든 항목 다음에 고려되므로, last, active 또는 none 레이블이 붙은 메뉴 항목과의 일치가 대신 위의 리터럴로 해석될 수 있음을 의미합니다.

파일 처리기¶

Tk는 파일 기술자에서 I/O가 가능할 때 Tk 메인 루프에서 호출할 콜백 함수를 등록하고 등록 취소할 수 있도록 합니다. 파일 기술자당 하나의 처리기 만 등록 될 수 있습니다. 예제 코드:

import tkinter
widget = tkinter.Tk()
mask = tkinter.READABLE | tkinter.WRITABLE
widget.tk.createfilehandler(file, mask, callback)
...
widget.tk.deletefilehandler(file)

윈도우에서는 이 기능을 사용할 수 없습니다.

class tkinter.Misc¶

The Misc 클래스는 Tk 가 상속하며, BaseWidget 을 통해 모든 위젯이 상속하는 믹스인(mix-in)입니다. 이 클래스는 모든 Tk 객체에 공통적으로 필요한 방대한 메서드 세트(창 정보 조회, 이벤트 바인딩 및 이벤트 루프 관리, 키보드 포커스 및 포인터 그랩 제어, 선택 영역/클립보드/옵션 데이터베이스 액세스, 그리고 다양한 유틸리티 및 인트로스펙션 서비스 등)를 제공합니다. 이러한 메서드들은 상속되기 때문에 모든 위젯과 Tk 애플리케이션 객체에서 사용할 수 있으며, 각 위젯마다 반복하여 설명하는 대신 여기에 한 번만 기술됩니다.

bind(sequence=None, func=None, add=None)¶

이 위젯의 이벤트 패턴 sequence 를 호출 가능한 func 에 바인딩합니다.

sequence 는 '<Button-1>' (마우스 클릭) 또는 '<KeyPress-a>' 와 같은 이벤트 패턴으로, 선택적으로 하나 뒤에 다른 하나가 연이어 발생해야 하는 여러 패턴의 결합체일 수도 있습니다. 이벤트가 발생하면 이를 설명하는 Event 인스턴스가 유일한 인자로 전달되면서 func 이 호출됩니다. 만약 func 이 'break' 문자열을 반환하면 해당 이벤트에 대한 추가적인 바인딩은 실행되지 않습니다.

add 이 참이면 func 가 이미 sequence 에 바인딩된 함수들에 추가되고, 그렇지 않으면 기존 기능들을 대체합니다. 이 바인딩은 해당 위젯에만 적용됩니다.

bind() 는 문자열 식별자(funcid)를 반환합니다. 이 식별자는 나중에 unbind() 에 전달하여 관련된 Tcl 명령을 누출시키지 않고 바인딩을 제거하는 데 사용될 수 있습니다.

func 이 생략된 경우 현재 sequence 와 연관된 바인딩을 반환하고, sequence 도 생략된 경우 이 위젯에 바인딩이 존재하는 모든 시퀀스의 목록을 반환합니다.

bind_class(className, sequence=None, func=None, add=None)¶

bind() 와 유사하지만, 단일 위젯이 아닌 바인딩 태그 className 에 func 를 바인딩하여 해당 태그를 가진 모든 위젯에 바인딩이 적용되도록 합니다. className 은 보통 'Button'' 과 같은 위젯 클래스 이름이며, 이 경우 해당 클래스의 모든 위젯에 바인딩이 영향을 미칩니다. 위젯의 바인딩 태그 세트는 bindtags() 를 사용하여 확인하거나 변경할 수 있습니다.

나머지 인자와 반환 값은 bind() 와 동일합니다.

bind_all(sequence=None, func=None, add=None)¶

bind() 와 유사하지만, func 를 특별한 바인딩 태그인 'all' 에 바인딩하여 애플리케이션 내의 모든 위젯에 바인딩이 적용되도록 합니다.

나머지 인자와 반환 값은 bind() 와 동일합니다.

unbind(sequence, funcid=None)¶

이 위젯에서 이벤트 패턴 sequence 에 대한 바인딩을 제거합니다.

funcid 가 제공된 경우, 해당 식별자로 확인되는 함수(이전 bind() 호출에서 반환된 값)만 제거되고 관련 Tcl 명령도 삭제됩니다. 그렇지 않으면 sequence 에 대한 모든 바인딩이 파기되어 바인딩되지 않은 상태로 남습니다.

버전 3.13에서 변경: funcid 가 제공된 경우 해당 콜백만 바인딩이 해제되며, sequence 에 바인딩된 다른 콜백은 유지됩니다.

unbind_class(className, sequence)¶

바인딩 태그 className 에서 이벤트 패턴 sequence 에 대한 모든 바인딩을 제거합니다. bind_class() 를 참조하십시오.

unbind_all(sequence)¶

특별한 바인딩 태그 'all' 에서 이벤트 패턴 sequence 에 대한 모든 바인딩을 제거합니다. bind_all() 을 참조하십시오.

bindtags(tagList=None)¶

tagList 이 생략된 경우 이 위젯과 관련된 바인딩 태그 튜플을 반환합니다. 위젯에서 이벤트가 발생하면 순서에 따라 위젯의 각 바인딩 태그에 적용되며, 각 태그에 대해 가장 구체적인 일치하는 바인딩이 실행됩니다. 기본적으로 위젯은 네 가지 바인딩 태그를 가집니다: 자체 패스네임(pathname), 위젯 클래스, 가장 가까운 최상위(toplevel) 요소의 패스네임, 그리고 'all' 순서입니다.

tagList 이 제공되는 경우, 이는 문자열 시퀀스여야 하며, 위젯의 바인딩 태그는 해당 요소들로 설정됩니다. 이 값들은 바인딩이 평가되는 순서를 결정합니다.

event_add(virtual, *sequences)¶

이름이 '<<Paste>>' 형식을 갖는 가상 이벤트 virtual 을 sequences 로 제공된 각 물리적 이벤트 패턴과 연관시켜, 해당 이벤트 중 어느 하나라도 발생할 때마다 가상 이벤트가 트리거되도록 합니다. virtual 이 이미 정의된 경우, 새로운 시퀀스가 기존 시퀀스에 추가됩니다.

event_delete(virtual, *sequences)¶

가상 이벤트 virtual 과 연관된 항목들 중에서 sequences 를 각각 제거합니다. 현재 virtual 과 연관되지 않은 시퀀스는 무시됩니다. sequences 가 제공되지 않으면 모든 물리적 이벤트 시퀀스가 제거되어 virtual 이 더 이상 트리거되지 않습니다.

event_generate(sequence, **kw)¶

이 위젯에서 이벤트 sequence*를 생성하고, 마치 윈도우 시스템에서 발생한 것처럼 처리되도록 설정합니다. *sequence*는 여러 개가 결합된 형태가 아니라 ``’<Button-1>’`` 또는 ``’<<Paste>>’``와 같은 단일 이벤트 패턴이어야 합니다. 키워드 인수는 이벤트의 추가 필드를 지정하며, 예를 들어 포인터 위치를 위한 *x 및 y, 처리 시점을 제어하기 위한 when 등이 포함됩니다. 전체 목록은 Tk event 매뉴얼 페이지를 참조하십시오.

event_info(virtual=None)¶

virtual 이 생략된 경우 현재 정의된 모든 가상 이벤트의 튜플을 반환합니다. virtual 이 제공된 경우 그것과 연관된 물리적 이벤트 시퀀스의 튜플을 반환하며, 정의되어 있지 않으면 빈 튜플을 반환합니다.

after(ms, func=None, *args, **kw)¶

ms 밀리초 후에 호출될 콜러블(callable)인 func 을 예약하며, 이때 args 와 kw 가 각각 위치 및 키워드 인자로 전달됩니다. 호출을 취소하기 위해 after_cancel() 에 전달할 수 있는 식별자를 반환합니다.

func 이 생략된 경우 대신 ms 밀리초 동안 대기하며 그동안 이벤트를 처리하지 않고 None 을 반환합니다.

버전 3.10에서 변경: func 은 이제 함수뿐만 아니라 모든 콜러블(callable) 객체일 수 있습니다.

버전 3.14에서 변경: 키워드 인자가 이제 func 에 전달됩니다.

after_cancel(id)¶

Cancel a callback previously scheduled with after() or after_idle(). id must be an identifier returned by one of those methods; passing a value that is not such an identifier raises ValueError. If the callback has already run or been cancelled, this has no effect.

버전 3.7에서 변경: id 로 None (또는 다른 거짓 값)을 전달하면 이제 ValueError 가 발생합니다.

after_idle(func, *args, **kw)¶

Tk 메인 루프가 다음번에 한가해질 때(즉, 처리할 다른 이벤트가 없을 때) args 와 kw 를 인자로 전달하며 호출될 콜러블(callable) func 을 예약합니다. 호출을 취소하기 위해 after_cancel() 에 전달할 수 있는 식별자를 반환합니다.

버전 3.14에서 변경: 키워드 인자가 이제 func 에 전달됩니다.

after_info(id=None)¶

If id is omitted, return a tuple of the identifiers of all callbacks currently scheduled with after() and after_idle() for this interpreter.

id 가 제공된 경우, 아직 실행되지 않았거나 취소되지 않은 콜백을 식별해야 하며, 반환 값은 (script, type) 튜플입니다. 여기서 script 는 호출될 함수를 가리키고, type 은 'idle' 또는 'timer' 중 하나입니다. id 가 존재하지 않으면 TclError 가 발생합니다.

Added in version 3.13.

mainloop(n=0)¶

모든 창이 파괴될 때까지 이벤트를 처리하는 Tk 이벤트 루프에 진입합니다. 이 메서드는 일반적으로 애플리케이션을 실행하기 위해 루트 창에서 한 번 호출됩니다.

quit()¶

Tcl 인터프리터를 종료하고 mainloop() 가 반환되도록 합니다.

update()¶

아이들(idle) 콜백을 포함하여 대기 중인 모든 이벤트가 처리될 때까지 이벤트 루프에 진입합니다. 이 과정에서 디스플레이를 최신 상태로 업데이트하고 이미 큐에 쌓인 모든 이벤트를 처리한 후 반환됩니다.

update_idletasks()¶

대기 중인 모든 아이들 콜백이 호출될 때까지 이벤트 루프에 진입합니다. 이는 기하학적 구조(geometry) 변경 시와 같이 창의 디스플레이를 업데이트하지만, 사용자에 의해 발생한 이벤트는 처리하지 않습니다.

wait_variable(name='PY_VAR')¶

Tcl 변수 name 이 변경될 때까지 기다리며, 그동안 애플리케이션의 반응성을 유지하기 위해 계속 이벤트를 처리합니다. name 은 일반적으로 IntVar 또는 StringVar 와 같은 Variable 인스턴스입니다.

waitvar`는 :meth:()!wait_variable`의 별칭입니다.

wait_window(window=None)¶

window 이 파괴될 때까지 기다리며, 그동안 이벤트를 계속 처리합니다. window 이 생략된 경우 현재 위젯을 사용합니다. 이는 보통 사용자가 대화 상자와의 상호작용을 마칠 때까지 기다릴 때 사용됩니다.

wait_visibility(window=None)¶

window 의 가시성 상태가 변경될 때까지(예를 들어 화면에 처음 나타날 때) 기다리며, 그동안 이벤트를 계속 처리합니다. window 이 생략된 경우 현재 위젯을 사용합니다. 이는 보통 새로 생성된 창이 보이게 된 후 동작을 수행하기 위해 기다릴 때 사용됩니다.

focus()¶

Direct the keyboard input focus for this widget’s display to this widget. If the application does not currently have the input focus on this widget’s display, the widget is remembered as the focus window for its top level, and the focus will be redirected to it the next time the window manager gives the focus to the top level. focus() is an alias of focus_set(), except on the Canvas and ttk.Treeview widgets, which provide their own focus() method.

focus_force()¶

애플리케이션이 현재 위젯의 디스플레이에 대한 입력 포커스를 가지고 있지 않더라도, 키보드 입력을 이 위젯으로 집중시킵니다. 이 방법은 가급적 사용하지 않는 것이 좋으며, 보통 애플리케이션은 윈도우 매니저가 포커스를 부여할 때까지 기다려야 합니다.

focus_get()¶

애플리케이션에서 현재 키보드 포커스를 가진 위젯을 반환하며, 포커스를 가진 위젯이 없는 경우 None 을 반환합니다. 여러 디스플레이와 올바르게 작동하려면 focus_displayof() 를 사용하십시오.

focus_displayof()¶

이 위젯이 위치한 디스플레이에서 현재 키보드 포커스를 가진 위젯을 반환하며, 해당 디스플레이에 포커스가 있는 위젯이 없는 경우 None 을 반환합니다.

focus_lastfor()¶

이 위젯과 동일한 top level 내의 모든 위젯 중 가장 최근에 키보드 포커스를 가졌던 위젯을 반환하며, 이는 윈도우 매니저가 해당 top level에 다음으로 포커스를 부여할 때 포커스를 받게 될 위젯입니다. 만약 해당 topLevl에서 포커스를 가진 적이 없거나 가장 최근의 포커스 위젯이 삭제된 경우, top level 자체를 반환합니다.

tk_focusFollowsMouse()¶

마우스 포인터가 위젯 안으로 들어올 때마다 해당 위팅에 포커스가 설정되는 암시적 포커스 모델을 사용하도록 Tk를 재구성합니다. 이 기능은 한 번 활성화되면 쉽게 비활성화할 수 없습니다.

tk_focusNext()¶

키보드 순회 순서(traversal order)에서 이 위젯 다음의 위젯을 반환하며, 없으면 None 을 반환합니다. 순회 순서는 먼저 다음 자식으로 이동하고, 그 다음 재귀적으로 그 자식의 자식들로 이동하며, 그런 다음 적층 순서상 더 높은 위치에 있는 형제(sibling)로 이동합니다. takefocus 옵션이 0 으로 설정된 위젯은 건너뜁니다. 이 메서드는 Tab 키를 위한 기본 바인딩에서 사용됩니다.

tk_focusPrev()¶

키보드 순회 순서(traversal order)에서 이 위젯 앞의 위젯을 반환하며, 없으면 None 을 반환합니다. 순서가 어떻게 정의되는지는 tk_focusNext() 를 참조하십시오. 이 메서드는 Shift-Tab 키를 위한 기본 바인딩에서 사용됩니다.

grab_set()¶

이 위젯에 로컬 그랩(local grab)을 설정합니다. 그랩은 포인터 이벤트를 이 위젯과 그 자손들로 제한합니다. 포인터가 위젯 하위 트리 밖에 있는 동안에도 버튼 누름 및 해제, 포인터 이동이 그랩 위젯에 보고되며, 그랩이 해제될 때까지 해당 트리 밖의 창은 반응하지 않게 됩니다. 로컬 그랩은 오직 그랩을 설정한 애플리케이션에만 영향을 미칩니다. 이 애플리케이션에서 이 위젯의 디스플레이에 이전에 설정된 모든 그랩은 자동으로 해제됩니다. 그랩을 설정하는 것은 대화 상자를 모달(modal)로 만드는 일반적인 방법이며, 그랩이 활성화되는 동안 사용자는 애플리케이션의 다른 창과 상호작용할 수 없습니다.

grab_set_global()¶

Set a global grab on this widget. A global grab is like the local grab set by grab_set(), but it locks out all other applications on the screen, so that only this widget’s subtree is sensitive to pointer events, and it also grabs the keyboard. Use with caution: it is easy to render a display unusable with a global grab, since other applications stop receiving events until it is released.

grab_release()¶

이 위젯에 그랩이 설정되어 있는 경우 이를 해제합니다. 그렇지 않으면 아무 작업도 수행하지 않습니다.

grab_current()¶

이 위젯의 디스플레이에 대해 이 애플리케이션 내에서 현재 그랩을 보유하고 있는 위젯을 반환하며, 그런 위젯이 없으면 None 을 반환합니다.

grab_status()¶

이 위젯에 현재 설정된 그랩이 없으면 None 을 반환하고, 로컬 그랩이 설정되어 있으면 "local", 글로벌 그랩이 설정되어 있으면 "global" 을 반환합니다.

selection_clear(**kw)¶

더 이상 어떤 창도 소유하지 않도록 X 선택(X selection)을 지웁니다. 제거할 선택은 키워드 인자 selection*으로 지정하며, 이는 ``’PRIMARY’’ 또는 ``’CLIPBOARD’’와 같은 아톰 이름이며 기본값은 ``PRIMARY``입니다. *displayof 키워드 인자는 작업할 디스플레이를 결정하는 위젯을 지정하며, 기본값은 이 위젯입니다.

This is overridden by the Entry, Listbox and Spinbox widgets, where selection_clear() clears the widget’s own selection instead.

selection_get(**kw)¶

현재 X 선택의 내용을 반환합니다. 키워드 인자 selection*은 선택을 지정하며 기본값은 ``PRIMARY``입니다. 키워드 인자 *type*은 데이터가 반환될 형태(원하는 변환 대상)를 지정하며, 이는 ``’STRING’’ 또는 ``’FILE_NAME’’과 같은 아톰 이름입니다. X11 환경에서는 ``UTF8_STRING``을 먼저 시도하고 ``STRING``을 예비로 사용하지만, 그 외의 상황에서 기본값은 ``STRING``입니다. *displayof 키워드 인자는 선택을 가져올 디스플레이를 결정하는 위젯을 지정하며, 기본값은 이 위젯입니다.

selection_handle(command, **kw)¶

다른 애플리케이션이 요청할 때 이 위젯이 소유한 X selection을 제공하기 위해 command 를 처리기로 등록합니다. 선택이 조회될 때, command 는 시작 문자 오프셋과 반환할 최대 문자 수를 인자로 받아 호출되며, 해당 오프셋부터 시작하여 최대 그만큼의 선택 내용을 반환해야 합니다. 매우 긴 선택인 경우 증가하는 오프셋으로 여러 번 반복해서 호출됩니다. 키워드 인수 selection 은 선택의 이름을 지정하며(기본값 PRIMARY), 키워드 인수 type 은 처리기가 제공할 선택의 형태를 지정합니다(예: 'STRING'' 또는 `` 'FILE_NAME', 기본값 `` STRING’’).

selection_own(**kw)¶

이 위젯을 해당 디스플레이의 X selection 소유자로 만듭니다. 이전 소유자가 있는 경우, 해당 소유자에게 선택권 상실이 통지됩니다. 키워드 인수 selection 은 선택의 이름을 지정하며 기본값은 PRIMARY 입니다.

selection_own_get(**kw)¶

이 위젯을 포함하는 디스플레이에서 X selection을 소유하고 있는 이 애플리케이션 내의 위젯을 반환합니다. 만약 해당 애플리케이션 내에 소유한 위젯이 없다면 None 을 반환합니다. 키워드 인수 selection 은 선택의 이름을 지정하며 기본값은 PRIMARY 입니다. displayof 키워드 인수는 쿼리할 디스플레이를 결정하는 위젯을 지정하며, 기본값은 현재 위젯입니다.

clipboard_append(string, **kw)¶

Append string to the Tk clipboard and claim ownership of the clipboard on this widget’s display. Before appending, the clipboard should be emptied with clipboard_clear(); all appends should be completed before returning to the event loop so that the clipboard is updated atomically. The keyword argument type specifies the form of the data, an atom name such as 'STRING' or 'FILE_NAME' (default STRING), and the keyword argument format specifies the representation used to transmit it (default STRING). The displayof keyword argument names a widget that determines the target display, and defaults to this widget. The contents can be retrieved with clipboard_get() or selection_get().

clipboard_clear(**kw)¶

이 위젯의 디스플레이에서 클립보드 소유권을 주장하고 이전 내용들을 제거합니다. displayof 키워드 인수는 대상 디스플레이를 결정하는 위젯을 지정하며, 기본값은 현재 위젯입니다.

clipboard_get(**kw)¶

Retrieve data from the clipboard on this widget’s display. The keyword argument type specifies the form in which the data is to be returned, an atom name such as 'STRING' or 'FILE_NAME'; it defaults to STRING, except on X11, where UTF8_STRING is tried first and STRING is used as a fallback. tk_busy_hold(**kw)¶

이 위젯을 바쁨(busy) 상태로 표시합니다. 투명한 창이 위젯 앞에 배치되어, 해당 위젯과 위젯 계층 구조 내의 모든 하위 요소가 포인터 이벤트를 받지 못하게 하며 바쁨(busy) 커서를 표시합니다. 일반적으로 애플리케이션이 처리를 시작하기 전에 홀드(hold) 동작이 적용되도록 그 직후에 update() 를 호출해야 합니다.

지원되는 유일한 구성 옵션은 위젯이 바쁜 동안 표시될 커서인 cursor 이며, 이는 configure() 에서 수용되는 어떤 값이라도 가질 수 있습니다.

busy_hold(), busy() 및 tk_busy`는 :meth:()!tk_busy_hold`의 별칭입니다.

Added in version 3.13.

tk_busy_configure(cnf=None, **kw)¶

바쁨(busy) 창의 구성 옵션을 조회하거나 수정합니다. 위젯은 이전에 tk_busy_hold() 에 의해 바쁨 상태로 설정되어야 합니다. 인수가 없으면 사용 가능한 모든 옵션을 설명하는 딕셔너리를 반환하고, cnf 가 옵션 이름인 경우 해당 옵션을 설명하는 튜플을 반환합니다. 그 외의 경우에는 주어진 옵션을 지정된 값으로 설정합니다. 옵션은 tk_busy_hold() 에서 수용되는 어떤 값이라도 가질 수 있습니다.

옵션 데이터베이스는 위젯 이름 또는 클래스를 통해 참조됩니다. 예를 들어, 이름이 frame 인 Frame 위젯을 바쁨 상태로 만들 경우, 다음 중 하나의 호출을 통해 바쁨 커서를 지정할 수 있습니다:

w.option_add('*frame.busyCursor', 'gumby')
w.option_add('*Frame.BusyCursor', 'gumby')

busy_configure(), busy_config() 및 tk_busy_config`는 :meth:()!tk_busy_configure`의 별칭입니다.

Added in version 3.13.

위젯의 부모 내에서 위젯 테두리(테두리가 없는 경우 위젯 자체)의 왼쪽 상단 모서리 y 좌표를 반환합니다.

info_patchlevel()¶

Return the Tcl/Tk patch level as a named tuple with the same five fields as sys.version_info: major, minor, micro, releaselevel and serial. releaselevel is 'alpha', 'beta' or 'final'. class tkinter.Wm¶

Wm 믹스인은 윈도우 매니저에 대한 접근을 제공하며, 이를 통해 애플리케이션이 최상위 창의 제목, 기하학적 구조(geometry), 아이콘 등과 같은 항목을 제어하고, 크기 조정 방식 및 윈도우 매니저 프로토콜에 대응하는 방식을 제어할 수 있습니다. 이 믹스인은 Tk 및 Toplevel`에 포함되므로 모든 최상위 창에서 해당 메서드를 사용할 수 있습니다. 각 메서드는 짧은 이름과 ``wm_` 접두사가 붙은 이름(예: title() 및 wm_title())의 두 가지 동일한 표기법을 가집니다.

aspect(minNumer=None, minDenom=None, maxNumer=None, maxDenom=None)¶

창의 종횡비(가로 대비 세로 비율)를 제한합니다. 4개의 인자가 모두 제공되면 창 관리자가 비율을 minNumer/minDenom``에서 ``maxNumer/maxDenom 사이로 유지하며, 빈 문자열을 전달하면 기존 제약이 해제됩니다. 인자가 없는 경우 현재 값 4개를 포함하는 튜플을 반환하고, 종횡비 제한이 적용되지 않는 경우에는 빈 문자열을 반환합니다. wm_aspect`는 :meth:()!aspect`의 별칭입니다.

attributes(*args, return_python_dict=False, **kwargs)¶

창의 플랫폼 전용 속성을 조회하거나 설정합니다. 인자가 없으면 플랫폼별 플래그와 해당 값을 반환하며, return_python_dict 를 True로 전달하면 딕셔너리 형태로 받습니다. 'alpha'' 와 같은 단일 옵션 이름을 사용하면 해당 옵션의 값을 반환하고, 키워드 인자(예: alpha=0.5)를 사용하여 옵션을 설정합니다.

사용 가능한 속성은 플랫폼마다 다릅니다. 모든 플랫폼은 다음 항목을 지원합니다:

alpha

창의 불투명도(opacity)를 0.0 (완전 투명)에서 1.0 (불투명) 사이로 설정합니다. 투명도를 지원하지 않는 환경에서는 값이 1.0 으로 유지됩니다.

appearance

Whether the window is rendered in dark mode on Windows and macOS: 'auto', 'light' or 'dark' (this has no effect on X11).

fullscreen

창이 전체 화면을 차지하고 테두리가 없는지 여부입니다.

topmost

창이 다른 모든 창보다 위에 표시되는지 여부입니다.

Windows에서 추가로 지원하는 사항:

disabled

창이 비활성(disabled) 상태인지 여부입니다.

toolwindow

창이 도구 창(tool window) 스타일을 사용하는지 여부입니다.

transparentcolor

완전 투명하게 처리할 색상이며, 지정하지 않은 경우 빈 문자열을 반환합니다.

macOS에서 추가로 지원하는 사항:

class

기본 Aqua 창이 nswindow 인지 nspanel 인지 여부입니다. 이 값은 창이 생성되기 전에만 설정할 수 있습니다.

modified

창의 닫기 버튼과 프록시 아이콘에 표시되는 수정 상태입니다.

notify

애플리케이션의 독(dock) 아이콘이 주의를 끌기 위해 튀어오르는지 여부.

stylemask

titled 또는 resizable 과 같은 비트 이름의 목록으로 제공되는 기반 Aqua 창의 스타일 마스크입니다.

tabbingid

창이 속한 탭 그룹의 식별자입니다.

tabbingmode

창이 탭으로 열릴 수 있는지 여부: 'auto', 'preferred' 또는 'disallowed'.

titlepath

창의 프록시 아이콘으로 표현되는 파일의 경로입니다.

transparent

콘텐츠 영역이 투명하고 창의 그림자 기능이 꺼져 있는지 여부.

X11은 추가로 다음을 지원합니다:

type

윈도우 매니저가 창을 해석하는 데 사용해야 하는 창 유형 또는 우선순위에 따른 유형 목록입니다(예: 'dialog' 또는 'splash').

zoomed

창이 최대화되어 있는지 여부.

참고

Tk 8.6에서 type 어트리뷰트가 추가되었으며, Tk 9.0에서는 appearance, class, stylemask, tabbingid 및 tabbingmode 어트리뷰트가 추가되었습니다.

X11에서는 변경 사항이 비동기적으로 적용되므로, 조회된 값이 아직 최신 요청을 반영하지 않을 수 있습니다. wm_attributes`는 :meth:()!attributes`의 별칭입니다.

버전 3.13에서 변경: 이제 단일 어트리뷰트를 앞에 - 를 붙이지 않고 이름으로 조회할 수 있으며, 키워드 인자를 사용하여 어트리뷰트를 설정할 수 있습니다. return_python_dict 파라미터가 추가되었습니다.

버전 3.13부터 폐지됨: 옵션 이름(앞에 - 포함)과 값을 두 개의 위치 인자로 전달하여 어트리뷰트를 설정하는 방식(예: w.attributes('-alpha', 0.5))은 더 이상 권장되지 않습니다. 대신 키워드 인자를 사용하십시오.

client(name=None)¶

윈도우 또는 세션 매니저에서 사용할 수 있도록, 애플리케이션이 실행되는 호스트의 이름이어야 하는 name 을 창의 WM_CLIENT_MACHINE 속성에 저장합니다. 빈 문자열을 사용하면 속성이 삭제됩니다. 인자가 없으면 마지막으로 설정된 이름을 반환하며, 설정된 값이 없으면 빈 문자열을 반환합니다. wm_client() 는 client() 의 별칭입니다.

colormapwindows(*wlist)¶

전용 컬러맵을 가진 창에 대한 정보를 윈도우 매니저에 알리는 WM_COLORMAP_WINDOWS 속성을 조작합니다. wlist 가 제공되면 해당 속성을 해당 창들로 덮어씁니다(그들의 순서는 컬러맵 설치를 위한 우선순위입니다). 인자가 없으면 현재 해당 속성에 이름이 지정된 창의 목록을 반환합니다. wm_colormapwindows() 는 colormapwindows() 의 별칭입니다.

command(value=None)¶

윈도우 또는 세션 매니저에서 사용하도록 창의 WM_COMMAND 속성에 value 를 저장합니다. 이 값은 애플리케이션을 실행하는 데 사용된 명령의 단어들을 포함하는 목록이어야 합니다. 빈 문자열을 사용하면 속성이 삭제됩니다. 인자가 없으면 마지막으로 설정된 값을 반환하며, 설정된 값이 없으면 빈 문자열을 반환합니다. wm_command() 는 command() 의 별칭입니다.

deiconify()¶

맵핑(mapping)을 통해 창을 일반(아이콘화되지 않은) 형태로 표시합니다. 창이 한 번도 맵핑된 적이 없는 경우, 이 함수는 처음 맵핑될 때 아이콘화되지 않은 상태로 나타나도록 보장합니다. Windows에서는 창을 위로 올리고 포커스를 부여합니다. wm_deiconify`는 :meth:()!deiconify`의 별칭입니다.

focusmodel(model=None)¶

창의 포커스 모델을 설정하거나 조회합니다. model 은 'active' (포커스가 다른 애플리케이션에 있더라도 해당 창이나 그 하위 요소들이 입력 포커스를 독점함) 또는 'passive' (창이 윈도우 매니저가 제공하는 포커스에 의존함) 중 하나입니다. 인수가 없으면 현재 모델을 반환합니다. 기본값은 focus() 명령이 사용하는 'passive' 입니다. wm_focusmodel() 은 focusmodel() 의 별칭입니다.

forget(window)¶

화면에서 window 의 매핑을 해제하여 윈도우 매니저가 더 이상 관리하지 않도록 합니다. 이 경우 Toplevel 은 Frame 처럼 취급되지만, -menu 설정은 유지되며 위젯이 다시 관리될 때 메뉴가 다시 나타납니다. wm_forget() 은 forget() 의 별칭입니다.

Not to be confused with Pack.forget().

Added in version 3.3.

frame()¶

윈도우 매니저가 창을 그러한 프레임으로 재부모화(reparented)한 경우, 해당 창을 포함하는 가장 바깥쪽의 장식 프레임에 대한 플랫폼별 창 식별자를 반환합니다. 그렇지 않으면 창 자체의 식별자를 반환합니다. wm_frame`은 :meth:()!frame`의 별칭입니다.

geometry(newGeometry=None)¶

창의 지오메트리(geometry)를 설정하거나 조회합니다. newGeometry 는 =widthxheight+x+y 형식을 따르며, 이 중 =, widthxheight, +x+y 위치는 생략 가능합니다. width 와 height 는 픽셀(그리드 창의 경우 그리드 단위)로 표기됩니다. + 로 시작하는 좌표는 화면의 왼쪽 또는 상단 가장자리로부터 측정되며, - 로 시작하는 좌표는 오른쪽 또는 하단 가장자리부터 측정됩니다. 빈 문자열은 사용자가 지정한 지오메트리를 취소하고 창을 원래 크기로 되돌립니다. 인수가 없으면 현재 지오메트리를 '200x200+10+10' 과 같은 형식의 문자열로 반환합니다. wm_geometry() 는 geometry() 의 별칭입니다.

grid(baseWidth=None, baseHeight=None, widthInc=None, heightInc=None)¶

창을 그리드(gridded) 창으로 관리하고 그리드 단위와 픽셀 간의 관계를 정의합니다. baseWidth 와 baseHeight 는 창이 내부적으로 요청한 크기에 대한 그리드 단위 수이고, widthInc 와 heightInc 는 가로 및 세로 그리드 단위의 픽셀 크기입니다. 빈 문자열은 그리드 관리를 비활성화합니다. 인수가 없으면 네 가지 현재 값의 튜플을 반환하며, 창이 그리드 방식이 아니면 빈 문자열을 반환합니다. wm_grid() 는 grid() 의 별칭입니다.

Not to be confused with the grid geometry manager Grid.grid().

group(pathName=None)¶

관련 창 그룹의 리더를 설정하거나 조회합니다. pathName 은 그룹 리더의 경로 이름을 지정하며, 예를 들어 리더가 아이콘화될 때 윈도우 매니저가 해당 그룹 내의 모든 창의 매핑을 해제할 수 있습니다. 빈 문자열을 입력하면 창을 모든 그룹에서 제거합니다. 인수가 없으면 현재 그룹 리더의 경로 이름을 반환하며, 없을 경우 빈 문자열을 반환합니다. wm_group() 은 group() 의 별칭입니다.

iconbadge(badge)¶

Set a badge for the window’s icon, intended for display in the Dock (macOS), taskbar (Windows) or app panel (X11). badge may be a positive integer (for example a count of unread messages) or an exclamation point to denote that attention is needed; an empty string removes the badge. On X11 the variable ::tk::icons::base_icon(window) must be set to the window’s icon image for the badge to appear. wm_iconbadge() is an alias of iconbadge().

Added in version 3.16.0a0 (unreleased): Requires Tk 9.0 or newer.

iconbitmap(bitmap=None, default=None)¶

윈도우 매니저가 창의 아이콘에 사용하는 비트맵을 설정하거나 조회합니다. bitmap*은 Tk에서 허용하는 표준 형식 중 하나인 비트맵을 지정하며, 빈 문자열은 현재 아이콘 비트맵 설정을 취소합니다. 인수가 없으면 현재 아이콘 비트맵의 이름을 반환하며, 없을 경우 빈 문자열을 반환합니다. Windows에서는 *default 인수로 자체 아이콘이 없는 모든 최상위 창에 적용될 아이콘(예: .ico 파일)을 지정할 수 있습니다. wm_iconbitmap`은 :meth:()!iconbitmap`의 별칭입니다.

iconify()¶

창을 아이콘화합니다. 창이 아직 한 번도 매핑된 적이 없는 경우, 나중에 매핑될 때 아이콘 상태로 나타나도록 준비합니다. wm_iconify`는 :meth:()!iconify`의 별칭입니다.

iconmask(bitmap=None)¶

아이콘 마스크로 사용되는 비트맵을 설정하거나 조회합니다(참고: iconbitmap()). 마스크가 0인 곳에는 아이콘이 표시되지 않으며, 1인 곳에는 해당 아이콘 비트맵의 관련 비트들이 표시됩니다. 빈 문자열을 전달하면 현재 마스크를 해제합니다. 인수가 없으면 현재 아이콘 마스크의 이름을 반환하며, 설정된 것이 없으면 빈 문자열을 반환합니다. wm_iconmask`는 :meth:()!iconmask`의 별칭입니다.

iconname(newName=None)¶

Register func as the handler for the window manager protocol name, an atom such as 'WM_DELETE_WINDOW', 'WM_SAVE_YOURSELF' or 'WM_TAKE_FOCUS'; func is then called whenever the window manager sends a message of that protocol. class tkinter.Pack¶

Geometry manager that arranges widgets by packing them against the sides of their container. The Pack mix-in is inherited by all widgets (through Widget) and provides the methods for managing a widget with the pack geometry manager. See also 패커.

참고

Pack, Place and Grid all define the short method names forget(), info(), slaves(), content() and propagate(). On a widget the bare names resolve to the pack manager’s versions, since Pack and Misc precede Place and Grid in the method resolution order, whatever manager actually manages the widget; and configure()/config() configure the widget’s options, not its geometry. Use the explicit pack_*, grid_* and place_* methods (and pack, grid, place for geometry configuration) to act on a specific geometry manager.

class tkinter.XView¶

xview(*args)¶

뷰의 수평 위치를 조회하거나 변경합니다. 인자가 없으면 현재 보이는 문서 영역을 0과 1 사이의 두 분수 비율로 나타내는 튜플 (first, last) 를 반환합니다. 그렇지 않으면 인수가 Tk xview_ 위젯 명령으로 전달되며 보통 스크롤 막대에 의해 생성됩니다. xview_moveto() 와 xview_scroll() 은 더 편리한 인터페이스를 제공합니다.

xview_moveto(fraction)¶

문서 전체 너비의 fraction 이 왼쪽 화면 밖에 위치하도록 뷰를 조정합니다. fraction 은 0과 1 사이의 숫자입니다.

xview_scroll(number, what)¶

class tkinter.Canvas(master=None, cnf={}, **kw)¶

Canvas 위젯은 구조화된 그래픽을 구현합니다. 호(arc), 선(line), 타원(oval), 다각형(polygon), 직사각형(rectangle), 텍스트, 비트맵, 이미지 및 임베디드 창과 같이 그리기, 이동, 색상 변경 및 이벤트 바인딩이 가능한 다양한 아이템 을 표시합니다. 이 위젯은 Widget, XView, 그리고 YView 를 상속받으므로, xview() 와 yview() 를 사용하여 뷰를 가로 및 세로로 스크롤할 수 있습니다. 위젯과 아이템 옵션의 전체 목록은 Tk canvas 매뉴얼 페이지를 참조하십시오.

각 아이템은 생성 시 할당되는 고유한 정수형 id 와 하나 이상의 문자열 tags 를 가집니다. 태그는 정수 형태가 아닌 임의의 문자열이며, 동일한 태그를 여러 아이템이 공유할 수 있으므로 아이템 그룹화에 편리합니다. 특수한 태그 'all'' 은 캔버스의 모든 아이템과 일치하고, 'current'' 는 마우스 포인터 아래에 있는 가장 위의 아이템과 일치합니다. 대부분의 메서드는 단일 아이템을 식별하는 정수형 id 또는 하나 이상의 아이템을 식별하는 태그가 될 수 있는 tagOrId 인수를 받습니다. Tk canvas 매뉴얼 페이지에서 설명된 바와 같이, 태그는 &&, ||, ^, ! 연산자와 괄호로 결합된 태그들의 논리식일 수도 있습니다. 단일 아이템을 대상으로 하는 메서드에 여러 아이템이 일치하는 tagOrId 가 제공되는 경우, 일반적으로 표시 목록(display list)에서 가장 낮은 위치의 일치하는 아이템을 사용합니다.

아이템은 그리기 순서를 결정하는 display list 에 보관됩니다. 리스트의 뒤쪽에 있는 아이템이 앞선 아이템 위에 그려집니다. 새로 생성된 아이템은 리스트의 맨 위에 배치되며, 해당 순서는 tag_raise() 및 tag_lower() 로 변경할 수 있습니다.

create_arc(*args, **kw)¶
create_bitmap(*args, **kw)¶
create_image(*args, **kw)¶
create_line(*args, **kw)¶
create_oval(*args, **kw)¶
create_polygon(*args, **kw)¶
create_rectangle(*args, **kw)¶
create_text(*args, **kw)¶
create_window(*args, **kw)¶

해당 유형의 새로운 아이템을 생성하고 정수형 id를 반환합니다. 각 메서드는 create_TYPE(coord..., **options)``와 같은 형식으로 호출됩니다. 앞선 위치 인수는 아이템을 정의하는 좌표(개별 숫자, 단일 숫자 시퀀스 또는 좌표 쌍 형태)를 나타내고, 키워드 인수는 아이템 전용 옵션을 설정합니다. 좌표 및 화면 거리는 숫자로 제공될 수도 있고(이 경우 픽셀로 해석됨), 단위 접미사(‘m’’, ``'c'', 'i'' 또는 'p'' — 각각 밀리미터, 센티미터, 인치, 프린터 포인트)가 포함된 문자열로 제공될 수도 있으나, 항상 픽셀 단위로 저장되고 반환됩니다.

아이템 유형은 다음과 같습니다: arc (포함되는 직사각형의 대각선 양 끝 모서리 x1, y1, x2, y2 에 의해 정의되며 타원의 일부분인 호 모양 영역), bitmap (지점 x, y 에 위치한 2색 비트맵), image (지점 x, y 에 위치한 Tk 이미지), line (지점 x1, y1, ..., xn, yn 을 통과하는 선 또는 곡선), oval (직사각형 x1, y1, x2, y2 내부에 들어 있는 원 또는 타원), polygon (지점 x1, y1, ..., xn, yn 을 지나는 닫한 다각형), rectangle (모서리 x1, y1, x2, y2 를 가진 직사각형), text (지점 x, y 에 위치한 텍스트 문자열), 그리고 window (window 옵션으로 지정된 지점 x, y 에 임베디드 된 자식 위젯).

대부분의 아이템 유형은 공통적인 표준 아이템 옵션 세트와 각 유형에 고유한 몇 가지 옵션을 지원합니다. 옵션 이름은 앞에 붙는 하이픈(-) 없이 키워드 인수로 전달됩니다.

표준 항목 옵션은 다음과 같습니다:

fill

항목의 내부를 채우거나, line 항목 또는 text 항목의 문자를 그릴 때 사용되는 색상입니다. 빈 문자열(내용이 없는 경우이며, line 과 text 를 제외한 모든 유형에 대한 기본값임)은 항목을 채우지 않은 상태로 둡니다.

outline

항목의 외곽선을 그릴 때 사용하는 색상입니다. 빈 문자열은 외곽선을 그리지 않습니다.

width

외곽선의 너비이며, 기본값은 1.0 입니다. outline 이 비어 있으면 적용되지 않습니다.

dash

외곽선용 대시(dash) 패턴으로, 픽셀 단위의 세그먼트 길이 시퀀스 또는 '.', ',', '-', '_' 및 공백 문자로 구성된 문자열로 제공됩니다. 빈 패턴(기본값)은 실선 형태의 외곽선을 그립니다.

dashoffset

dash 패턴 내에서 시작되는 픽셀 단위 오프셋입니다. dash 패턴이 없는 경우 무시됩니다.

stipple

항목을 채울 때 스티플(stipple) 패턴으로 사용되는 비트맵입니다. X11 환경에서만 안정적으로 지원됩니다.

outlinestipple

외곽선을 그릴 때 스티플 패턴으로 사용되는 비트맵입니다. outline 이 비어 있으면 아무런 효과가 없습니다.

offset, outlineoffset

채우기 및 외곽선 스티플 패턴의 오프셋이며, 'x,y' 또는 'n', 'se' 또는 'center' 와 같은 방향으로 제공됩니다. 스티플 오프셋은 X11에서만 지원됩니다.

state

이 항목에 대한 캔버스 상태를 재정의합니다. 가능한 값은 'normal', 'disabled' 또는 'hidden' 입니다.

tags

항목과 연관된 단일 태그 또는 태그 시퀀스이며, 기존의 모든 태그를 대체합니다.

이 옵션 중 상당수는 항목이 활성 상태(마우스 포인터 아래에 있음)이거나 비활성화된 상태일 때 기본 옵션을 재정의하는 active… 및 disabled… 변형(예: activefill, disabledfill, activewidth, disableddash, activeoutline, disabledstipple)을 포함합니다.

다음 항목 유형은 추가 옵션을 지원합니다.

arc 항목의 경우:

start

3시 방향에서 반시계 방향으로 측정한 도(degree) 단위의 호 각도 범위 시작 지점입니다.

extent

start 에서 반시계 방향으로 측정된 도(degree) 단위의 각도 범위 크기입니다.

style

호가 그려지는 방식: 'pieslice'``(기본값), ``'chord' 또는 'arc'.

line 항목의 경우:

arrow

화살촉이 그려지는 위치: 'none'``(기본값), ``'first', 'last' 또는 'both'.

arrowshape

화살촉의 모양을 설명하는 세 개의 거리 시퀀스입니다.

capstyle

선 끝이 그려지는 방식: 'butt'``(기본값), ``'projecting' 또는 'round'.

joinstyle

선 정점이 그려지는 방식: 'round'``(기본값), ``'bevel' 또는 'miter'.

smooth

부드럽게 처리하는 방식입니다. 부드러운 처리를 하지 않으려면 거짓(false) 값(기본값)을 사용하고, 선을 곡선으로 그리려면 'true'/'bezier' 또는 'raw' 를 선택합니다.

splinesteps

smooth 가 활성화된 경우, 각 스플린을 근사하는 선 세그먼트의 수입니다.

polygon 항목의 경우:

joinstyle, smooth, splinesteps

line 항목의 경우 폴리곤(polygon)의 윤곽선에 적용됩니다.

text 항목의 경우:

text

표시할 문자열입니다. 줄 바꿈 문자는 새로운 줄을 시작합니다.

font

텍스트에 사용되는 글꼴입니다.

justify

줄의 정렬 방식입니다: 'left'``(기본값), ``'right' 또는 'center'.

anchor

기준점에 대한 텍스트의 위치이며, 기본값은 'center' 입니다.

class tkinter.Checkbutton(master=None, cnf={}, **kw)¶

Checkbutton 위젯은 사각형 표시기와 함께 텍스트 문자열, 비트맵 또는 이미지를 표시하며, 눌렀을 때 불리언(boolean) 선택 상태를 토글합니다. 이 위젯은 단순 버튼의 모든 동작을 수행할 뿐만 아니라 선택이 가능합니다. 선택되면 표시기에 체크 표시가 그려지고 관련 변수가 onvalue 로 설정되며, 해제되면 표시기에 아무것도 그려지지 않고 변수가 offvalue 로 설정됩니다. Widget 를 상속받습니다. 표준 위젯 옵션 외에도, checkbutton은 Tk checkbutton 매뉴얼 페이지에 기술된 variable, onvalue, offvalue 및 command 와 같은 옵션을 지원합니다.

class tkinter.Entry(master=None, cnf={}, **kw)¶

Entry 위젯은 한 줄의 텍스트를 표시하며 사용자가 이를 편집할 수 있게 합니다. Widget 및 XView 를 상속받으며, 엔트리는 창에 들어가지 않을 정도로 긴 문자열을 포함할 수 있으므로 xview() 를 통한 가로 스크롤을 지원합니다.

In addition to the standard widget options, an entry accepts the options documented in the Tk entry manual page. Notable ones are textvariable (the name of a variable kept in sync with the entry’s contents), show (if set, each character is displayed as the given character rather than its true value, useful for password entry), validate and validatecommand (which together let a callback accept or reject edits), and state (one of 'normal', 'disabled' or 'readonly').

아래 메서드 중 다수는 엔트리 문자열에서 문자를 선택하는 index 인수를 받습니다. Tk entry 매뉴얼 페이지에 설명된 대로, index 는 숫자(0부터 시작), 'insert' (삽입 커서 바로 다음의 문자), 'end' (마지막 문자 바로 뒤), 'anchor' (선택 앵커 포인트), 'sel.first' 및 'sel.last' (선택 영역의 양 끝), 또는 @x (창에서 x 좌표 x 에 해당하는 문자)일 수 있습니다. 범위를 벗어난 인덱스는 가장 가까운 유효한 값으로 반올림됩니다.

delete(first, last=None)¶

엔트리의 현재 문자열을 반환합니다.

insert(index, string)¶

index 가 가리키는 문자 바로 앞에 string 을 삽입합니다.

icursor(index)¶

index 가 가리키는 문자 바로 앞에 삽입 커서가 표시되도록 설정합니다.

index(index)¶

index 에 해당하는 수치 인덱스를 반환합니다.

selection_adjust(index)¶

index 로 지정된 문자와 가장 가까운 선택 영역의 끝을 찾아, 그 끝이 index 가 되도록 조정합니다(단, index 를 포함하되 넘어서는 안 됩니다). 다른 한쪽은 향후 selection_to() 호출을 위한 앵커 포인트가 됩니다. 엔트리 내에 선택 영역이 없는 경우, index 와 가장 최근의 앵커 포인트 사이(양 끝 포함)에 새로운 영역을 생성합니다. select_adjust() 는 selection_adjust() 의 별칭입니다.

This shadows the inherited Misc.selection_clear(), which clears the X selection; that method is not available on an Entry.

선택 영역을 변경하지 않고, index 가 가리키는 문자 바로 앞을 선택 앵커 포인트로 설정합니다. select_from() 은 selection_from() 의 별칭입니다.

앵커 포인트와 index 사이의 영역을 선택합니다. index 가 앵커 포인트보다 앞선 경우, index 부터 앵커 포인트를 포함하지 않고 그 전까지 선택됩니다. index 가 앵커 포인트보다 뒤에 있는 경우, 앵커 포인트부터 index 를 포함하지 않고 그 전까지 선택됩니다. 두 지점이 일치하면 아무런 변화도 없습니다. 앵커 포인트는 가장 최근의 selection_from() 또는 selection_adjust() 호출로 설정된 것입니다. 엔트리 내에 선택 영역이 없는 경우, 가장 최근의 앵커 포인트를 사용하여 새로운 영역을 생성합니다. select_to() 는 selection_to() 의 별칭입니다.

scan_mark(x)¶

나중에 호출될 scan_dragto() 에서 사용하기 위해 엔트리 창의 x 좌표와 현재 뷰를 기록합니다. 일반적으로 위젯 내에서 마우스 버튼을 누를 때 실행됩니다.

class tkinter.Listbox(master=None, cnf={}, **kw)¶

Listbox 위젯은 한 줄의 텍스트 항목들을 리스트로 표시하며, 사용자는 이 중 하나 이상을 선택할 수 있습니다. 선택 동작 방식은 selectmode 옵션에 의해 결정되며, 다음과 같은 모드 중 하나를 지원합니다: browse (기본값; 최대 하나의 항목이며 마우스로 드래그 가능), single (최대 하나의 항목), multiple (임의의 개수의 항목을 각각 별도로 토글), 또는 extended (비연속적인 범위를 포함하여 임의의 개수의 항목을 클릭 및 드래그로 선택). Widget, XView 및 YView 를 상속하며, 이에 따라 xview() 와 yview() 를 사용하여 뷰를 가로 및 세로로 스크롤할 수 있습니다. 전체 옵션 목록은 Tk listbox 매뉴얼 페이지를 참조하십시오.

Many of the methods take an index argument identifying a particular item. As described in the Tk listbox manual page, index may be a numeric index (counting from 0 at the top), 'active' (the item with the location cursor, set with activate()), 'anchor' (the selection anchor, set with selection_anchor()), 'end' (the last item, or for index() and insert() the position just after it), or @x,y (the item covering pixel coordinates x, y in the listbox window). Arguments named first and last are indices of the same forms.

현재 선택된 모든 항목의 숫자 인덱스를 포함하는 튜플을 반환합니다. 선택된 항목이 없는 경우 빈 튜플을 반환합니다.

selection_anchor(index)¶

Set the selection anchor to the item given by index. If index refers to a non-existent item, the closest item is used. The selection anchor is the end of the selection that is fixed while dragging out a selection with the mouse, and may afterwards be referred to with the 'anchor' index. select_anchor() is an alias of selection_anchor().

selection_clear(first, last=None)¶

first 부터 last 까지 포함된 범위 내에서 선택된 항목들을 선택 해제합니다. 이 범위를 벗어난 항목의 선택 상태는 변경되지 않습니다. select_clear() 는 selection_clear() 의 별칭입니다.

참고

selection_includes(index)¶

index 로 지정된 항목이 현재 선택되어 있으면 True 를, 그렇지 않으면 False 를 반환합니다. select_includes() 는 selection_includes() 의 별칭입니다.

selection_set(first, last=None)¶

first 부터 last 까지 포함된 범위 내의 모든 항목을 선택하며, 해당 범위를 벗어난 항목의 선택 상태에는 영향을 주지 않습니다. select_set() 은 selection_set() 의 별칭입니다.

itemcget(index, option)¶

index 로 지정된 항목에 대해 설정 옵션 option 의 현재 값을 반환합니다.

itemconfigure(index, cnf=None, **kw)¶

index 로 지정된 항목의 구성 옵션을 조회하거나 수정합니다. 이는 리스트박스 전체가 아닌 개별 항목에 적용된다는 점을 제외하고는 configure() 와 동일하게 작동합니다. 옵션이 없는 경우 항목의 현재 옵션을 설명하는 딕셔너리를 반환하며, 그렇지 않으면 지정된 옵션들을 설정합니다. 지원되는 항목 옵션은 background, foreground, selectbackground 및 selectforeground 입니다. itemconfig() 는 itemconfigure() 의 별칭입니다.

scan_mark(x, y)¶

향후 scan_dragto() 호출 시 사용하기 위해 x, y 및 현재 뷰를 기록합니다. 이 작업은 일반적으로 위젯에서 마우스 버튼 클릭에 바인딩됩니다.

scan_dragto(x, y)¶

x, y 와 마지막으로 호출된 scan_mark() 에 전달된 좌표 사이의 차이의 10배만큼 리스트박스를 스크롤합니다. 이는 일반적으로 위젯 내에서 마우스 이동 이벤트에 바인딩되어, 창을 통해 리스트를 빠른 속도로 드래그하는 효과를 생성합니다.

class tkinter.Menu(master=None, cnf={}, **kw)¶

Menu 위젯은 항목(entry)의 열을 표시하며, 각 항목은 명령(command), 체크 버튼(checkbutton), 라디오 버튼(radiobutton), 계층형 메뉴(cascade, 연관된 하위 메뉴를 게시함) 또는 구분선(separator)이 될 수 있습니다. 메뉴는 최상위 창의 메뉴바, 계층형 항목이나 메뉴 버튼에서 호출되는 풀다운 메뉴, 그리고 팝업 메뉴로 사용됩니다. Widget 을 상속받습니다.

많은 항목 메서드는 작업을 수행할 항목을 선택하는 index 인수를 받습니다. Tk menu 매뉴얼 페이지에 설명된 바와 같이, index 는 숫자 인덱스(상단부터 0으로 카운트), 'active' (현재 활성화된 항목), 'end' 또는 'last' (가장 아래에 있는 항목), 'none' (아무도 없는 상태, Tcl에서는 {} 로 표기됨), @y (메뉴 창에서 y 좌표 y 를 포함하는 영역), 또는 상단부터 하향식으로 일치하는 패턴이 될 수 있습니다.

add(itemType, cnf={}, **kw)¶

메뉴의 하단에 새 항목을 추가합니다. itemType 은 'command', 'cascade', 'checkbutton', 'radiobutton' 또는 'separator' 중 하나이며, 새 항목의 유형을 결정합니다. 나머지 옵션들은 이를 구성합니다. add_command(), add_cascade(), add_checkbutton(), add_radiobutton() 및 add_separator() 편의 메서드는 해당 itemType 과 함께 이 메서드를 호출합니다.

항목은 다음 옵션들에 의해 구성되지만, 모든 옵션이 모든 항목 유형에 적용되는 것은 아닙니다(separator는 어떤 옵션도 적용되지 않습니다).

label

항목에 표시할 텍스트입니다.

command

항목이 호출될 때 실행할 함수입니다(command, checkbutton 및 radiobutton 항목).

accelerator

가속(accelerator) 키 입력을 알리기 위해 항목 오른쪽에 표시되는 문자열입니다. 이 자체로 바인딩을 생성하지는 않습니다.

underline

키보드 탐색 시 강조하기 위해 레이블에서 밑줄을 그을 문자의 인덱스입니다.

state

'normal', 'active' 또는 'disabled' 중 하나입니다.

image

텍스트 레이블 대신 또는 텍스트 레이블과 함께 표시될 이미지입니다.

compound

텍스트에 대한 이미지의 표시 위치입니다: 'none'``(기본값), ``'text', 'image', 'top', 'bottom', 'left' 또는 'right'.

bitmap

텍스트 레이블 대신 표시할 비트맵입니다.

font

텍스트에 사용할 글꼴입니다.

background, foreground

항목의 일반 상태에서의 배경색과 전경색입니다(macOS에서는 무시됩니다).

activebackground, activeforeground

항목이 활성화되었을 때 사용되는 배경색과 전경색입니다(macOS에서는 무시됩니다).

columnbreak

참(true)인 경우, 항목이 이전 항목 아래에 배치되는 대신 새로운 열을 시작합니다.

hidemargin

참(true)인 경우 항목 주변의 표준 여백이 생략되며, 이는 메뉴가 팔레트로 사용될 때 유용합니다.

menu

cascade 항목에 의해 게시되는 서브메뉴입니다. 이 서브메뉴는 반드시 이 메뉴의 자식이어야 합니다.

variable

checkbutton 또는 radiobutton 항목과 관련된 변수입니다.

onvalue, offvalue

checkbutton 항목이 선택되거나 해제될 때 variable 에 저장되는 값입니다.

value

radiobutton 항목이 선택될 때 variable 에 저장되는 값입니다.

indicatoron

checkbutton 또는 radiobutton 항목의 표시등(indicator)을 표시할지 여부입니다.

selectcolor

checkbutton 또는 radiobutton 항목이 선택되었을 때 표시등의 색상입니다.

selectimage

checkbutton 또는 radiobutton 항목이 선택되고 image 도 제공된 경우에 표시되는 이미지입니다.

add_cascade(cnf={}, **kw)¶

메뉴 하단에 새로운 cascade 항목을 추가합니다. cascade 항목은 menu 옵션으로 제공되는 관련 서브메뉴를 가지며, 이 서브메뉴는 반드시 해당 메뉴의 자식이어야 합니다. 항목을 게시할 때 서브메뉴가 그 옆에 함께 게시됩니다.

add_checkbutton(cnf={}, **kw)¶

메뉴 하단에 새로운 checkbutton 항목을 추가합니다. checkbutton 항목은 호출될 때 onvalue 와 offvalue 사이를 전환하며, 그 결과를 관련 variable 에 저장하고 선택 여부를 나타내는 표시등을 표시합니다.

add_command(cnf={}, **kw)¶

메뉴 하단에 새로운 명령 항목을 추가합니다. 명령 항목은 버튼과 유사하게 작동하며, 호출 시 command 옵션에 지정된 콜백이 실행됩니다.

add_radiobutton(cnf={}, **kw)¶

메뉴 하단에 새로운 라디오 버튼(radiobutton) 항목을 추가합니다. 동일한 variable 을 공유하는 라디오 버튼 항목은 그룹을 형성하며, 한 번에 하나만 선택할 수 있습니다. 항목을 선택하면 해당 항목의 value 가 변수에 저장됩니다.

add_separator(cnf={}, **kw)¶

메뉴 하단에 구분선(separator)을 추가합니다. 구분선은 가로 구분선으로 표시되며 활성화하거나 호출할 수 없습니다.

insert(index, itemType, cnf={}, **kw)¶

add() 와 동일하지만, 새 항목을 메뉴 끝에 추가하는 대신 index 로 지정된 항목 바로 앞에 삽입합니다. itemType 은 'command', 'cascade', 'checkbutton', 'radiobutton' 또는 'separator' 중 하나입니다. insert_command(), insert_cascade(), insert_checkbutton(), insert_radiobutton() 및 insert_separator() 편의 메서드는 해당 itemType 을 사용하여 이 메서드를 호출합니다.

insert_cascade(index, cnf={}, **kw)¶

index 로 지정된 항목 앞에 새로운 캐스케이드(cascade) 항목을 삽입합니다(참고: add_cascade()).

insert_checkbutton(index, cnf={}, **kw)¶

index 로 지정된 항목 앞에 새로운 체크버튼(checkbutton) 항목을 삽입합니다(참고: add_checkbutton()).

insert_command(index, cnf={}, **kw)¶

index 로 지정된 항목 앞에 새로운 명령(command) 항목을 삽입합니다(참고: add_command()).

insert_radiobutton(index, cnf={}, **kw)¶

index 로 지정된 항목 앞에 새로운 라디오 버튼(radiobutton) 항목을 삽입합니다(참고: add_radiobutton()).

insert_separator(index, cnf={}, **kw)¶

index 로 지정된 항목 앞에 구분선(separator)을 삽입합니다(참고: add_separator()).

delete(index1, index2=None)¶

index1*과 *index2 사이의 모든 메뉴 항목을 삭제합니다(양 끝 포함). index2*가 생략된 경우 기본값으로 *index1*이 설정되어 단일 항목이 삭제됩니다. 떼어내기(tear-off) 항목을 삭제하려는 시도는 무시되므로, 대신 *tearoff 옵션을 변경하여 제거하십시오.

entrycget(index, option)¶

index 로 지정된 항목의 구성 옵션 option 의 현재 값을 반환합니다.

entryconfigure(index, cnf=None, **kw)¶

index 로 지정된 항목의 구성 옵션을 조회하거나 수정합니다. 이는 메뉴 전체가 아닌 개별 항목에 적용된다는 점을 제외하고는 configure() 와 동일하게 작동합니다. 옵션이 없는 경우 해당 항목의 현재 옵션을 설명하는 딕셔너리를 반환하며, 그렇지 않으면 제공된 옵션을 설정합니다. 지원되는 옵션은 해당 항목 유형에 대해 add() 가 허용하는 것들입니다. entryconfig() 는 entryconfigure() 의 별칭(alias)입니다.

index(index)¶

index 에 해당하는 수치 인덱스를 반환합니다. index 가 아무 항목도 선택하지 않은 경우 None 을 반환합니다.

type(index)¶

index 로 지정된 항목의 유형을 반환합니다. 유형은 'command', 'cascade', 'checkbutton', 'radiobutton', 'separator' 또는 'tearoff' (떼어내기 항목) 중 하나입니다.

activate(index)¶

index 로 지정1된 항목을 활성(active) 항목으로 설정하고, 활성 색상을 적용하여 다시 표시하며, 이전에 활성화되었던 항목을 비활성화합니다. index 가 아무 항목도 선택하지 않거나 선택된 항목이 비활성화된 경우, 메뉴에 활성 항목이 없게 됩니다.

invoke(index)¶

index 로 지정된 항목이 클릭된 것처럼 동작을 실행합니다. 항목이 비활성화된 경우 아무 일도 일어나지 않습니다. 항목에 command 가 연결되어 있는 경우 해당 명령의 결과가 반환되며, 그렇지 않으면 빈 문자열을 반환합니다.

post(x, y)¶

postcascade(index)¶

Post the submenu associated with the cascade entry given by index, unposting any previously posted submenu. This has no effect if index does not name a cascade entry or if the menu itself is not posted.

tk_popup(x, y, entry='')¶

xposition(index)¶

메뉴 창 내에서 index 로 지정된 항목의 가장 왼쪽 픽셀의 x 좌표를 반환합니다.

yposition(index)¶

메뉴 창 내에서 index 로 지정된 항목의 가장 위쪽 픽셀의 y 좌표를 반환합니다.

class tkinter.Menubutton(master=None, cnf={}, **kw)¶

Menubutton 위젯은 사용자가 클릭할 때 텍스트 문자열, 비트맵 또는 이미지를 표시하고 menu 옵션에 의해 지정된 관련 Menu 를 게시합니다. Label 과 마찬가지로 text, textvariable 또는 image 를 표시할 수 있으며, direction 옵션은 버튼을 기준으로 메뉴가 나타나는 위치를 제어합니다. 이 위젯은 Widget 을 상속받습니다. 전체 옵션 목록은 Tk menub_button 매뉴얼 페이지를 참조하십시오.

class tkinter.Message(master=None, cnf={}, **kw)¶

Message 위젯은 text 옵션에 의해 제공되거나 textvariable 을 통해 변수에 연결된 비대화형 텍스트 문자열을 표시합니다. Label 과 달리, 주어진 종횡비를 생성하기 위해 문자열을 여러 줄로 나누며 단어 경계에서 줄바꿈을 선택하고, 텍스트를 왼쪽, 가운데 또는 오른쪽으로 정렬할 수 있습니다. 이 위젯은 Widget 을 상속받습니다. 전체 옵션 목록은 Tk message 매뉴얼 페이지를 참조하십시오.

class tkinter.OptionMenu(master, variable, value, *values, **kwargs)¶

A helper subclass of Menubutton that displays a pop-up menu of mutually exclusive choices. variable is a Variable kept in sync with the selection, value is the initial choice, and values are the remaining menu entries. The keyword argument command may be given a callback that is invoked with the selected value, and the keyword argument name sets the Tk widget name. Other keyword arguments are passed to the underlying Menubutton and may override its default appearance.

class tkinter.PanedWindow(master=None, cnf={}, **kw)¶

PanedWindow 는 임의의 수의 자식 panes 를 행(orient 가 'horizontal' 인 경우) 또는 열(orient 가 'vertical' 인 경우)로 배치하는 지오메트리 관리자(geometry-manager) 위젯입니다. 각 pane은 하나의 위젯을 포함하며, 인접한 각 쌍의 pane은 사용자가 마우스로 드래그하여 양쪽의 위젯 크기를 조정할 수 있는 이동 가능한 sash 에 의해 구분됩니다. 이 위젯은 Widget 을 상속받습니다.

orient 옵션은 레이아웃 방향을 선택하고, sashwidth 는 각 sash의 너비를 설정하며, sashrelief 는 해당 relief를 설정합니다. showhandle 이 참(true)이면 사용자가 잡아서 드래그할 수 있는 작은 핸들이 각 sash에 그려집니다. 전체 옵션 목록은 Tk panedwindow 매뉴얼 페이지를 참조하십시오.

add(child, **kw)¶

child 를 기존 pane들 다음에 배치되는 새 pane으로 panedwindow에 추가합니다. 키워드 인자는 child 에 대한 각 pane별 관리 옵션을 지정하며, 이는 paneconfigure() 에서 허용하는 모든 옵션이 될 수 있습니다.

remove(child)¶

Remove the pane containing child from the panedwindow. All geometry management options for child are forgotten. forget() is an alias of remove(). This shadows the inherited geometry-manager forget(); use pack_forget(), grid_forget() or place_forget() to remove the widget itself from its manager.

panes()¶

panedwindow에 의해 관리되는 위젯들을 각 pane 하나당 하나씩 순서대로 튜플로 반환합니다.

panecget(child, option)¶

child 를 포함하는 pane의 관리 옵션 option 의 현재 값을 반환합니다. option 은 paneconfigure() 에서 허용하는 모든 값이 될 수 있습니다.

paneconfigure(tagOrId, cnf=None, **kw)¶

tagOrId 위젯을 포함하는 pane의 관리 옵션을 조회하거나 수정합니다. 옵션이 없는 경우 해당 pane에서 사용 가능한 모든 옵션을 설명하는 딕셔너리를 반환하며, 문자열로 된 단일 옵션 이름을 제공하면 해당 옵션에 대한 설명을 반환하고, 그 외의 경우에는 지정된 옵션들을 설정합니다. 지원되는 옵션에는 after 및 before (다른 관리되는 창 앞에 또는 뒤에 pane을 삽입), height 및 width (경계 포함 창의 외측 치수), minsize (paned 차원에서의 최소 크기), padx 및 pady (창의 각 측면에 남길 여유 공간), sticky (문자 n, s, e, w 를 사용하여 양이 많은(oversized) pane 내에서 창의 위치나 확장 비율을 결정), hide (pane 목록은 유지하면서 pane을 숨김), 그리고 stretch (여분의 공간이 pane에 할당되는 방식: 'always', 'first', 'last', 'middle' 또는 'never' 중 하나)가 포함됩니다. paneconfig() 는 paneconfigure() 의 별칭입니다.

identify(x, y)¶

윈도우 좌표계에서 x 와 y 로 주어진 점 아래에 있는 panedwindow 컴포넌트를 식별합니다. 만약 해당 지점이 sash 또는 sash 핸드(handle) 위에 있다면, 결과는 sash 또는 핸드의 인덱스와 그것이 sash인지 handle인지를 나타내는 단어를 포함하는 두 요소의 튜플(예: (0, 'sash') 또는 (2, 'handle'))입니다. 점이 panedwindow의 다른 부분 위에 있는 경우 결과는 빈 문자열을 반환합니다.

sash(*args)¶

panedwindow 내의 sashes 위치를 조회하거나 변경합니다. 이 메서드는 Tk sash 서브커맨드를 위한 얇은 래퍼(wrapper)이며, 일반적으로는 편리한 기능인 sash_coord(), sash_mark() 및 sash_place() 메서드를 대신 사용하는 것이 좋습니다.

sash_coord(index)¶

index 로 지정된 sash의 현재 x 및 y 좌표 쌍을 반환합니다. index 는 0과 panedwindow 내 pane 수에서 하나를 뺀 값 사이의 정수여야 합니다. 반환되는 좌표는 해당 sash를 포함하는 영역의 왼쪽 상단 모서리 좌표입니다.

sash_mark(index)¶

나중에 sash를 이동하기 위한 sash-drag 작업과 함께 사용하도록, index 로 지정된 sash의 현재 마우스 위치를 기록합니다.

sash_place(index, x, y)¶

index*로 지정된 sash를 *x 및 y 좌표에 배치합니다.

proxy(*args)¶

sash proxy의 위치를 조회하거나 변경합니다. sash proxy는 비불투명(non-opaque) 크기 조정 시 sash가 드래그되는 동안 표시되는 “고스트” sash입니다. 이 메서드는 Tk proxy 서브커맨드를 위한 얇은 래퍼이며, 일반적으로는 편리한 기능인 proxy_coord(), proxy_forget() 및 proxy_place() 메서드를 대신 사용하는 것이 좋습니다.

proxy_coord()¶

가장 최근의 proxy 위치를 포함하는 x 및 y 좌표 튜플을 반환합니다.

proxy_forget()¶

표시 화면에서 proxy를 제거합니다.

proxy_place(x, y)¶

proxy를 x 및 y 좌표에 배치합니다.

class tkinter.Radiobutton(master=None, cnf={}, **kw)¶

Radiobutton 위젯은 텍스트 문자열, 비트맵 또는 이미지와 함께 다이아몬드형 또는 원형 표시기를 보여주며, 여러 선택지 중 하나를 선택합니다. 이 위젯은 단순 버튼의 모든 동작을 수행하며, 추가로 선택 기능을 제공합니다. 일반적으로 여러 radiobutton이 하나의 variable 을 공유하며, 하나를 선택하면 해당 변수가 해당 radiobutton의 value 로 설정됩니다. 또한 각 radiobutton은 해당 변수를 모니터링하여 변수가 변경될 때 자동으로 자신을 선택하거나 해제합니다. Widget 을 상속받습니다. 표준 위젯 옵션 외에도, radiobutton은 Tk radiobutton 매뉴얼 페이지에 설명된 variable, value 및 command 와 같은 옵션을 수용합니다.

invoke()¶

사용자가 마우스로 radiobutton을 클릭했을 때와 동일한 동작을 수행합니다. 즉, 버튼을 선택하고 관련 명령이 있는 경우 해당 명령을 실행합니다. 명령이 없으면 빈 문자열을 반환하며, radiobutton의 상태가 disabled 인 경우에는 이 동작이 무시됩니다.

select()¶

radiobutton을 선택하고 관련 변수를 해당 위젯에 해당하는 값으로 설정합니다.

deselect()¶

radiobutton의 선택을 해제하고 관련 변수를 빈 문자열로 설정합니다. 이 radiobutton이 현재 선택된 상태가 아니었다면 아무런 영향도 주지 않습니다.

flash()¶

활성(active) 색상과 기본(normal) 색상을 번갈아 가며 여러 번 다시 표시하여 radiobutton을 깜박이게 합니다. 깜박임이 끝난 후에도 radiobutton은 메서드 호출 당시와 동일한 기본 또는 활성 상태를 유지합니다. radiobutton의 상태가 disabled 인 경우 이 동작은 무시됩니다.

class tkinter.Scale(master=None, cnf={}, **kw)¶

Scale 위젯은 사용자가 트러프(trough)를 따라 슬라이더를 움직여 수치 값을 선택할 수 있게 합니다. 세로 또는 가로 방향으로 배치될 수 있으며, 옵션에 따라 레이블과 현재 값을 표시할 수 있습니다. Widget 을 상속받습니다.

In addition to the standard widget options, a scale accepts the options documented in the Tk scale manual page, such as from_, to, resolution, orient, tickinterval, variable and command. As elsewhere in tkinter, the leading - of the Tk option name is dropped; from is spelled from_ because from is a Python keyword.

get()¶

scale의 현재 값을 반환합니다. 결과는 scale의 resolution 이 정수를 생성하는 경우 정수로 반환되며, 그렇지 않으면 실수(float)로 반환됩니다.

set(value)¶

스케일을 value 로 설정하고 그에 따라 슬라이더를 이동시킵니다. 스케일이 비활성화된 경우 영향이 없습니다.

coords(value=None)¶

value 에 해당하는 트러프 중심선의 포인트에 대한 위젯 상대적 픽셀 좌표를 (x, y) 튜플로 반환합니다. value 가 생략된 경우 스케일의 현재 값이 사용됩니다.

identify(x, y)¶

픽셀 좌표 x, y 에 위치한 스케일 부분('slider', 'trough1' $(슬라이더 위 또는 왼쪽의 트러프 부분)$, 'trough2' $(슬라이더 아래 또는 오른쪽의 트러프 부분)$)을 설명하는 문자열을 반환합니다. 해당 지점이 이러한 요소 중 어느 것과도 겹치지 않으면 빈 문자열을 반환합니다.

class tkinter.Scrollbar(master=None, cnf={}, **kw)¶

Scrollbar 위젯은 사용자에게 연결된 위젯(예: Listbox, Text, Canvas 또는 Entry)을 스크롤할 수 있도록 하는 슬라이더와 두 개의 화살표를 표시합니다. 해당 위젯의 xscrollcommand 또는 yscrollcommand 옵션을 스크롤 막대의 set() 메서드로 설정하고, 스크롤 막대의 command 옵션을 대상 위젯의 xview() 또는 yview() 메서드로 설정하여 연결됩니다. Widget 을 상속받습니다.

get()¶

현재 가시적인 문서 영역을 설명하는 0과 1 사이의 두 분수로 구성된 튜플 (first, last) 를 반환합니다. 이 값은 마지막으로 set() 에 전달된 것과 같습니다.

set(first, last)¶

스크롤 막대를 설정합니다. first 와 last 는 연결된 문서의 가시 영역 시작 및 종료 위치를 나타내는 0과 1 사이의 분수입니다. 이 메서드는 보통 스크롤되는 위젯의 xscrollcommand 또는 yscrollcommand 로 등록되며 해당 위젯에 의해 호출됩니다.

activate(index=None)¶

Mark the element index (one of 'arrow1', 'slider' or 'arrow2') as active, displaying it according to the activebackground and activerelief options. If index is omitted, return the name of the currently active element, or None if no element is active.

버전 3.5에서 변경: index 인수는 이제 생략 가능합니다.

delta(deltax, deltay)¶

슬라이더를 수평(수평 스크롤 막대의 경우)으로 deltax 픽셀 또는 수직(수직 스크롤 막대의 경우)으로 deltay 픽셀 이동할 때 해당하는 스크롤 막대 설정의 비율 변화를 나타내는 부동 소수점 값을 반환합니다.

fraction(x, y)¶

픽셀 좌표 x, y 에 위치한 점이 트러프 내 어느 곳에 있는지 나타내는 0과 1 사이의 부동 소수점 값을 반환합니다. 여기서 0은 트러프의 상단 또는 왼쪽을, 1은 하단 또는 오른쪽을 의미합니다.

identify(x, y)¶

픽셀 좌표 x, y 아래에 있는 요소(예: 'arrow1')의 이름을 반환하며, 해당 지점이 스크롤 막제의 어떠한 요소와도 일치하지 않는 경우 빈 문자열을 반환합니다.

class tkinter.Spinbox(master=None, cnf={}, **kw)¶

Spinbox 위젯은 값을 직접 편집할 수 있을 뿐만 아니라 상/하 화살표 버튼을 사용하여 일련의 값 범위를 단계별로 이동할 수 있는 Entry 형태의 위젯입니다. 값 세트는 from_, to, 및 increment 옵션에 의해 제공되는 숫자 범위이거나, values 옵션(범위보다 우선됨)을 통해 명시된 문자열 리스트일 수 있습니다. 화살표를 사용할 때마다 (존재하는 경우) command 콜백이 실행되며, wrap 옵션은 범위를 벗어날 때 반대편으로 순환할지 여부를 제어합니다. format 옵션은 숫자 값이 출력되는 형식을 지정하며, validate 옵션은 입력된 텍스트의 유효성 검사를 활성화합니다. Widget 및 XView 를 상속받습니다.

많은 메서드가 스핀박스 문자열의 문자를 식별하는 index 인수를 받습니다. Tk spinbox 매뉴얼 페이지에 설명된 대로, index 는 숫자 인덱스(0부터 시작), 'anchor' (선택 앵커 지점), 'end' (마지막 문자 바로 뒤), 'insert' (삽입 커서 바로 다음의 문자), 'sel.first' 또는 'sel.last' (선택 영역의 끝), 또는 @x (창에서 x-좌표 x 에 해당하는 문자)가 될 수 있습니다.

get()¶

스핀박스의 문자열을 반환합니다.

insert(index, s)¶

s 문자열의 문자들을 index 로 지정된 문자의 바로 앞에 삽입합니다.

delete(first, last=None)¶

스핀박스의 하나 이상의 문자를 삭제합니다. first*는 삭제할 첫 번째 문자의 인덱스이고, *last*는 삭제할 마지막 문자의 바로 다음 문자의 인덱스입니다. *last*가 생략된 경우, *first 위치에 있는 단일 문자가 삭제됩니다.

icursor(index)¶

index 가 가리키는 문자 바로 앞에 삽입 커서가 표시되도록 설정합니다.

index(index)¶

index 에 해당하는 수치 인덱스를 문자열로 반환합니다.

bbox(index)¶

index 로 지정된 문자의 바운딩 박스를 설명하는 4개의 정수 튜플 (x, y, width, height) 를 반환합니다. x 와 y 는 위젯을 기준으로 한 해당 문자의 왼쪽 상단 모서리 픽셀 좌표이며, width 와 height 는 픽셀 단위의 크기입니다. 바운딩 박스는 창의 가시 영역 외의 영역을 가리킬 수도 있습니다.

This shadows the inherited Misc.bbox(); use grid_bbox() for the grid bounding box.

identify(x, y)¶

픽셀 좌표 x, y 에 있는 창 요소의 이름을 반환합니다. 가능한 값은 'buttondown', 'buttonup', 'entry' 또는 'none' 중 하나입니다.

invoke(element)¶

element 로 지정된 스핀 버튼('buttonup' 또는 'buttondown')을 호출하여 해당 동작을 실행합니다.

scan(*args)¶

뷰를 빠르게 드래그하는 기능을 구현하기 위해 Tk scan_ 위젯 서브 명령을 감싸는 래퍼입니다. scan_('mark', x) 는 x 와 현재 뷰를 기록하고, scan_('dragto', x) 는 해당 마크에 맞춰 뷰를 조정합니다. scan_mark() 및 scan_dragto() 메서드는 이 두 형식을 각각 감싸고 있습니다.

scan_mark(x)¶

나중에 호출할 scan_dragto() 에서 사용하기 위해 스핀박스 창에 x 와 현재 뷰를 기록합니다. 이는 보통 위젯에서의 마우스 버튼 클릭과 연관됩니다.

scan_dragto(x)¶

x 와 마지막 scan_mark() 호출에 전달된 x 사이의 차이에 10을 곱한 만큼 뷰를 조정합니다. 이는 주로 마우스 이동 이벤트와 연관되며, 사용자가 창에서 스핀박스를 빠른 속도로 드래그하는 효과를 냅니다.

selection(*args)¶

스핀박스 내의 선택 영역을 조정하기 위해 Tk selection 위젯 서브 명령을 감싸는 래퍼입니다. 첫 번째 인수에 따라 여러 형식이 있으며, 예를 들어 selection('adjust', index), selection('clear), selection('element', ?elem?), selection('from', index), selection('present), selection('range', start, end) 및 selection('to', index) 등이 있습니다. selection_adjust(), selection_clear(), selection_element(), selection_from(), selection_present(), selection_range() 및 selection_to() 메서드가 이 형상들을 감싸고 있습니다.

selection_adjust(index)¶

index 로 지정된 문자에 가장 가까운 선택 영역의 끝을 찾아 해당 지점을 index 에 맞게 조정합니다(인덱스를 포함하되 넘지 않음). 다른 한쪽 끝은 향후 selection_to() 호출을 위한 앵커 포인트가 됩니다. 현재 스핀박스 내에 선택 영역이 없는 경우, index 와 가장 최근의 앵커 포인트 사이의 문자들을 포함하는 새로운 선택 영역이 생성됩니다.

selection_clear()¶

class tkinter.Text(master=None, cnf={}, **kw)¶

Text 위젯은 멀티라인 텍스트를 표시하고 편집합니다. 텍스트의 일부에는 tags 로 스타일을 입힐 수 있고, 특정 위치는 플로팅 marks 로 주석을 달 수 있으며, 임의의 이미지 및 기타 위젯들을 텍스트에 삽입할 수 있습니다. 이 위젯은 무제한의 실행 취소/다시 실행(undo/redo) 기능을 제공하며 동일한 기초 데이터를 공유하는 피어 위젯을 지원합니다. Widget, XView, 그리고 YView 를 상속하므로, 뷰를 xview() 및 yview() 로 가로 및 세로 방향으로 스크롤할 수 있습니다. 전체 옵션 목록은 Tk text 매뉴얼 페이지를 참조하십시오.

대부분의 메서드는 텍스트 내의 위치를 식별하는 하나 이상의 index 인수를 받습니다. Tk text 매뉴얼 페이지에 설명된 대로, 인덱스는 기본(base)으로 구성되며 선택적으로 하나 이상의 수정자(modifier)가 뒤따르는 문자열입니다. 기본은 'line.char' (라인 line, 글자 char 이며, 라인은 1부터 세고 한 줄 내의 문자는 0부터 시작함; 'line.end' 는 해당 행을 끝내는 개행 문자를 의미), 'end' (마지막 개행 바로 다음 위치), 마크(mark) 이름, 'tag.first' 또는 'tag.last' (tag 으로 태그된 첫 번째 문자 또는 그러한 마지막 문자 바로 뒤의 위치), 삽입된 이미지나 창의 이름, 또는 @x,y (위젯 내 픽셀 좌표 x, y 를 포함하는 문자)가 될 수 있습니다. '+5 chars', '-3 lines', 'linestart', 'lineend', 'wordstart' 또는 'wordend' 와 같은 수정자는 기본을 기준으로 인덱스를 조정하며, 여러 수정자를 결합하여 왼쪽에서 오른쪽 방향으로 적용할 수 있습니다. 예를 들어 'insert wordstart - 1 c' 와 같이 사용할 수 있습니다.

insert(index, chars, *args)¶

index 위치의 문자 바로 앞에 chars 를 삽입합니다(만약 index 가 'end' 인 경우, 마지막 개행 문자의 바로 앞). 기본적으로 새 텍스트는 삽입 지점 양쪽에 존재하는 모든 태그를 상속받습니다. args 가 제공되는 경우, 이는 tagList 와 chars 값이 번갈아 나타나는 형식으로 구성되며, 앞에 오는 chars 에 나열된 태그 목록(태그 목록은 단일 태그 이름 또는 이름의 시퀀스일 수 있음)을 정확히 적용하여 주변의 태그를 덮어씌웁니다.

search(pattern, index, stopindex=None, forwards=None, backwards=None, exact=None, regexp=None, nocase=None, count=None, elide=None, *, nolinestop=None, strictlimits=None)¶

class tkinter.Variable(master=None, value=None, name=None)¶

Tk 변수 래퍼의 기본 클래스입니다. Tk 변수는 Tcl 인터프리터에 저장되는 값으로, 위젯의 variable 또는 textvariable 옵션을 통해 연결될 수 있습니다(참조: 위젯 변수 결합하기). 이를 통해 양방히 방향으로 변경 사항이 전파됩니다. 즉, 변수를 업데이트하면 해당 변수와 바인딩된 모든 위젯이 업데이트되고, 사용자가 해당 위젯을 편집하면 변수가 업데이트됩니다.

master 는 해당 변수를 소유하는 Tcl 인터프리터의 위젯입니다. 생략할 경우 기본 루트 창이 사용됩니다. value 는 초기값이며, 생략 시 유형별(type-specific) 기본값이 사용됩니다. name 은 Tcl 인터프리터 내의 변수 이름이며, 생략될 경우 'PY_VARnum' 형태의 고유한 이름이 생성됩니다. name 이 기존 변수와 일치하고 value 가 생략된 경우에는 기존 값이 유지됩니다.

대부분의 경우, Variable 을 직접 사용하는 대신 아래와 같이 타입이 지정된 하위 클래스 중 하나를 사용해야 합니다. – StringVar, IntVar, DoubleVar 또는 BooleanVar

버전 3.10에서 변경: 이제 두 변수는 이름이 같고, 클래스가 동일하며, 동일한 Tcl 인터프리터에 속할 때만 서로 같은지(==) 비교합니다.

구성 옵션은 data 또는 file (X11 비트맵 형식의 문자열이나 해당 형식이 지정된 파일 이름), maskdata 또는 maskfile (동일한 형식의 마스크 비트맵), 그리고 foreground 와 background (두 가지 색상)입니다. 마스크가 0인 픽셀은 아무것도 표시하지 않으며, 그 외의 픽셀은 소스가 1이면 전경색을, 소스가 0이면 배경색을 표시합니다. background 가 빈 문자열로 설정된 경우, 해당 배경 픽셀은 투명하게 처리됩니다.

BitmapImage 는 Image 에서 상속받은 것 외에 자체적인 메서드가 없습니다.

class tkinter.Event¶

Misc.bind() 로 바인드된 콜백에 전달되는 이벤트 속성들의 컨테이너입니다. Event 인스턴스는 다음과 같은 속성들을 가지며, 각각은 기본 Tk 이벤트의 필드와 대응합니다. 이벤트 유형에 따라 일부 속성은 의미가 없음을 나타내기 위해 '??' 문자열로 설정될 수 있습니다. 자세한 내용은 바인딩과 이벤트 를 참조하십시오.

class tkinter.EventType(*values)¶

Tk 이벤트 유형을 열거하는 enum.StrEnum 이며, Event.type 의 값으로 사용됩니다. 이 멤버에는 KeyPress, KeyRelease, ButtonPress, ButtonRelease, Motion, Enter, Leave, FocusIn, FocusOut, Configure, Map, Unmap, Expose, Destroy 및 MouseWheel 등이 포함됩니다.

Added in version 3.6.

class tkinter.CallWrapper(func, subst, widget)¶

Tcl에서 호출할 수 있도록 파이썬 콜백을 래핑하는 내부 도우미입니다. func 는 파이썬 함수이고, subst 는 Tcl 인수를 전처리하는 선택적 기능이며, widget 은 오류 보고에 사용되는 위젯입니다. 이 클래스의 인스턴스는 Misc.register() 에 의해 자동으로 생성되며, 일반적으로 직접 사용되지 않습니다.
