imaplib — IMAP4 프로토콜 클라이언트¶

소스 코드: Lib/imaplib.py

이 모듈은 IMAP4, IMAP4_SSL 및 IMAP4_stream`의 세 가지 클래스를 정의하며, 이들은 IMAP4 서버 연결을 캡슐화하고 :rfc:`3501`에 정의된 대로 IMAP4rev1 클라이언트 프로토콜의 상당 부분을 구현합니다. IMAP4 (:rfc:`1730) 서버와 하위 호환되지만, IMAP4에서는 STATUS 명령이 지원되지 않음에 유의하십시오.

가용성: not WASI.

이 모듈은 웹어셈블리에서 작동하지 않거나 제공되지 않습니다. 자세한 내용은 웹어셈블리 플랫폼을 참조하세요.

imaplib 모듈은 세 가지 클래스를 제공하며, IMAP4 는 베이스 클래스입니다:

class imaplib.IMAP4(host='', port=IMAP4_PORT, timeout=None)¶

이 클래스는 실제 IMAP4 프로토콜을 구현합니다. 연결이 만들어지고 인스턴스가 초기화될 때 프로토콜 버전(IMAP4 또는 IMAP4rev1)이 결정됩니다. host를 지정하지 않으면, ''(로컬 호스트)가 사용됩니다. port를 생략하면, 표준 IMAP4 포트(143)가 사용됩니다. 선택적 timeout 매개 변수는 연결 시도에 대한 시간제한을 초로 지정합니다. timeout이 제공되지 않거나 None이면, 전역 기본 소켓 시간제한이 사용됩니다.

IMAP4 클래스는 with 문을 지원합니다. 이처럼 사용될 때, with 문을 빠져나갈 때 IMAP4 LOGOUT 명령이 자동으로 발행됩니다. 예를 들어:

>>> from imaplib import IMAP4
>>> with IMAP4("domain.org") as M:
...     M.noop()
...
('OK', [b'Nothing Accomplished. d25if65hy903weo.87'])

버전 3.5에서 변경: with 문에 대한 지원이 추가되었습니다.

버전 3.9에서 변경: 선택적 timeout 매개 변수가 추가되었습니다.

세 가지 예외가 IMAP4 클래스의 어트리뷰트로 정의됩니다:

exception IMAP4.error¶

모든 에러에 대해 발생하는 예외. 예외의 이유는 문자열로 생성자에 전달됩니다.

exception IMAP4.abort¶

IMAP4 서버 에러는 이 예외를 발생시킵니다. 이것은 IMAP4.error의 서브 클래스입니다. 인스턴스를 닫고 새 인스턴스를 만들면 일반적으로 이 예외에서 복구할 수 있습니다.

exception IMAP4.readonly¶

쓰기 가능한 사서함(mailbox)의 상태가 서버에 의해 변경되면 이 예외가 발생합니다. 이것은 IMAP4.error의 서브 클래스입니다. 이제 일부 다른 클라이언트에는 쓰기 권한이 있으며, 쓰기 권한을 다시 얻으려면 사서함을 다시 열어야 합니다.

보안 연결을 위한 서브 클래스도 있습니다:

class imaplib.IMAP4_SSL(host='', port=IMAP4_SSL_PORT, *, ssl_context=None, timeout=None)¶

SSL 암호화 소켓을 통해 연결되는 IMAP4에서 파생된 서브 클래스입니다 (이 클래스를 사용하려면 SSL 지원과 함께 컴파일된 소켓 모듈이 필요합니다). host를 지정하지 않으면, ''(로컬 호스트)가 사용됩니다. port를 생략하면, 표준 IMAP4-over-SSL 포트(993)가 사용됩니다. ssl_context는 SSL 구성 옵션, 인증서 및 개인 키를 단일 (잠재적으로 오래가는) 구조로 번들링 할 수 있는 ssl.SSLContext 객체입니다. 모범 사례는 보안 고려 사항을 읽으십시오.

참고

기본 ssl_context 를 사용하면 연결은 암호화되지만 서버 인증서와 호스트 이름은 검증되지 않습니다. 이를 검증하려면 ssl.create_default_context() 로 생성된 컨텍스트를 전달하십시오.

선택적 timeout 매개 변수는 연결 시도에 대한 시간제한을 초로 지정합니다. timeout이 제공되지 않거나 None이면, 전역 기본 소켓 시간제한이 사용됩니다.

버전 3.3에서 변경: ssl_context 매개 변수가 추가되었습니다.

버전 3.4에서 변경: 이 클래스는 이제 ssl.SSLContext.check_hostname과 서버 이름 표시(Server Name Indication)로 호스트명 확인을 지원합니다 (ssl.HAS_SNI를 참조하십시오).

버전 3.9에서 변경: 선택적 timeout 매개 변수가 추가되었습니다.

버전 3.12에서 변경: 폐지된 keyfile 과 certfile 매개 변수를 제거했습니다.

두 번째 서브 클래스는 자식 프로세스가 만든 연결을 허용합니다:

class imaplib.IMAP4_stream(command)¶

이것은 command를 subprocess.Popen()에 전달하여 만들어진 stdin/stdout 파일 기술자에 연결하는 IMAP4에서 파생된 서브 클래스입니다.

다음과 같은 유틸리티 함수가 정의됩니다:

imaplib.Internaldate2tuple(resp)¶

IMAP4 INTERNALDATE 응답이 포함된 bytes-like object 를 구문 분석하여 해당하는 지역 시간을 반환합니다. 입력 형식이 올바르지 않으면 반환 값은 time.struct_time 튜플이거나 None 입니다.

imaplib.Int2AP(num)¶

집합 [A .. P]의 문자를 사용하여 정수를 바이트열 표현으로 변환합니다.

imaplib.ParseFlags(resp)¶

IMAP4 FLAGS 응답이 포함된 bytes-like object 를 bytes 형태의 개별 플래그 튜플로 변환합니다. 입력 형식이 올바르지 않으면 반환 값은 빈 튜플입니다.

imaplib.Time2Internaldate(date_time)¶

date_time을 IMAP4 INTERNALDATE 표현으로 변환합니다. 반환 값은 다음과 같은 형식의 문자열입니다: "DD-Mmm-YYYY HH:MM:SS +HHMM" (큰따옴표를 포함합니다). date_time 인자는 에포크 이후의 초(time.time()이 반환하는 것과 같습니다)를 나타내는 숫자 (int 또는 float), 지역 시간을 나타내는 9-튜플인 time.struct_time의 인스턴스 (time.localtime()이 반환하는 것과 같습니다), datetime.datetime의 어웨어(aware) 인스턴스 또는 큰따옴표로 인용된(double-quoted) 문자열일 수 있습니다. 마지막 경우에는, 이미 올바른 형식으로 되어 있다고 가정합니다.

사서함이 변경됨에 따라 IMAP4 메시지 번호가 변경됨에 유의하십시오. 특히, EXPUNGE 명령이 삭제를 수행한 후 나머지 메시지의 번호가 다시 매겨집니다. 따라서 UID 명령으로 UID를 대신 사용하는 것이 좋습니다.

모듈의 끝에는, 더 광범위한 사용 예제가 포함된 테스트 섹션이 있습니다.

IMAP4 객체¶

모든 IMAP4rev1 명령은 대문자나 소문자의 같은 이름의 메서드로 표현됩니다.

AUTHENTICATE``와 IMAP4 리터럴로 전달되는 ``APPEND``의 마지막 인자를 제외하고, 명령에 대한 모든 인자는 문자열로 변환됩니다. 필요한 경우(문자열에 IMAP4 프로토콜 민감 문자가 포함되어 있고 괄호나 큰따옴표로 둘러싸여 있지 않은 경우) 각 문자열은 인용됩니다. 그러나 ``LOGIN 명령의 password 인자는 항상 인용됩니다. 인자 문자열이 인용되는 것을 방지하려면(예: STORE``의 *flags* 인자), 해당 문자열을 괄호로 묶으십시오(예: ``r'(\Deleted)'). 또는 직접 문자열을 인용할 수도 있습니다. 이미 큰따옴표로 둘러싸인 인자는 변경되지 않습니다. 일반적으로는 인용되지 않은 상태로 전달하고 모듈이 필요에 따라 인용하도록 하는 것이 좋습니다.

Mailbox names are encoded as modified UTF-7 (RFC 3501, section 5.1.3), so a mailbox name containing non-ASCII characters can be passed as an ordinary str. A str that is already valid modified UTF-7 is left unchanged, so that a name obtained from list() (raw bytes decoded to text) round-trips; pass bytes to send the exact bytes with no encoding. When UTF8=ACCEPT is enabled (see enable()), mailbox names are sent as UTF-8 instead.

버전 3.16.0a0 (unreleased)에서 변경: 비 ASCII 사서함 이름은 자동으로 modified UTF-7으로 인코딩됩니다.

대부분의 명령은 튜플 (type, [data, ...]) 을 반환하며, 여기서 type 은 보통 'OK' 또는 'NO' 이고, data 는 명령 응답에서 나온 텍스트이거나 명령에 따른 필수 결과입니다. 각 data 는 bytes 이거나 튜플입니다. 튜플인 경우 첫 번째 부분은 응답의 헤더이고 두 번째 부분은 데이터(즉, ‘literal’ 값)를 포함합니다.

아래 명령의 message_set 옵션은 수행할 하나 이상의 메시지를 지정하는 문자열일 수 있습니다. 이는 단순 메시지 번호('1'), 메시지 번호 범위('2:4'), 또는 쉼표로 구분된 불연속 범위 그룹('1:3,6:9')이 될 수 있습니다. 범위에는 무한 상한을 나타내기 위해 별표가 포함될 수 있습니다('3:*').

또는 정수 및 range 객체를 사용하여 지정할 수 있습니다. 이는 단일 메시지 번호 또는 시퀀스일 수 있습니다. 시퀀스 항목은 정수, (start, stop) 튜플(여기서 None 또는 '*' 은 마지막 메시지를 의미함), 또는 range 객체일 수 있습니다. 예를 들어, [1, (3, 5), 8] 과 [range(1, 6), 8] 은 모두 '1,3:5,8' 과 동일합니다.

버전 3.16.0a0 (unreleased)에서 변경: 구조화된 message_set 에 대한 지원을 추가했습니다.

원자들의 괄호로 묶인 리스트 형태의 명령 인자(예: store() 의 flag_list 및 append() 의 flags, status() 의 names, sort() 의 sort_criteria, 또는 fetch() 의 message_parts)는 단일 미리 포맷된 문자열 대신 문자열 시퀀스로 전달할 수 있습니다. 예를 들어, [r'\Seen', r'\Answered'] 는 (\Seen \Answered) 와 동일합니다.

버전 3.16.0a0 (unreleased)에서 변경: 이러한 인자들을 시퀀스로 전달하는 기능을 추가했습니다.

검색 및 가져오기 명령의 값을 포함하는 인자는 수동으로 인용할 수도 있지만, 이는 오류가 발생하기 쉽습니다. 대신, 해당 인자들은 sqlite3 매개 변수 치환 방식과 유사하게 params 키워드 인자로부터 ? 자리 표시자를 사용하여 대체되고 필요에 따라 인용될 수 있습니다:

\# SEARCH FROM me@example.com SUBJECT "trip report"
M.search(None, 'FROM ? SUBJECT ?', params=['me@example.com', 'trip report'])

\# FETCH 1:5 (FLAGS BODY[HEADER.FIELDS (DATE FROM)])
M.fetch('1:5', 'FLAGS BODY[HEADER.FIELDS ?]', params=[['DATE', 'FROM']])

자리 표시자는 다음과 같습니다:

  • ? — astring: 문자열(필요한 경우 따옴표가 붙음), 정수 또는 정수 및/또는 문자열의 목록(괄호로 묶인 리스트로 전송됨);

  • ?f — 플래그 또는 플래그의 목록; 따옴표 없이 있는 그대로 전송됩니다.

  • ?s — 위에 기술된 구조화된 형태의 message_set 입니다.

?? 은 리터럴 ? 를 의미합니다.

params 가 제공될 때만 치환이 수행됩니다. params 가 제공되지 않으면 리터럴 ? 를 포함하는 인자는 변하지 않습니다. params 키워드는 search(), fetch(), sort(), thread() 및 uid() 에서 수용됩니다.

Added in version 3.16.0a0 (unreleased): params 키워드 인자.

IMAP4 인스턴스에는 다음과 같은 메서드가 있습니다:

IMAP4.append(mailbox, flags, date_time, message, *, translate_line_endings=True)¶

명명된 사서함(mailbox)에 message를 추가합니다.

flags 는 None 이거나 IMAP 플래그 토큰 문자열일 수 있습니다. 여러 개의 플래그는 공백으로 구분됩니다(예: r'\Seen \Answered'). flags 가 괄호로 묶여 있지 않은 경우 괄호가 자동으로 추가됩니다.

translate_line_endings 가 True(기본값)이면 message 의 줄 바꿈이 CRLF로 변환됩니다. 단독 CR 또는 LF를 포함하는 메시지를 그대로 유지하려면 False 를 전달하십시오. 이 경우 message 는 RFC 3501 에서 요구하는 대로 이미 CRLF 줄 바꿈을 사용해야 합니다. 예를 들어, email.policy.SMTP 를 사용하여 email 메시지를 직렬화하십시오.

버전 3.16.0a0 (unreleased)에서 변경: translate_line_endings 파라미터를 추가했습니다.

IMAP4.authenticate(mechanism, authobject)¶

인증 명령 — 응답 처리가 필요합니다.

mechanism은 사용할 인증 메커니즘을 지정합니다 - 인스턴스 변수 capabilities에 AUTH=mechanism 형식으로 나타나야 합니다.

authobject는 콜러블 객체여야 합니다:

data = authobject(response)

서버 계속(continuation) 응답을 처리하기 위해 호출됩니다; 전달된 response 인자는 bytes입니다. base64로 인코딩되어 서버로 전송되는 bytes data를 반환해야 합니다. 클라이언트 중단 응답 *를 대신 보내야 하면 None을 반환해야 합니다.

버전 3.5에서 변경: 문자열 사용자 이름과 비밀번호는 이제 ASCII로 제한되지 않고 utf-8로 인코딩됩니다.

IMAP4.check()¶

서버의 사서함을 검사합니다.

IMAP4.close()¶

현재 선택된 사서함을 닫습니다. 삭제된 메시지는 쓰기 가능한 사서함에서 제거됩니다. LOGOUT 이전의 권장 명령입니다.

IMAP4.copy(message_set, new_mailbox, *, uid=False)¶

message_set 메시지를 new_mailbox 끝에 복사합니다.

uid 가 true이면, message_set 은 UID의 집합이며 COPY 대신 UID COPY 명령이 사용됩니다.

버전 3.16.0a0 (unreleased)에서 변경: uid 파라미터를 추가했습니다.

IMAP4.create(mailbox)¶

mailbox라는 이름의 새 사서함을 만듭니다.

IMAP4.delete(mailbox)¶

mailbox라는 이름의 기존 사서함을 삭제합니다.

IMAP4.deleteacl(mailbox, who)¶

사서함(mailbox)의 사용자(who)에 대해 설정된 ACL을 삭제합니다 (모든 권한을 제거합니다).

IMAP4.enable(capability)¶

capability를 활성화합니다 (RFC 5161을 참조하십시오). 대부분의 기능은 활성화할 필요 없습니다. 현재 UTF8=ACCEPT 기능만 지원됩니다 (RFC 6855를 참조하십시오).

Added in version 3.5: enable() 메서드 자체와 RFC 6855 지원.

IMAP4.expunge(message_set=None, *, uid=False)¶

선택한 사서함에서 삭제된 항목을 영구적으로 제거합니다. 삭제된 각 메시지에 대해 EXPUNGE 응답을 생성합니다. 반환된 데이터에는 수신된 순서의 EXPUNGE 메시지 번호 리스트가 포함됩니다.

IMAP4.idle(duration=None)¶

Idler`를 반환합니다. 이는 :rfc:`2177`에 정의된 IMAP4 ``IDLE` 명령을 구현하는 반복 가능한 컨텍스트 매니저입니다.

반환된 객체는 with 문에 의해 활성화될 때 IDLE 명령을 전송하고, iterator 프로토콜을 통해 IMAP 태그 없는 응답(untagged responses)을 생성하며, 컨텍스트 종료 시 DONE 을 전송합니다.

IDLE 명령을 보낸 후 도착하는 모든 비태그 응답(명령을 서버가 승인하기 전에 도착하는 응답 포함)은 반복을 통해 사용할 수 있습니다. (만약 with 컨텍스트에서 반복되지 않은 남아 있는 응답은 IDLE 이 끝난 후, IMAP4.response() 를 사용하여 평소와 같은 방식으로 검색할 수 있습니다.)

응답은 IMAP4 Objects 에 설명된 대로 (type, [data, ...]) 튜플로 표현됩니다.

duration 인수는 유휴 상태를 유지할 최대 시간(초)을 설정하며, 이 시간이 지나면 진행 중인 모든 반복이 중지됩니다. 이 값은 int 또는 float 일 수 있으며, 제한이 없는 경우 None 으로 설정합니다. 비활성 타임아웃을 적용하는 서버에서 이를 방지하려면 최대 29분(1740초) 이하로 유지해야 합니다. 소켓 연결이 필요하며, duration 은 IMAP4_stream 연결에서는 반드시 None 이어야 합니다.

>>> with M.idle(duration=29 * 60) as idler:
...     for typ, data in idler:
...         print(typ, data)
...
EXISTS [b'1']
RECENT [b'1']
Idler.burst(interval=0.1)¶

Yield a burst of responses no more than interval seconds apart (expressed as an int or float).

This generator is an alternative to iterating one response at a time, intended to aid in efficient batch processing. It retrieves the next response along with any immediately available subsequent responses. (For example, a rapid series of EXPUNGE responses after a bulk delete.)

소켓 연결이 필요하며, IMAP4_stream 연결에서는 작동하지 않습니다.

>>> with M.idle() as idler:
...     # 0.1초 이내에 이어지는 응답을 포함하여 응답을 가져옵니다.
...     batch = list(idler.burst())
...     print(f'processing {len(batch)} responses...')
...     print(batch)
...
처리 중인 응답 3개...
[('EXPUNGE', [b'2']), ('EXPUNGE', [b'1']), ('RECENT', [b'0'])]

팁

IMAP4.idle() 에 전달된 IDLE 컨텍스트의 최대 지속 시간이 묶음 내 첫 번째 응답을 기다릴 때 적용됩니다. 따라서 만료된 Idler 인 경우 이 제너레이터는 아무것도 생성하지 않고 즉시 반환됩니다. 루프에서 사용할 경우 호출자는 이 점을 고려해야 합니다.

참고

IMAP4.idle() 가 반환하는 이터레이터는 with 문 내에서만 사용 가능합니다. 해당 컨텍스트 이전이나 이후에도 명령이 끝날 때마다 요청하지 않은 응답들이 내부적으로 수집되며, IMAP4.response() 를 통해 가져올 수 있습니다.

참고

Idler 클래스 이름과 구조는 내부 인터페이스이므로 변경될 수 있습니다. 호출 코드는 컨텍스트 관리, 반복 및 공개 메서드의 안정성에 의존할 수 있지만, 해당 클래스를 서브클래스화하거나 인스턴스화하거나 비교하거나 기타 방식으로 직접 참조해서는 안 됩니다.

Added in version 3.14.

IMAP4.search(charset, criterion, [..., ]*, uid=False, params=None)¶

일치하는 메시지가 있는지 사서함을 검색합니다. charset은 None일 수 있으며, 이 경우 서버에 대한 요청에 CHARSET이 지정되지 않습니다. IMAP 프로토콜은 적어도 하나의 기준을 지정하도록 요구합니다; 서버가 에러를 반환하면 예외가 발생합니다. enable() 명령을 사용하여 UTF8=ACCEPT 기능이 활성화되면 charset은 None이어야 합니다.

uid 가 true이면, 응답에 포함된 메시지 번호는 UID입니다(UID SEARCH).

str 로 전달된 기준은 charset (Python에서 알려진 코덱이어야 함)으로 인코딩됩니다. charset 이 Python에서 지원하지 않는 방식일 경우, 이미 인코딩된 기준을 보내려면 bytes 를 전달하십시오. charset 이 None 인 경우(UTF8=ACCEPT 설정 시 필수), 해당 기준은 연결의 인코딩을 사용하여 전송됩니다.

params 가 제공되면, 조건 내의 ? 자리 표시자가 따옴표가 포함된 매개 변수로 대체됩니다(참조: the placeholders).

예:

\# M은 연결된 IMAP4 인스턴스입니다...
typ, msgnums = M.search(None, 'FROM', '"John Smith"')

\# 또는:
typ, msgnums = M.search(None, '(FROM "John Smith")')

\# 또는, 모듈이 값을 따옴표로 묶도록 하는 방식(권장됨):
typ, msgnums = M.search(None, 'FROM ?', params=['John Smith'])

버전 3.16.0a0 (unreleased)에서 변경: params 및 uid 매개 변수가 추가되었습니다. str 검색 조건은 charset 으로 인코딩됩니다.

IMAP4.sort(sort_criteria, charset, search_criterion, [..., ]*, uid=False, params=None)¶

sort 명령은 결과에 대한 정렬이 추가된 search의 변형입니다. 반환된 데이터는 일치하는 메시지 번호의 공백으로 구분된 목록을 포함합니다.

sort에는 search_criterion 인자 앞에 두 개의 인자가 있습니다; sort_criteria의 괄호로 묶은 목록과 검색 charset. search와 달리, 검색 charset 인자는 필수임에 유의하십시오. uid search가 search에 해당하는 방식으로 sort에 해당하는 uid sort 명령도 있습니다. sort 명령은 먼저 검색 기준의 문자열 해석을 위해 charset 인자를 사용하여 주어진 검색 기준과 일치하는 메시지를 사서함에서 검색합니다. 그런 다음 일치하는 메시지 수를 반환합니다.

uid 가 true이면, 응답에 포함된 메시지 번호는 UID입니다(UID SORT).

search() 와 마찬가지로, str 로 전달된 search_criterion 은 charset 으로 인코딩됩니다. 이미 인코딩된 값을 보내려면 bytes 를 전달하십시오.

params 가 제공되면, 검색 조건 내의 ? 자리 표시자가 따옴표가 포함된 매개 변수로 대체됩니다(참조: the placeholders).

이것은 IMAP4rev1 확장 명령입니다.

버전 3.16.0a0 (unreleased)에서 변경: params 및 uid 매개 변수가 추가되었습니다. str 검색 조건은 charset 으로 인코딩됩니다.

IMAP4.store(message_set, command, flag_list, *, uid=False)¶

사서함 내 메시지의 플래그 속성을 변경합니다. command 는 RFC 3501 의 섹션 6.4.6에 따라 “FLAGS”, “+FLAGS”, 또는 “-FLAGS” 중 하나로 지정되며, 선택적으로 “.SILENT” 접미사가 붙을 수 있습니다.

uid 가 true이면, message_set 은 UID의 집합이며 STORE 대신 UID STORE 명령이 사용됩니다.

예를 들어, 모든 메시지에 삭제 플래그를 설정하려면 다음을 수행합니다:

typ, data = M.search(None, 'ALL')
for num in data[0].split():
   M.store(num, '+FLAGS', r'\Deleted')
M.expunge()

참고

‘]’을 포함하는 플래그(예: “[test]”)를 생성하는 것은 RFC 3501 (IMAP 프로토콜)을 위반하는 사항입니다. 그러나 imaplib은 역사적으로 이러한 플래그 생성을 허용해 왔으며, Gmail과 같은 유명한 IMAP 서버들도 이러한 플래그를 수용하고 생성합니다. 또한 파이썬 이외의 프로그램들도 이러한 플래그를 생성합니다. RFC 위반이며 IMAP 클라이언트와 서버가 엄격하게 동작해야 함에도 불구하고, imaplib은 하위 호환성을 위해 이러한 플래그 생성을 계속 허용하며, Python 3.6부터는 실질적인 호환성을 높이기 위해 서버에서 전송된 경우에도 이를 처리합니다.

버전 3.16.0a0 (unreleased)에서 변경: uid 파라미터를 추가했습니다.

IMAP4.subscribe(mailbox)¶

새 사서함을 구독합니다.

IMAP4.thread(threading_algorithm, charset, search_criterion, [..., ]*, uid=False, params=None)¶

thread 명령은 결과에 대한 스레딩이 추가된 search의 변형입니다. 반환된 데이터는 스레드 구성원의 스페이스로 구분된 목록을 포함합니다.

스레드 구성원은 연속된 부모와 자식을 나타내는 스페이스로 구분된 0개 이상의 메시지 번호로 구성됩니다.

thread에는 search_criterion 인자 앞에 두 개의 인자가 있습니다; threading_algorithm과 검색 charset. search와 달리, 검색 charset 인자는 필수임에 유의하십시오. uid search가 search에 해당하는 방식으로 thread에 해당하는 uid thread 명령도 있습니다. thread 명령은 먼저 검색 기준의 문자열 해석을 위해 charset 인자를 사용하여 주어진 검색 기준과 일치하는 메시지를 사서함에서 검색합니다. 그런 다음 지정된 스레딩 알고리즘에 따라 스레드 된 일치 메시지들을 반환합니다.

uid 가 true이면, 응답에 포함된 메시지 번호는 UID입니다(UID THREAD).

search() 와 마찬가지로, str 로 전달된 search_criterion 은 charset 으로 인코딩됩니다. 이미 인코딩된 값을 보내려면 bytes 를 전달하십시오.

params 가 제공되면, 검색 조건 내의 ? 자리 표시자가 따옴표가 포함된 매개 변수로 대체됩니다(참조: the placeholders).

이것은 IMAP4rev1 확장 명령입니다.

버전 3.16.0a0 (unreleased)에서 변경: params 및 uid 매개 변수가 추가되었습니다. str 검색 조건은 charset 으로 인코딩됩니다.

IMAP4.uid(command, arg, [..., ]*, params=None)¶

메시지 번호가 아닌 UID로 식별된 메시지들로 명령 인자를 실행합니다. 명령에 적합한 응답을 반환합니다. 최소한 하나의 인자가 제공되어야 합니다; 아무것도 제공하지 않으면, 서버는 에러를 반환하고 예외가 발생합니다.

params 가 제공되면, SEARCH, SORT 및 THREAD 조건이나 FETCH 부분의 ? 자리 표시자가 따옴표가 포함된 매개 변수로 대체됩니다(참조: the placeholders).

버전 3.16.0a0 (unreleased)에서 변경: params 매개 변수가 추가되었습니다.

IMAP4.unsubscribe(mailbox)¶

기존 사서함에서 구독 취소합니다.

IMAP4.unselect()¶

imaplib.IMAP4.unselect()는 선택한 사서함과 관련된 서버 자원을 해제하고 서버를 인증된 상태로 되돌립니다. 이 명령은 현재 선택된 사서함에서 메시지가 영구적으로 제거되지 않는다는 점을 제외하고, imaplib.IMAP4.close()와 같은 작업을 수행합니다.

Added in version 3.9.

IMAP4.xatom(name[, ...])¶

CAPABILITY 응답에서 서버가 통지한 간단한 확장 명령을 허용합니다.

IMAP4 인스턴스에는 다음과 같은 어트리뷰트가 정의되어 있습니다:

IMAP4.PROTOCOL_VERSION¶

서버의 CAPABILITY 응답에서 가장 최근에 지원되는 프로토콜.

IMAP4.debug¶

디버깅 출력을 제어하기 위한 정숫값. 초기화 값은 모듈 변수 Debug에서 취합니다. 3보다 큰 값은 각 명령을 추적합니다.

IMAP4.utf8_enabled¶

일반적으로 False이지만, UTF8=ACCEPT 기능에 대해 enable() 명령이 성공적으로 발행되면 True로 설정되는 불리언 값.

Added in version 3.5.

property IMAP4.file¶

기본 소켓과 연결된 내부 BufferedReader 입니다. 이 속성은 레거시 목적을 위해 문서화되어 있지만 공개 인터페이스의 일부는 아닙니다. 호출자는 이를 변경하기 전에 현재 파일을 닫아야 할 책임이 있습니다.

버전 3.15부터 사용 지원 중단(deprecated), 버전 3.19에서 제거 예정.

IMAP4 예¶

다음은 사서함을 열고 모든 메시지를 가져오고 인쇄하는 최소한의 예(에러 검사는 없습니다)입니다:

import getpass, imaplib

M = imaplib.IMAP4(host='example.org')
M.login(getpass.getuser(), getpass.getpass())
M.select()
typ, data = M.search(None, 'ALL')
for num in data[0].split():
    typ, data = M.fetch(num, '(RFC822)')
    print('Message %s\n%s\n' % (num, data[0][1]))
M.close()
M.logout()

참고

FETCH 응답에 추가 데이터나 원치 않는 데이터가 포함될 수 있으므로(RFC 3501, 섹션 7.4.2), 실제 프로덕션 코드에서는 data[0][1] 에 의존하기보다 전체 응답을 확인해야 합니다.
