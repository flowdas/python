새로운 기능들¶

PEP 657: 트레이스백에서 세밀한 오류 위치¶

트레이스백을 인쇄할 때, 인터프리터는 이제 단지 라인만 가리키는 것이 아니라 오류를 유발한 정확한 표현식까지 표시합니다. 예를 들어:

Traceback (most recent call last):
  File "distance.py", line 11, in <module>
    print(manhattan_distance(p1, p2))
          ^^^^^^^^^^^^^^^^^^^^^^^^^^
  File "distance.py", line 6, in manhattan_distance
    return abs(point_1.x - point_2.x) + abs(point_1.y - point_2.y)
                           ^^^^^^^^^
AttributeError: 'NoneType' object has no attribute 'x'

Previous versions of the interpreter would point to just the line, making it ambiguous which object was None. These enhanced errors can also be helpful when dealing with deeply nested dict objects and multiple function calls:

Traceback (most recent call last):
  File "query.py", line 37, in <module>
    magic_arithmetic('foo')
  File "query.py", line 18, in magic_arithmetic
    return add_counts(x) / 25
           ^^^^^^^^^^^^^
  File "query.py", line 24, in add_counts
    return 25 + query_user(user1) + query_user(user2)
                ^^^^^^^^^^^^^^^^^
  File "query.py", line 32, in query_user
    return 1 + query_count(db, response['a']['b']['c']['user'], retry=True)
                               ~~~~~~~~~~~~~~~~~~^^^^^
TypeError: 'NoneType' object is not subscriptable

As well as complex arithmetic expressions:

Traceback (most recent call last):
  File "calculation.py", line 54, in <module>
    result = (x / y / z) * (a / b / c)
              ~~~~~~^~~
ZeroDivisionError: division by zero

Additionally, the information used by the enhanced traceback feature is made available via a general API, that can be used to correlate bytecode instructions with source code location. This information can be retrieved using:

  • The codeobject.co_positions() method in Python.

  • The PyCode_Addr2Location() function in the C API.

See PEP 657 for more details. (Contributed by Pablo Galindo, Batuhan Taskaya and Ammar Askar in bpo-43950.)

참고

이 기능은 컴파일된 Python 파일의 인터프리터 메모리와 디스크 사용량을 약간 증가시킬 수 있는 codeobjects`에 열 위치를 저장하는 것을 필요로 합니다. 추가 정보를 저장하지 않고 추가 traceback 정보 출력을 비활성화하려면, :option:-X no_debug_ranges <-X>` 명령줄 옵션 또는 PYTHONNODEBUGRANGES 환경 변수를 사용하십시오.

PEP 654: Exception Groups 및 except*¶

PEP 654 는 프로그램이 여러 개의 관련 없는 예외를 동시에 발생시키고 처리할 수 있게 하는 언어 기능을 소개합니다. 내장 타입인 ExceptionGroup 및 BaseExceptionGroup 은 예외들을 그룹화하고 함께 발생시키는 것을 가능하게 하며, 새로운 except_* 구문은 except_ 를 예외 그룹의 하위 그룹에 일치하도록 일반화합니다.

자세한 내용은 :pep:`654`를 참조하십시오.

(Irit Katriel이 :issue:`45292`에서 기여했습니다. PEP는 Irit Katriel, Yury Selivanov 및 Guido van Rossum이 작성했습니다.)

PEP 678: 예외에 주석 추가 가능¶

add_note() 메서드가 :exc:`BaseException`에 추가되었습니다. 이 메서드는 예외가 발생할 시점에 사용 가능한 컨텍스트 정보를 포함하여 예외를 풍부하게 만드는 데 사용할 수 있습니다. 추가된 주석은 기본 추적(traceback)에 표시됩니다.

자세한 내용은 :pep:`678`을 참조하십시오.

(Irit Katriel이 :issue:`45607`에서 기여했습니다. PEP는 Zac Hatfield-Dodds가 작성했습니다.)

Windows py.exe 런처 개선 사항¶

Python 3.11에 포함된 Python Install Manager<br> 설치 관리자 사본이 크게 업데이트되었습니다. 이제 제한적인 -{<major>}.{<minor>}` 대신, PEP 514 에서 정의된 회사/태그 구문을 사용하여 -V:{<company>}/{<tag>}` 인자도 지원합니다. 이를 통해 python.org <https://www.python.org> 에 호스팅되는 PythonCore 를 제외한 배포판을 실행할 수 있습니다.

When using -V: selectors, either company or tag can be omitted, but all installs will be searched. For example, -V:OtherPython/ will select the “best” tag registered for OtherPython, while -V:3.11 or -V:/3.11 will select the “best” distribution with tag 3.11.

레거시 -<major>`나 :samp:-{<major>}.{<minor>}` ,:samp:-{<major>}-{<bitness>} 또는 -<major>.<minor>-<bitness> 인자를 사용할 때, 모든 기존 동작은 이전 버전에서 보존되어야 하며 PythonCore``의 릴리스만 선택됩니다. 하지만 이제 ``-64 접미사는 “32비트가 아님”을 의미합니다 (반드시 x86-64인 것은 아닙니다). 지원되는 64비트 플랫폼이 여러 개 있기 때문입니다. 32비트 런타임은 런타임의 태그를 확인하여 -32 접미사가 있는지 검사함으로써 감지됩니다. 3.5 버전 이후 모든 Python 릴리스에는 32비트 빌드에 이 내용이 포함되었습니다.

타입 힌트와 관련된 새로운 기능¶

본 섹션에서는 PEP 484 타입 힌트와 typing 모듈에 영향을 미치는 주요 변경 사항을 다룹니다.

PEP 646: 가변적 제네릭¶

:pep:`484`는 이전에 :data:`~typing.TypeVar`를 소개하여 단일 타입으로 매개변수화된 제네릭 생성 기능을 가능하게 했습니다. :pep:`646`은 :data:`~typing.TypeVarTuple`를 추가하여 임의 수의 타입으로 매개변수화하는 것을 활성화했습니다. 즉, :data:`~typing.TypeVarTuple`는 가변적*(variadic) 타입 변수이며, *가변적 제네릭을 가능하게 합니다.

이것은 광범위한 사용 사례를 가능하게 합니다. 특히 NumPy 및 TensorFlow와 같은 수치 계산 라이브러리에서 배열과 유사한 구조의 타입을 배열 쉐이프 로 매개변수화할 수 있게 합니다. 정적 타입 검사기는 이제 이러한 라이브러리를 사용하는 코드에서 쉐이프 관련 버그를 포착할 수 있습니다.

더 자세한 내용은 :pep:`646`을 참조하십시오.

(Matthew Rahtz가 :issue:`43224`에서 기여했고, Serhiy Storchaka와 Jelle Zijlstra가 기여했습니다. PEP는 Mark Mendoza, Matthew Rahtz, Pradeep Kumar Srinivasan 및 Vincent Siles가 작성했습니다.)

PEP 655: 개별 TypedDict 항목을 필수 또는 선택으로 표시하기¶

Required 및 :data:`~typing.NotRequired`는 :class:`~typing.TypedDict`의 개별 항목이 필수인지 여부를 표시하는 간단한 방법을 제공합니다. 이전에는 이는 상속을 통해서만 가능했습니다.

total 매개변수가 False 로 설정되지 않는 한 모든 필드는 기본적으로 필요하며, 이 경우 모든 필드는 여전히 기본적으로 선택 사항입니다. 예를 들어, 다음은 하나는 필수이고 하나는 선택적인 키를 가진 TypedDict 를 지정합니다.

class Movie(TypedDict):
   title: str
   year: NotRequired[int]

m1: Movie = {"title": "Black Panther", "year": 2018}  # OK
m2: Movie = {"title": "Star Wars"}  # OK (없어도 되는 필드입니다)
m3: Movie = {"year": 2022}  # 오류 (필수 필드 title 누락)

다음 정의는 다음과 동등합니다:

class Movie(TypedDict, total=False):
   title: Required[str]
   year: int

더 자세한 내용은 PEP 655\를 참조하십시오.

(David Foster와 Jelle Zijlstra가 bpo-47087\에서 기여했으며, PEP는 David Foster가 작성했습니다.)

PEP 673: Self 타입¶

The new Self annotation provides a simple and intuitive way to annotate methods that return an instance of their class. This behaves the same as the TypeVar-based approach specified in PEP 484, but is more concise and easier to follow.

일반적인 사용 사례에는 classmethod s 형태로 제공되는 대체 생성자 및 self 를 반환하는 __enter__() 메서드가 포함됩니다:

class MyLock:
    def __enter__(self) -> Self:
        self.lock()
        return self

    ...

class MyInt:
    @classmethod
    def fromhex(cls, s: str) -> Self:
        return cls(int(s, 16))

    ...

:data:`~typing.Self`는 또한 닫고 있는 클래스와 동일한 유형의 메서드 매개변수나 속성을 어노테이트하는 데 사용될 수 있습니다.

더 자세한 내용은 :pep:`673`을 참조하십시오.

(James Hilton-Balfe가 bpo-46534\에서 기여했으며, PEP는 Pradeep Kumar Srinivasan와 James Hilton-Balfe가 작성했습니다.)

PEP 675: 임의 리터럴 문자열 타입¶

새 LiteralString 어노테이션은 함수 매개변수가 모든 리터럴 문자열 타입일 수 있음을 나타하는 데 사용될 수 있습니다. 이를 통해 함수가 임의 리터럴 문자열 타입뿐만 아니라 다른 리터럴 문자열에서 생성된 문자열도 허용하도록 합니다. 타입 체커는 이후 SQL 구문이나 쉘 명령을 실행하는 것과 같은 민감한 함수가 정적 인자만을 사용하여 호출되도록 강제하여, 주입 공격에 대한 보호 기능을 제공할 수 있습니다.

예를 들어, SQL 쿼리 함수는 다음과 같이 어노테이션될 수 있습니다:

def run_query(sql: LiteralString) -> ...
    ...

def caller(
    arbitrary_string: str,
    query_string: LiteralString,
    table_name: LiteralString,
) -> None:
    run_query("SELECT * FROM students")       # ok
    run_query(query_string)                   # ok
    run_query("SELECT * FROM " + table_name)  # ok
    run_query(arbitrary_string)               # type checker error
    run_query(                                # type checker error
        f"SELECT * FROM students WHERE name = {arbitrary_string}"
    )

자세한 내용은 :pep:`675`를 참조하십시오.

(Jelle Zijlstra가 bpo-47088\에서 기여했으며, PEP는 Pradeep Kumar Srinivasan와 Graham Bleaney가 작성했습니다.)

PEP 681: 데이터 클래스 변환기¶

@~typing.dataclass_transform may be used to decorate a class, metaclass, or a function that is itself a decorator. The presence of @dataclass_transform() tells a static type checker that the decorated object performs runtime “magic” that transforms a class, giving it dataclass-like behaviors.

예를 들어:

# create_model 데코레이터는 라이브러리에 의해 정의됩니다.
@typing.dataclass_transform()
def create_model(cls: Type[T]) -> Type[T]:
    cls.__init__ = ...
    cls.__eq__ = ...
    cls.__ne__ = ...
    return cls

# 이제 create_model 데코레이터를 사용하여 새로운 모델 클래스를 생성할 수 있습니다:
@create_model
class CustomerModel:
    id: int
    name: str

c = CustomerModel(id=327, name="Eric Idle")

자세한 내용은 PEP 681\를 참조하십시오.

(Jelle Zijlstra가 gh-91860\에서 기여했으며, PEP는 Erik De Bonte와 Eric Traut이 작성했습니다.)

PEP 563은 미래 기능이 아닐 수 있다¶

PEP 563 <는 원래 Python 3.10에 출시될 예정이었던 어노테이션의 지연 평가(from __future__ import annotations future 문)가 무기한 보류되었습니다. 자세한 정보는 this message from the Steering Council <https://mail.python.org/archives/list/python-dev@python.org/message/VIZEBX5EYMSYIJNDBF6DMUMZOCWHARSO/> \를 참조하십시오.

이외의 언어 변경 사항¶

  • 별표 해체 표현식은 이제 for 문에서 사용할 수 있습니다. (더 자세한 내용은 bpo-46725\를 참조하십시오.)

  • 비동기 comprehensions 내의 컴프리헨션에서도 허용됩니다. 이 경우 바깥쪽 컴프리헨션은 암묵적으로 비동기화됩니다. (Serrhiy Storchaka 작성, bpo-33346.)

  • context manager 프로토콜을 지원하지 않는 객체에서는 with 구문 및 contextlib.ExitStack.enter_context() 에서, 그리고 asynchronous context manager 프로토콜을 지원하지 않는 객체에서는 async with 구문 및 contextlib.AsyncExitStack.enter_async_context() 에서 AttributeError 대신 TypeError 가 발생합니다. (Serhiy Storchaka 작성, bpo-12022 및 bpo-44471.)

  • Added object.__getstate__(), which provides the default implementation of the __getstate__() method. copying and pickleing instances of subclasses of builtin types bytearray, set, frozenset, collections.OrderedDict, collections.deque, weakref.WeakSet, and datetime.tzinfo now copies and pickles instance attributes implemented as slots. This change has an unintended side effect: It trips up a small minority of existing Python projects not expecting object.__getstate__() to exist. See the later comments on gh-70766 for discussions of what workarounds such code may need. (Contributed by Serhiy Storchaka in bpo-26579.)

  • }:option:-P 명령어 라인 옵션과 PYTHONSAFEPATH 환경 변수가 추가되어 스크립트를 실행할 때 sys.path 에 스크립트 디렉터리를 자동으로 앞에 추가하거나, -c ` 및 -m 사용할 때 현재 디렉터리를 추가하는 것이 비활성화됩니다. 이를 통해 import 가 stdlib와 설치된 모듈만 가져오도록 보장하며, 로컬(일반적으로 사용자 쓰기 가능) 디렉터리에 있는 모듈과 의도치 않게 또는 악의적으로 네임스페이스 충돌을 피할 수 있습니다. (Victor Stinner 작성, gh-57684.)

  • 포맷 명세 미니 언어 에 음수를 포맷 정밀도로 반올림한 후 양수 0으로 강제하는 "z" 옵션이 추가되었습니다. 자세한 내용은 PEP 682 를 참조하세요. (John Belmonte 작성, gh-90153.)

  • sys.path 에서 바이트(Bytes)는 더 이상 허용되지 않습니다. 이 지원은 Python 3.2와 3.6 사이에 중단되었으며, 아무도 Python 3.10.0이 출시된 후에야 알아<0xEC><0xB1><0x98>습니다. 게다가, -b `와 sys.path_importer_cache 간의 상호 작용으로 인해 str 및 bytes 키가 혼합되어 있을 때 지원을 다시 가져오는 것은 문제가 될 것입니다. (Thomas Grainger 작성, gh-91181.)

기타 CPython 구현 변경 사항¶

  • complex`에 대한 특수 메서드 :meth:`~object.__complex__`와 :class:`bytes`에 대한 :meth:`~object.__bytes__`가 해당 :class:`typing.SupportsComplex 및 typing.SupportsBytes 프로토콜을 지원하도록 구현되었습니다. (Mark Dickinson 및 Donghee Na 작성, bpo-24234.)

  • siphash13 이 새로운 내부 해싱 알고리즘으로 추가되었습니다. 이는 siphash24 와 유사한 보안 속성을 가지지만, 긴 입력에 대해서는 약간 더 빠릅니다. 이제 str, bytes, 그리고 일부 다른 타입들이 hash() 의 기본 알고리즘으로 이를 사용합니다. PEP 552 해시 기반 .pyc 파일 도 siphash13 를 사용합니다. (Inada Naoki 작성, bpo-29410.)

  • 활성 예외가 매개변수 없이 raise 문에 의해 다시 발생할 때, 이 예외에 연결된 트레이스백은 이제 항상 sys.exc_info()[1].__traceback__ 입니다. 이는 현재 except 절에서 변경된 내용이 재발생한 예외에 반영됨을 의미합니다. (Irit Katriel 작성, bpo-45711.)

  • 처리된 예외의 인터프리터 상태 표현(별칭 exc_info 또는 _PyErr_StackItem)은 이제 exc_value 필드만 가지게 되었습니다. exc_value 에서 파생될 수 있으므로, exc_type 과 exc_traceback 는 제거되었습니다. (Irit Katriel 작성, bpo-45711.)

  • 새로운 명령줄 옵션 AppendPath 이 Windows 설치 프로그램용으로 추가되었습니다. 이 옵션은 PrependPath 와 유사하게 작동하지만, 미리 추가하는 대신 설치 디렉터리 및 스크립트 디렉터리를 추가합니다. (Bastian Neuburger가 bpo-44934 에서 기여).

  • The PyConfig.module_search_paths_set field must now be set to 1 for initialization to use PyConfig.module_search_paths to initialize sys.path. Otherwise, initialization will recalculate the path and replace any values added to module_search_paths.

  • --help 옵션의 출력은 이제 50줄/80열 내에 맞습니다. Python 환경 변수 및 -X 옵션에 대한 정보는 해당 --help-env 및 --help-xoptions 플래그, 그리고 새로운 :option:`–help-all`을 사용하여 사용할 수 있습니다. (Éric Araujo가 :issue:`46142`에서 기여).

  • 배수(binary), 4, 8(octal), 16(hexadecimal) 또는 32와 같은 2진수를 제외한 다른 기반에서 int`과 :class:`str 간의 변환은 이제 문자열 형태의 자릿수가 알고리즘적 복잡성으로 인한 잠재적인 서비스 거부 공격을 방지하기 위한 제한을 초과할 경우 ValueError`를 발생시킵니다. 이것은 :cve:`2020-10735`에 대한 완화 조치입니다. 이 한계는 환경 변수, 명령줄 플래그 또는 :mod:`sys API로 구성하거나 비활성화할 수 있습니다. 자세한 내용은 정수 문자열 변환 길이 제한 문서를 참조하십시오. 기본 제한은 문자열 형태의 4300 자릿수입니다.

개선된 모듈들¶

asyncio¶

  • TaskGroup 클래스가 추가되었습니다. 이 클래스는 작업의 그룹을 담으며, 종료 시 모든 작업을 기다립니다(비동기 컨텍스트 관리자). 새로운 코드에서는 :func:`~asyncio.create_task`와 :func:`~asyncio.gather`를 직접 사용하는 것보다 이것을 권장합니다. (Yury Selivanov 및 다른 사람들이 :gh:`90908`에서 기여).

  • 비동기 작업을 위한 시간 초과 설정용 비동기 컨텍스트 관리자인 :func:`~asyncio.timeout`가 추가되었습니다. 새로운 코드에서는 :func:`~asyncio.wait_for`를 직접 사용하는 것보다 이것을 권장합니다. (Andrew Svetlov가 :gh:`90927`에서 기여).

  • Runner() 클래스가 추가되었습니다. (Andrew Svetlov가 :gh:`91218`에서 기여).

  • 비동기 라이브러리의 동기화 원시 타입에 Barrier 클래스가 추가되었고, 관련 예외인 :exc:`~asyncio.BrokenBarrierError`도 함께 추가되었습니다. (Yves Duprat 및 Andrew Svetlov가 :gh:`87518`에서 기여).

  • 다중 연결 오류가 ExceptionGroup 으로 발생할 수 있도록 asyncio.loop.create_connection() 에 키워드 인자인 all_errors 를 추가했습니다.

  • 기존 스트림 기반 연결을 TLS로 업그레이드하기 위한 asyncio.StreamWriter.start_tls() 메서드가 추가되었습니다. (Ian Good가 :issue:`34975`에서 기여).

  • 이벤트 루프에 원시 데이터그램 소켓 함수들(sock_sendto(), sock_recvfrom() 및 sock_recvfrom_into())가 추가되었습니다. 이들은 :class:`~asyncio.SelectorEventLoop`와 :class:`~asyncio.ProactorEventLoop`에 구현되어 있습니다. (Alex Grönholm가 :issue:`46805`에서 기여).

  • uncancel 메서드가 추가되었습니다. 이들은 주로 내부 사용을 위해, 특히 :class:`~asyncio.TaskGroup`에 의해 사용됩니다.

enum 관련 요소¶

  • EnumMeta`가 :class:`~enum.EnumType`으로 이름이 변경되었습니다 (참조용 별칭으로 :class:!EnumMeta` 유지).

  • 멤버를 사용하며 반드시 문자열이어야 하는 멤버를 갖는 :class:`~enum.StrEnum`을 추가했습니다.

  • __str__ 및 __format__`에 대한 리터럴 값(이름이 아닌)을 반환합니다 (이는 :func:`str(), format() 및 f-string\s에서 사용됩니다).

  • Enum.__format__() (기본값으로, format(), str.format(), 및 f-string\s에서 사용됨)이 이제 항상 Enum.__str__() <enum.Enum.__str__>`와 동일한 결과를 반환하도록 변경되었습니다: :class:`~enum.ReprEnum()\을 상속받는 열거형의 경우 멤버의 값이 되고, 다른 모든 열거형의 경우 열거형과 멤버 이름(예: Color.RED)이 됩니다.

  • 범위 밖에 있는 플래그 값을 처리하는 방법을 제어하기 위해 Flag 열거형에 새로운 경계 클래스 매개변수와 해당 옵션을 가진 FlagBoundary 열거형이 추가되었습니다.

  • 여러 특정 제약 조건과 비교하여 열거형 클래스를 확인할 수 있도록, verify() 열거형 데코레이터와 해당 옵션을 갖는 EnumCheck 열거형이 추가되었습니다.

  • 장식된 객체가 열거형 멤버로 변환되거나 변환되지 않도록 보장하는 member() 및 nonmember() 데코레이터가 추가되었습니다.

  • @property`와 비슷하게 작동하지만 열거형에 대해서는 예외를 두는 :deco:`~enum.property 데코레이터가 추가되었습니다. 이 대신 types.DynamicClassAttribute()\을 사용하십시오.

  • global_enum() 열거형 데코레이터가 추가되어, __repr__() 및 __str__() 를 열거형 클래스 멤버가 아닌 모듈의 멤버로 값을 표시하도록 조정합니다. 예를 들어, re.RegexFlag \의 ASCII 멤버에 대해 're.ASCII' 가 반환되며 'RegexFlag.ASCII' 가 반환되지 않습니다.

  • Flag`를 강화하여 :func:`len, 순회, 그리고 멤버에 대한 in/not in`을 지원하도록 했습니다. 예를 들어, 다음 코드가 이제 작동합니다: ``len(AFlag(3)) == 2 and list(AFlag(3)) == (AFlag.ONE, AFlag.TWO)`

  • 멤버가 Enum() 및 :class:`~enum.Flag`를 변경했습니다. 따라서 :func:`dir`은 이제 혼합된 데이터 형식의 메서드 등을 포함합니다.

  • Flag`가 기본값(2의 거듭제곱)만 정규식으로 고려하고 복합 값(``3`, 6, 10 등)은 별칭으로 간주하도록 변경되었으며, 반전 플래그는 양수로 강제 변환됩니다.

functools¶

  • @functools.singledispatch`는 이제 디스패치 인수로 :class:`types.UnionType 및 :class:`typing.Union`을 어노테이션으로 지원합니다:

    >>> from functools import singledispatch
>>> @singledispatch
... def fun(arg, verbose=False):
...     if verbose:
...         print("Let me just say,", end=" ")
...     print(arg)
...
>>> @fun.register
... def _(arg: int | float, verbose=False):
...     if verbose:
...         print("Strength in numbers, eh?", end=" ")
...     print(arg)
...
>>> from typing import Union
>>> @fun.register
... def _(arg: Union[list, set], verbose=False):
...     if verbose:
...         print("Enumerate this:")
...     for i, elem in enumerate(arg):
...         print(i, elem)
...

    (Yurii Karabas가 bpo-46014\를 통해 기여하였습니다.)

gzip 모듈¶

  • gzip.compress() 함수에 mtime=0 인수를 사용할 때 더 빨라졌으며, 이는 압축을 전체적으로 단일 zlib.compress() 작업으로 위임하기 때문입니다. 이 변경 사항에는 한 가지 부작용이 있습니다: gzip 파일 헤더는 헤더 내에 “OS” 바이트를 포함합니다. 이전에는 전통적으로 gzip 모듈에서 이를 “알 수 없음”을 나타내는 값 255로 설정했습니다. 이제 mtime=0 으로 compress() 를 사용하면, Python이 연결된 기반 zlib C 라이브러리에 의해 다른 값으로 설정될 수 있습니다. (부작용에 대한 자세한 내용은 gh-112346 을 참조하세요.)

더 빠른 CPython¶

CPython 3.11은 Ubuntu Linux에서 GCC로 컴파일된 경우, pyperformance 벤치마크 스위트에서 측정했을 때 CPython 3.10보다 평균적으로 25% 더 빠릅니다. 워크로드에 따라 전반적인 속도 향상은 10~60%까지 가능합니다.

이 프로젝트는 파이썬의 두 가지 주요 영역, 즉 빠른 시작 및 :ref:`whatsnew311-faster-runtime`<br>에 초점을 맞추고 있습니다. 이 프로젝트에서 다루지 않은 최적화 사항은 별도로 :ref:`whatsnew311-optimizations`<br> 아래에 나열되어 있습니다.

빠른 시작¶

프리징된 임포트 / 정적 코드 객체¶

Python caches bytecode in the __pycache__ directory to speed up module loading.

이전에는 3.10에서 파이썬 모듈 실행이 다음과 같았습니다:

Read __pycache__ -> Unmarshal -> Heap allocated code object -> Evaluate

Python 3.11에서는 파이썬 시작에 필수적인 핵심 모듈들이 “프리징(frozen)”되었습니다. 이는 해당 모듈들의 코드 객체 (및 바이트코드)가 인터프리터에 의해 정적으로 할당됨을 의미합니다. 이에 따라 모듈 실행 과정의 단계는 다음과 같이 감소했습니다:

Statically allocated code object -> Evaluate

인터프리터 시작 속도가 Python 3.11에서 10-15% 향상되었습니다. 이는 파이썬을 사용하는 짧게 실행되는 프로그램에 큰 영향을 미칩니다.

(Contributed by Eric Snow, Guido van Rossum and Kumar Aditya in many issues.)

런타임 속도 향상¶

저렴하고, 느긋한 파이썬 프레임¶

실행 정보를 담고 있는 파이썬 프레임은 파이썬이 파이썬 함수를 호출할 때마다 생성됩니다. 다음은 새로운 프레임 최적화 기능들입니다:

  • 프레임 생성 과정이 간소화되었습니다.

  • C 스택에서 프레임 공간을 아낌없이 재사용하여 메모리 할당을 피했습니다.

  • 내부 프레임 구조를 필수 정보만 포함하도록 간소화했습니다. 이전에 프레임은 추가적인 디버깅 및 메모리 관리 정보를 가지고 있었습니다.

구 방식의 프레임 객체 <frame-objects>`는 이제 디버거나 :func:`sys._getframe 및 :func:`inspect.currentframe`과 같은 파이썬 인트로스펙션 함수에서 요청할 때만 생성됩니다. 대부분의 사용자 코드에서는 프레임 객체가 전혀 생성되지 않습니다. 결과적으로, 거의 모든 파이썬 함수 호출 속도가 크게 향상되었습니다. pyperformance 테스트에서 3-7%의 속도 향상을 측정했습니다.

(Contributed by Mark Shannon in bpo-44590.)

파이썬 함수 호출 내장¶

파이썬 함수 호출 중, 파이썬은 해당 함수의 코드를 해석하기 위해 평가하는 C 함수를 호출합니다. 이는 순수 파이썬 재귀가 C 스택에서 안전한 범위로 효과적으로 제한됩니다.

3.11에서 CPython이 파이썬 코드가 다른 파이썬 함수를 호출하는 것을 감지하면, 새로운 프레임을 설정하고 “점프”하여 새 프레임 내부의 코드를 실행합니다. 이로써 C 해석기 함수 호출 자체를 회피할 수 있습니다.

대부분의 파이썬 함수 호출은 이제 C 스택 공간을 소비하지 않아 속도가 빨라졌습니다. 피보나치(fibonacci)나 팩토리얼(factorial) 같은 간단한 재귀 함수에서, 저희는 1.7배의 속도 향상을 확인했습니다. 이는 또한 재귀 함수가 훨씬 더 깊게 재귀할 수 있음을 의미합니다 (사용자가 :func:`sys.setrecursionlimit`을 통해 재귀 제한을 늘릴 경우). 저희는 pyperformance에서 1-3%의 개선을 측정했습니다.

(Pablo Galindo 및 Mark Shannon이 bpo-45256\를 통해 기능을 구현하였습니다.)

PEP 659: 적응형 인터프리터 특화¶

PEP 659 는 Faster CPython 프로젝트의 핵심 부분 중 하나입니다. 일반적인 아이디어는 파이썬이 동적 언어이지만, 대부분의 코드에는 객체와 타입이 거의 변경되지 않는 영역이 있다는 것입니다. 이 개념은 타입 안정성 으로 알려져 있습니다.

실행 시점에 파이썬은 일반적인 패턴과 실행 중인 코드의 타입 안정성을 찾으려고 시도할 것입니다. 그런 다음 현재 연산을 보다 특화된 연산으로 대체합니다. 이 특화된 연산은 오직 해당 사용 사례/타입에만 사용 가능한 빠른 경로를 이용하며, 일반적으로 범용 대응물보다 성능이 우수합니다. 이는 또한 인라인 캐싱 이라는 또 다른 개념을 가져오는데, 파이썬이 비용이 많이 드는 연산 결과를 바이트코드 내부에 직접 캐시하는 것입니다.

특화기(specializer)는 또한 특정 공통 명령어 쌍을 하나의 슈퍼 명령어와 결합하여 실행 중 오버헤드를 줄일 것입니다.

파이썬은 “핫”한(여러 번 실행되는) 코드를 볼 때만 특화됩니다. 이는 파이썬이 한 번 실행되는 코드로 시간을 낭비하는 것을 방지합니다. 또한 코드가 너무 동적이거나 사용 방식이 변경될 경우 디특화(de-specialize)할 수도 있습니다. 특화는 주기적으로 시도되며, 특화 시도는 비용이 너무 크지 않아 새로운 상황에 적응하도록 허용합니다.

(PEP를 Mark Shannon가 작성했고, Stefan Brunthaler의 아이디어에서 영감을 받았습니다. 자세한 내용은 :pep:`659`를 참조하십시오. 구현은 Mark Shannon과 Brandt Bucher가 했고, Irit Katriel 및 Dennis Sweeney의 추가적인 도움이 있었습니다.)

기타¶

  • 오브젝트는 이제 게으르게 생성되는 객체 네임스페이스 덕분에 메모리 사용량이 감소했습니다. 따라서 그 네임스페이스 딕셔너리 또한 키를 더욱 자유롭게 공유할 수 있게 됩니다. (Mark Shannon 기여, bpo-45340 및 bpo-40116).

  • 예외 처리에 “제로 비용”이 구현되어, 예외가 발생하지 않을 때 try 구문에 드는 비용이 제거되었습니다. (Mark Shannon 기여, bpo-40222).

  • 인터프리터에서 예외를 처리하는 방식이 더 간결해져서, 예외를 가로채는 데 필요한 시간이 약 10% 감소했습니다. (Irit Katriel 기여, bpo-45711).

  • re`의 정규 표현식 매칭 엔진이 부분적으로 리팩토링되었으며, 이제 지원되는 플랫폼에서 계산된 gotos("스레드 코드")를 사용합니다. 그 결과, Python 3.11은 `pyperformance regular expression benchmarks <https://pyperformance.readthedocs.io/benchmarks.html#regex-dna>`_를 실행할 때 Python 3.10보다 최대 10% 더 빠르게 작동합니다. (Brandt Bucher 기여, :gh:`91404).

자주 묻는 질문¶

이러한 속도 향상을 활용하려면 어떻게 코드를 작성해야 하나요?¶

공통된 모범 사례를 따르는 Pythonic 코드를 작성하면 됩니다. 코드를 반드시 변경할 필요는 없습니다. Faster CPython 프로젝트는 우리가 관찰하는 일반적인 코드 패턴에 대해 최적화 작업을 진행합니다.

CPython 3.11이 더 많은 메모리를 사용할까요?¶

그렇지는 않을 것입니다. 3.10보다 20% 이상 증가할 것으로 예상하지 않습니다. 이는 위에 언급한 프레임 객체 및 객체 딕셔너리 메모리 최적화로 상쇄됩니다.

제 작업 부하에서는 속도 향상을 확인할 수 없습니다. 왜 그런가요?¶

특정 코드는 눈에 띄는 이점을 갖지 못할 수 있습니다. 코드의 대부분이 I/O 작업에 사용되거나, 이미 NumPy와 같은 C 확장 라이브러리에서 대부분의 계산을 수행하는 경우에는 상당한 속도 향상이 없을 것입니다. 본 프로젝트는 현재 순수 Python 워크로드에 가장 많은 이점을 제공합니다.

게다가, pyperformance 수치는 기하 평균입니다. pyperformance 벤치마크 내에서도 일부 벤치마크는 약간 속도가 느려진 반면, 다른 벤치마크는 거의 2배 빨라졌습니다!

JIT 컴파일러가 있습니까?¶

아니요. 다른 최적화 방안을 계속 탐구하고 있습니다.

정보¶

Faster CPython은 :term:`CPython`에 대한 최적화 기능을 탐구합니다. 메인 팀은 마이크로소프트의 지원을 받아 전념하여 작업하고 있습니다. Pablo Galindo Salgado는 또한 블룸버그 LP로부터 프로젝트에 파트타임으로 지원을 받고 있습니다. 마지막으로, 많은 기여자들은 커뮤니티 자원봉사자들입니다.

CPython 바이트 코드 변경 사항¶

바이트 코드는 이제 인라인 캐시 항목을 포함하게 되었으며, 이는 새로 추가된 CACHE 명령어의 형태를 <0xEB><0x9D><0xB1>니다. 많은 옵코드가 정확한 수량의 캐시가 뒤따라야 하며, 인터프리터에게 런타임에 이를 건너뛰도록 지시합니다. 채워진 캐시는 임의의 명령처럼 보일 수 있으므로, 빠진 데이터가 포함된 원시적이고 적응형 바이트 코드를 읽거나 수정할 때는 큰 주의를 기울여야 합니다.

새 옵코드¶

  • ASYNC_GEN_WRAP, RETURN_GENERATOR 및 :opcode:`SEND`는 제너레이터와 코루틴에서 사용됩니다.

  • 클로저에 특수한 호출자 측 코드가 필요하지 않은 COPY_FREE_VARS.

  • 중단 처리가 바람직하지 않은 특정 루프에서 사용되는 JUMP_BACKWARD_NO_INTERRUPT.

  • :opcode:`MAKE_CELL`을 사용하여 :ref:`셀 객체 <cell-objects>``를 생성합니다.

  • 파이썬 버전 3.11에 추가된 PEP 654 의 새 예외 그룹 및 except* 를 처리하기 위해 CHECK_EG_MATCH 와 PREP_RERAISE_STAR.

  • 예외 핸들러에서 사용되는 PUSH_EXC_INFO.

  • 내부 추적, 디버깅 및 최적화 확인을 위한 무작위 명령(no-op)인 RESUME.

변경/제거된 옵코드¶

  • MATCH_CLASS 와 MATCH_KEYS 가 성공/실패 여부를 나타내는 추가 부울 값(boolean)을 더 이상 푸시하지 않도록 변경되었습니다. 대신, 추출된 값의 튜플 대신 실패 시 None 이 푸시됩니다.

  • 예외 처리와 함께 작동하는 옵코드들이 이제 세 개가 아닌 스택상의 하나의 항목으로 표현되도록 변경되었습니다(참고: gh-89874).

  • classmethod 설명자를 체인으로 연결하는 것은 이제 사용 지원이 중단되었습니다(bpo-19072 로 도입됨). property 와 같은 다른 설명자들을 감싸기(wrap) 위해 더 이상 사용할 수 없습니다. 이 기능의 핵심 설계에는 결함이 있었고, 여러 하위 문제를 일으켰습니다. classmethod 를 전달(pass-through)하려면, Python 3.10에서 추가된 __wrapped__ 어트리뷰트를 고려하십시오. (Raymond Hettinger가 gh-89519 로 기여하였습니다.)

  • 문자열 및 바이트 리터럴 내의 8진수 이스케이프는 값이 0o377 (십진수로 255)보다 큰 경우 이제 DeprecationWarning 을 생성합니다. 향후 Python 버전에서는 SyntaxWarning 을 발생시키고 결국에는 SyntaxError 를 발생시킬 것입니다. (Serhiy Storchaka가 gh-81548 로 기여하였습니다.)

제거됨¶

이 섹션은 파이썬 3.11에서 제거된 API를 나열합니다.

제거된 C API는 :ref:`separate <whatsnew311-c-api-removed>`에 별도로 나열되어 있습니다.

  • Removed the @asyncio.coroutine() decorator enabling legacy generator-based coroutines to be compatible with async / await code. The function has been deprecated since Python 3.8 and the removal was initially scheduled for Python 3.10. Use async def instead. (Contributed by Illia Volochii in bpo-43216.)

  • 디버그 모드에서 레거시 제너레이터 기반 코루틴 객체를 래핑하는 데 사용된 asyncio.coroutines.CoroWrapper`를 제거했습니다. (Illia Volochii가 :issue:`43216\를 통해 기능을 구현하였습니다.)

  • 심각한 보안 문제로 인해, Python 3.9에서 비활성화된 asyncio.loop.create_datagram_endpoint()\의 reuse_address 매개 변수는 이제 완전히 제거되었습니다. 이는 UDP에서 소켓 옵션 SO_REUSEADDR\의 동작 때문입니다. (Contributed by Hugo van Kemenade in bpo-45129.)

  • Python 3.9에서 사용이 중단된 binhex 모듈을 제거했습니다. 또한 관련하여 유사하게 사용이 중단된 binascii 함수들도 제거했습니다:

    • binascii.a2b_hqx()

    • binascii.b2a_hqx()

    • binascii.rlecode_hqx()

    • binascii.rldecode_hqx()

    binascii.crc_hqx() 함수는 계속 사용할 수 있습니다.

    (Contributed by Victor Stinner in bpo-45085.)

  • Python 3.9에서 사용이 중단된 distutils bdist_msi 명령을 제거했습니다. 대신 bdist_wheel\(휠 패키지)을 사용하십시오. (Contributed by Hugo van Kemenade in bpo-45124.)

  • Python 3.9부터 사용이 중단된 xml.dom.pulldom.DOMEventStream, wsgiref.util.FileWrapper 및 fileinput.FileInput`의 :meth:`~object.__getitem__ 메서드를 제거했습니다. (Contributed by Hugo van Kemenade in bpo-45132.)

  • Removed the deprecated gettext functions lgettext(), ldgettext(), lngettext() and ldngettext(). Also removed the bind_textdomain_codeset() function, the NullTranslations.output_charset() and NullTranslations.set_output_charset() methods, and the codeset parameter of translation() and install(), since they are only used for the l*gettext() functions. (Contributed by Donghee Na and Serhiy Storchaka in bpo-44235.)

  • inspect 모듈에서 다음이 제거되었습니다:

    • 사용이 중단된 getargspec() 함수를 사용했습니다. Python 3.0부터 사용이 중지되었으므로 대신 inspect.signature() 또는 :func:`inspect.getfullargspec`을 사용하십시오.

    • 사용이 중단된 formatargspec() 함수를 사용했습니다. Python 3.5부터 사용이 중지되었으므로 대신 inspect.signature() 함수나 inspect.Signature 객체를 직접 사용하십시오.

    • 사용이 중단된 Signature.from_builtin() 및 Signature.from_function() 메서드를 사용했습니다. Python 3.5부터 사용이 중지되었으므로 대신 Signature.from_callable() 메서드를 사용하십시오.

    (Contributed by Hugo van Kemenade in bpo-45320.)

  • pathlib.PurePath`에서 :meth:`~object.__class_getitem__ 메서드가 제거되었습니다. 이전 버전에서 실수로 추가되었으며 사용되지 않았기 때문입니다. (Contributed by Nikita Sobolev in bpo-46483.)

  • 외부 mailman 패키지 없이는 사용할 수 없는 MailmanProxy 클래스를 smtpd 모듈에서 제거했습니다. (Contributed by Donghee Na in bpo-35800.)

  • _tkinter.TkappType`의 사용이 중단된 :meth:!split` 메서드를 제거했습니다. (Contributed by Erlend E. Aasland in bpo-38371.)

  • unittest 검색 기능에서 네임스페이스 패키지 지원을 제거했습니다. 이 기능은 Python 3.4에 도입되었으나 Python 3.7부터 동작하지 않습니다. (Contributed by Inada Naoki in bpo-23882.)

Python 3.11로 이식하기¶

이 섹션은 파이썬 API의 변경 사항 및 기타 버그 수정 사항을 나열하며, 사용자의 파이썬 코드에 대한 수정이 필요할 수 있습니다.

C API 포팅 노트는 별도로 목록화되었습니다 _

  • open(), io.open(), codecs.open() 및 fileinput.FileInput`은 더 이상 파일 모드에서 `’U’`` (“universal newline”)를 허용하지 않습니다. Python 3에서는 텍스트 모드로 파일을 열 때 “universal newline” 모드가 기본으로 사용되며, 'U' 플래그는 Python 3.3부터 폐지되었습니다. 이 함수들에서 universal newlines 작동 방식을 제어하는 것은 newline parameter <open-newline-parameter>`입니다. (Contributed by Victor Stinner in :issue:`37330.)

  • ast.AST 노드의 위치는 이제 compile() 및 기타 관련 함수에 제공될 때 검증됩니다. 유효하지 않은 위치가 감지되면 ValueError`가 발생합니다. (Contributed by Pablo Galindo in :gh:`93351)

  • Python 3.8에서 폐지된 로직을 따른 비- concurrent.futures.ThreadPoolExecutor 실행기를 asyncio.loop.set_default_executor`에 전달하는 것은 금지됩니다. (Contributed by Illia Volochii in :issue:`43234().)

  • calendar: calendar.LocaleTextCalendar 및 calendar.LocaleHTMLCalendar 클래스는 더 이상 지역을 지정하지 않은 경우 locale.getdefaultlocale() 대신 locale.getlocale`를 사용합니다. (Contributed by Victor Stinner in :issue:`46659().)

  • pdb 모듈은 이제 'UTF-8' 인코딩을 가진 .pdbrc 설정 파일을 읽습니다. (Contributed by Srinivas Reddy Thatiparthy (శ్రీనివాస్ రెడ్డి తాటిపర్తి) in bpo-41137.)

  • random.sample`의 *population* 매개변수는 시퀀스여야 하며, :class:`set()s에서 lists로의 자동 변환은 더 이상 지원되지 않습니다. 또한, 샘플 크기가 모집단 크기보다 클 경우 ValueError`가 발생합니다. (Contributed by Raymond Hettinger in :issue:`40465.)

  • :func:`random.shuffle`의 random 선택적 매개변수는 제거되었습니다. 이전에는 셔플에 사용할 임의의 무작위 함수였으나, 이제는 :func:`random.random`(이전 기본값)이 항상 사용됩니다.

  • re`의 :ref:`re-syntax`에서 전역 인라인 플래그(예.: ``(?i)`)는 이제 정규 표현식 시작 부분에서만 사용할 수 있습니다. 다른 곳에서 사용되는 것은 Python 3.6부터 폐지되었습니다. (Contributed by Serhiy Storchaka in bpo-47066.)

Python 3.11로 이식하기¶

  • 일부 매크로는 정적 인라인 함수로 변환되어 macro pitfalls <https://gcc.gnu.org/onlinedocs/cpp/Macro-Pitfalls.html>\를 피하도록 했습니다. 이 변경 사항은 사용자에게 대부분 투명해야 합니다. 왜냐하면 대체 함수가 정적 타입 검사로 인한 컴파일러 경고를 방지하기 위해 인자를 예상된 형식으로 캐스팅할 것이기 때문입니다. 하지만, 제한된 C API가 >=3.11로 설정된 경우에는 이러한 캐스팅을 수행하지 않으며, 호출자는 인자를 예상되는 형식으로 캐스팅해야 합니다. 자세한 내용은 PEP 670\을 참조하십시오. (Victor Stinner와 Erlend E. Aasland가 gh-89653\에 기여하였습니다.)

  • PyErr_SetExcInfo() 는 더 이상 type 및 traceback 인자를 사용하지 않습니다. 해석기는 이제 예외 인스턴스(value 인자)로부터 해당 값들을 파생합니다. 이 함수는 여전히 세 인자의 참조를 가져갑니다. (Irit Katriel이 bpo-45711 \에 기여하였습니다.)

  • PyErr_GetExcInfo() 는 이제 결과의 type 및 traceback 필드를 예외 인스턴스(value 필드)로부터 파생합니다. (Irit Katriel이 bpo-45711 \에 기여하였습니다.)

  • _frozen 에는 플래그된 모듈이 패키국인지 여부를 나타내는 새로운 is_package 필드가 있습니다. 이전에는 size 필드의 음수 값이 해당 표시자였습니다. 이제 size 에 대해 음이 아닌 값만 사용되어야 합니다. (Kumar Aditya가 bpo-46608 \에 기여하였습니다.)

  • _PyFrameEvalFunction() 은 이제 두 번째 파라미터로 PyFrameObject* 대신 _PyInterpreterFrame* 를 받습니다. 이 함수 포인터 형식을 사용하는 방법에 대한 자세한 내용은 PEP 523 \을 참조하십시오.

  • PyCode_New`와 :c:func:()!PyCode_NewWithPosOnlyArgs`는 이제 추가적인 exception_table 인자를 받습니다. 이 함수들을 사용하는 것은 가능한 한 피해야 합니다. 사용자 지정 코드 객체를 얻으려면, 컴파일러를 사용하여 코드 객체를 생성한 다음, replace 메서드를 사용하여 수정된 버전을 가져오십시오.

  • 이전 trashcan 매크로(Py_TRASHCAN_SAFE_BEGIN/Py_TRASHCAN_SAFE_END)는 이제 더 이상 사용되지 않습니다. 대신 새로운 매크로 Py_TRASHCAN_BEGIN 및 Py_TRASHCAN_END 를 사용하여 대체해야 합니다.

    이전 매크로가 포함된 tp_dealloc 함수는 다음과 같습니다:

    static void
mytype_dealloc(mytype *p)
{
    PyObject_GC_UnTrack(p);
    Py_TRASHCAN_SAFE_BEGIN(p);
    ...
    Py_TRASHCAN_SAFE_END
}

    새 매크로를 다음과 같이 마이그레이션해야 합니다:

    static void
mytype_dealloc(mytype *p)
{
    PyObject_GC_UnTrack(p);
    Py_TRASHCAN_BEGIN(p, mytype_dealloc)
    ...
    Py_TRASHCAN_END
}

    Py_TRASHCAN_BEGIN 은 두 번째 인자로 해당 해제 함수 자체를 가져야 한다는 점에 유의하십시오.

    #if PY_VERSION_HEX >= 0x03080000
#  define CPy_TRASHCAN_BEGIN(op, dealloc) Py_TRASHCAN_BEGIN(op, dealloc)
#  define CPy_TRASHCAN_END(op) Py_TRASHCAN_END
#else
#  define CPy_TRASHCAN_BEGIN(op, dealloc) Py_TRASHCAN_SAFE_BEGIN(op)
#  define CPy_TRASHCAN_END(op) Py_TRASHCAN_SAFE_END(op)
#endif

    문서에는 PyFrameObject 필드가 언제든지 변경될 수 있다고 명시되어 있지만, 이 필드들은 오랫동안 안정적이었고 여러 인기 확장 모듈에서 사용되었습니다.

    Python 3.11에서는 성능 최적화를 위해 프레임 구조체(frame struct)가 재구성되었습니다. 일부 필드는 이전 구현의 세부 사항이었기 때문에 완전히 제거되었습니다.

    PyFrameObject 필드들:

    • f_back: :c:func:`PyFrame_GetBack`를 사용하십시오.

    • f_blockstack: 제거되었습니다.

    • f_builtins: :c:func:`PyFrame_GetBuiltins`를 사용하십시오.

    • f_code: :c:func:`PyFrame_GetCode`를 사용하십시오.

    • f_gen: :c:func:`PyFrame_GetGenerator`를 사용하십시오.

    • f_globals: :c:func:`PyFrame_GetGlobals`를 사용하십시오.

    • f_iblock: 제거되었습니다.

    • f_lasti: PyFrame_GetLasti() 를 사용하십시오. f_lasti 를 사용하는 코드는 PyCode_Addr2Line() 대신 PyFrame_GetLineNumber() 를 사용해야 합니다. 이 방법이 더 빠를 수 있습니다.

    • f_lineno: :c:func:`PyFrame_GetLineNumber`를 사용하십시오.

    • f_locals: :c:func:`PyFrame_GetLocals`를 사용하십시오.

    • f_stackdepth: 제거되었습니다.

    • f_state: 공개 API가 없습니다 (f_frame.f_state 로 이름이 변경됨).

    • f_trace: 공개 API가 없습니다.

    • f_trace_lines: PyObject_GetAttrString((PyObject_*)frame, "f_trace_lines") 를 사용하십시오.

    • f_trace_opcodes: PyObject_GetAttrString((PyObject_*)frame, "f_trace_opcodes") 를 사용하십시오.

    • f_localsplus: 공개 API가 없습니다 (f_frame.localsplus 로 이름이 변경됨).

    • f_valuestack: 제거되었습니다.

    Python 프레임 객체는 이제 지연(lazily)으로 생성됩니다. 부작용으로는, f_back 멤버를 직접 접근해서는 안 됩니다. 이 값 역시 지연 계산되기 때문입니다. 대신 PyFrame_GetBack() 함수를 호출해야 합니다.

    사실, 그들은 더 이상 :c:func:!PyFrame_FastToLocalsWithError`나 :c:func:`!PyFrame_LocalsToFast`를 호출할 필요가 없으며, 실제로도 그렇게 해서는 안 됩니다. 프레임의 필요한 업데이트는 이제 가상 머신에서 관리합니다.

    Python 3.8 및 이전 버전에서 PyFrame_GetCode() 를 정의하는 코드:

    #if PY_VERSION_HEX < 0x030900B1
static inline PyCodeObject* PyFrame_GetCode(PyFrameObject *frame)
{
    Py_INCREF(frame->f_code);
    return frame->f_code;
}
#endif

    Python 3.8 및 이전 버전에서 PyFrame_GetBack() 을 정의하는 코드:

    #if PY_VERSION_HEX < 0x030900B1
static inline PyFrameObject* PyFrame_GetBack(PyFrameObject *frame)
{
    Py_XINCREF(frame->f_back);
    return frame->f_back;
}
#endif

    또는 pythoncapi_compat project\를 사용하여 이 두 함수를 이전 버전의 파이썬에서 가져올 수 있습니다.

  • PyThreadState 구조체의 멤버 변경 사항:

    • frame: removed, use PyThreadState_GetFrame() (function added to Python 3.9 by bpo-40429). Warning: the function returns a strong reference, need to call Py_XDECREF().

    • tracing\: 변경되었으므로, 대신 PyThreadState_EnterTracing() 및 :c:func:`PyThreadState_LeaveTracing`을 사용하십시오 (이 함수들은 Python 3.11에서 :issue:`43760`에 의해 추가되었습니다).

    • recursion_depth \: 제거되었으며, 대신 (tstate->recursion_limit - tstate->recursion_remaining) 을 사용하십시오.

    • stackcheck_counter\: 제거되었습니다.

    Python 3.8 및 이전 버전에서 PyThreadState_GetFrame() 을 정의하는 코드:

    #if PY_VERSION_HEX < 0x030900B1
static inline PyFrameObject* PyThreadState_GetFrame(PyThreadState *tstate)
{
    Py_XINCREF(tstate->frame);
    return tstate->frame;
}
#endif

    Python 3.10 및 이전 버전에서 PyThreadState_EnterTracing() 및 PyThreadState_LeaveTracing() 을 정의하는 코드:

    #if PY_VERSION_HEX < 0x030B00A2
static inline void PyThreadState_EnterTracing(PyThreadState *tstate)
{
    tstate->tracing++;
#if PY_VERSION_HEX >= 0x030A00A1
    tstate->cframe->use_tracing = 0;
#else
    tstate->use_tracing = 0;
#endif
}

static inline void PyThreadState_LeaveTracing(PyThreadState *tstate)
{
    int use_tracing = (tstate->c_tracefunc != NULL || tstate->c_profilefunc != NULL);
    tstate->tracing--;
#if PY_VERSION_HEX >= 0x030A00A1
    tstate->cframe->use_tracing = use_tracing;
#else
    tstate->use_tracing = use_tracing;
#endif
}
#endif

    또는 the pythoncapi-compat project\를 사용하여 이전 버전의 함수에서 이 함수들을 가져오십시오.

  • 배포 담당자는 최적화된 Blake2 라이브러리 libb2 _}\로 파이썬을 빌드하는 것이 권장됩니다.

  • The PyConfig.module_search_paths_set field must now be set to 1 for initialization to use PyConfig.module_search_paths to initialize sys.path. Otherwise, initialization will recalculate the path and replace any values added to module_search_paths.

  • :c:func:`PyConfig_Read`는 더 이상 초기 검색 경로를 계산하지 않으며, :c:member:`PyConfig.module_search_paths`에 어떤 값도 채우지 않습니다. 기본 경로를 계산한 다음 수동으로 수정하려면, 초기화를 완료하고 :c:func:`PySys_GetObject`을 사용하여 :data:`sys.path`를 Python 리스트 객체로 검색하여 직접 수정하십시오.

제거됨¶

  • PyFrame_BlockSetup() 및 PyFrame_BlockPop`은 제거되었습니다. (Mark Shannon가 :issue:`40222()\를 통해 기능을 구현하였습니다.)

  • 다음 errno 변수를 사용하여 수학 매크로를 제거합니다:

    • Py_ADJUST_ERANGE1()

    • Py_ADJUST_ERANGE2()

    • Py_OVERFLOWED()

    • Py_SET_ERANGE_IF_OVERFLOW()

    • Py_SET_ERRNO_ON_MATH_ERROR()

    (Victor Stinner가 bpo-45412\를 통해 기능을 구현하였습니다.)

  • Python 3.3부터 폐지된 Py_UNICODE_COPY() 및 Py_UNICODE_FILL() 매크로를 제거하고, 대신 PyUnicode_CopyCharacters() 또는 memcpy() (wchar_t* 문자열), 그리고 PyUnicode_Fill() 함수를 사용하십시오. (Victor Stinner가 bpo-41123\를 통해 기능을 구현하였습니다.)

  • pystrhex.h 헤더 파일을 제거합니다. 이 파일은 비공개 함수만 포함하고 있습니다. C 확장 모듈은 주요 <Python.h> 헤더 파일만 포함해야 합니다. (Victor Stinner가 bpo-45434\를 통해 기능을 구현하였습니다.)

  • Py_FORCE_DOUBLE() 매크로를 제거합니다. 이 매크로는 Py_IS_INFINITY() 매크로에 의해 사용되었습니다. (Victor Stinner가 bpo-45440\를 통해 기능을 구현하였습니다.)

  • :c:macro:`Py_LIMITED_API`가 정의된 경우 다음 항목들은 더 이상 사용할 수 없습니다:

    • PyMarshal_WriteLongToFile()

    • PyMarshal_WriteObjectToFile()

    • PyMarshal_ReadObjectFromString()

    • PyMarshal_WriteObjectToString()

    • Py_MARSHAL_VERSION 매크로

    이들은 :ref:`limited API <limited-api-list>`의 일부가 아닙니다.

    (Victor Stinner가 bpo-45474\를 통해 기능을 구현하였습니다.)

  • 제한된 C API에서 PyWeakref_GET_OBJECT`를 제외합니다. 이는 :c:type:()!PyWeakReference` 구조체가 제한된 C API에서 불투명하기 때문에 작동하지 않았습니다. (Victor Stinner가 bpo-35134\를 통해 기능을 구현하였습니다.)

  • PyHeapType_GET_MEMBERS() 매크로를 제거합니다. 이 매크로는 실수로 공개 C API에 노출되었으며, 파이썬 내부에서만 사용해야 합니다. 대신 PyTypeObject.tp_members 멤버를 사용하십시오. (Victor Stinner가 bpo-40170\를 통해 기능을 구현하였습니다.)

  • HAVE_PY_SET_53BIT_PRECISION 매크로를 제거합니다 (내부 C API로 이동). (Victor Stinner가 bpo-45412\를 통해 기능을 구현하였습니다.)

  • Py_UNICODE 인코더 API는 Python 3.3부터 폐지되었고, 사용 빈도가 거의 없으며 권장되는 대안에 비해 비효율적이므로 제거합니다.

    • PyUnicode_EncodeASCII()

    • PyUnicode_EncodeLatin1()

    • PyUnicode_EncodeUTF7()

    • PyUnicode_EncodeUTF8()

    • PyUnicode_EncodeUTF16()

    • PyUnicode_EncodeUTF32()

    • PyUnicode_EncodeUnicodeEscape()

    • PyUnicode_EncodeRawUnicodeEscape()

    See PEP 624 for details and migration guidance. (Contributed by Inada Naoki in bpo-44029.)
